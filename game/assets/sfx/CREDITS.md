## 四、为什么换掉 v1（五个军事音效）

v1 用的是小森平の効果音工場（`taira-komori.net`）的「兵器·爆炸」分类。
授权本身没问题（允许商用、可加工、随作品发布、免署名），但**音色不对**。

拿四个客观指标一测就很清楚。前两个是判断"像不像真枪"的关键：

- **起振时间**：从峰值 10% 到 99% 的耗时。真枪的枪口冲击波是毫秒级，超过 10ms 就不像枪了。
- **峰值因子**（crest factor = 峰值/有效值，dB）：动态范围。压缩得越狠越小，听感越"扁"。
- **频谱平坦度**：噪声性（宽频）还是音调性（窄带）。枪声是宽频噪声。
- **低频占比**：200Hz 以下的能量，反映有没有"冲击"。

| 音效 | 版本 | 起振 | 峰值因子 | 判读 |
|---|---|---|---|---|
| fire | v1 小森平 shoot3 | 20.0ms | 14.0dB | 起振太慢，窄带有音调 → 像"biu"，不像枪 |
| fire | **v2 实弹 .22 Magnum** | **0.2ms** | **26.0dB** | 瞬态陡、动态大 → 真枪 |
| shell | v1 小森平 cannon1 | 140.0ms | 12.2dB | 起振极慢，75% 能量在 200Hz 以下 → 闷雷，没有爆裂 |
| shell | **v2 Mixkit** | **4.0ms** | **20.1dB** | 有冲击也有爆裂 |
| hit | v1 short_bomb | 2.2ms | 11.3dB | 压缩太重，打上去不"实" |
| hit | **v2 Mixkit** | **2.7ms** | **22.6dB** | 短促有力 |
| kill | v1 game_explosion1 | 44.0ms | 16.2dB | 偏软 |
| kill | **v2 Mixkit** | **12.3ms** | **20.7dB** | 多爆点，有份量 |
| alarm | v1 launcher1 | 8.0ms | 16.5dB | 像导弹发射，不像警报 |
| alarm | **v2 Mixkit** | **3.3ms** | **16.1dB** | 真的是警报声 |

**没有换成"更响"，换的是瞬态和动态。** 音量在 `FX.vol` 里统一调，音色才是这里要解决的。

### 一个反直觉的坑：mp3 编码不会拖钝起振

改之前担心 mp3 的编码器延迟会在音效前面塞十几毫秒静音，把枪声的"啪"变成"噗"。
实测（112kbps 单声道，编码后再解码测起振）：4 个样本全部一致，1.5ms→1.5ms、2.9ms→2.9ms，毫无变化。
现代解码器会读 LAME 写入的 delay 信息并跳过。**所以体积从 1818KB 压到 297KB，瞬态零损失。**

（真正会拖钝瞬态的是**降采样到 22.05kHz**：`fire_a` 从 1.5ms 变成 2.9ms，被插值抹平了一档。
所以最终交付统一 44.1kHz。）

## 六、换素材

**推荐用导入工具，别手工覆盖**（下一节）。手工覆盖能跑，但会踩三件事：
头尾静音、电平不齐、文件名不改导致浏览器拿缓存。

想换名字或加槽位，改 `campaign.html` 里 `const ASSETS` 的 `sfx` 一段。

浏览器会拿缓存的旧音频，本地听着"没变化"能查半天。改内容就顺手改个后缀。

## 七、bgm（已补齐，五首自制）

原计划从素材站买 loop，最后没这么做。原因不是授权，是**循环长度**：
素材站的 loop 包按 8 / 16 小节切，一条 30–60 秒，而一局兵棋要打 20–40 分钟——
同一段材料要重复四十遍，疲劳感压不住。自己写谱能控制三件事：
首尾落在小节线上、五首共用一套调性（D 小调 / D 多利亚），以及**长度按局面定**
（tension 只在建制崩溃时压上来，48 秒足够撑到玩家收拾完）。

谱是单一真源 `game/audio-lab/bgm-tracks.js`，`npm run bgm` 渲染成 ogg。
改曲改谱不改 ogg——手改 ogg 会让"试听一个样、导出另一个样"。

## 八、按兵种分派的新槽（2026-10）

> **状态：已换素材，见第十节。** 分派架构（`SONIC` 表 + 槽位）是要留的，
> 但当时这四支自制音色的**听感没通过验收**——合成器做不出真实枪膛和履带钢板的颗粒。
> 这一节留着是记录"为什么拆"；**槽位现在有八个**（机动六 + 攻击二），
> 全部是 freesound 实录，来源与参数在第十节。

这一版把"一个音效包打天下"拆开了。原来全场只有一条 `move`、一条 `fire`：
坦克走路和步兵走路一个声，步枪打掉三点血也放炮声。分派表在 `campaign.html` 的
`SONIC`，四支音效全部**自制**——没有引入第三方素材，因为要的不是"一条好枪声"，
而是"三支枪错开 80 ms 的齐射"和"每秒 42 记的履带节拍"，素材站不按这个粒度卖。

| 文件 | 时长 | 定标 | 实测 | 用途 |
|---|---|---|---|---|
| `rifle-synth.ogg` | 0.78s | 峰值 −2.5 | 起振 3.3ms · 峰值因子 18.4 · 重心 4313 Hz | 步兵 / 摩步 / 装步 / 侦察 攻击 |
| `step-synth.ogg` | 0.38s | 峰值 −7.0 | 起振 4.7ms · 峰值因子 12.4 · 重心 2307 Hz | 徒步单位机动 |
| `engine-synth.ogg` | 1.05s | RMS −19.0 | 峰值因子 9.8 · 重心 944 Hz | 轮式：摩步 / 牵引炮 / 防空 |
| `track-synth.ogg` | 1.15s | RMS −19.5 | 峰值因子 6.6 · 重心 2354 Hz | 履带：坦克 / 自行炮 / 装步 |

**生成方式**：`node tools/sfx-synth.js rifle step engine track`，
配方是 `tools/sfx-synth.js` 里的 `sRifle` / `sStep` / `sEngine` / `sTrack`。
确定性随机种子，两次跑出来的字节一样；改参数不用改 ogg。

**为什么步枪那条要单独做**：`fire-v2` 是 .22 实弹，起振 0.2 ms，单发无敌——
但一个步兵营齐射不是"同一条枪响 N 次"。真实现场里三支步枪的射击点错开 60–120 ms，
中间夹一梭子自动武器，这个**疏密不均**才是步兵交火。所以 `rifle` 用六发时间表
（3 栓动 + 3 连点）而不是一次触发播多遍——后者会等间隔，听起来像节拍器。

**一个踩过的坑**：中频（200–1500 Hz）不能用带通噪声补。白噪声过 Q≈0.9 的带通后
能量密度太低，权重加到 2.3 中频占比也只从 0.15 爬到 0.19。真实枪声那一段是
**枪管驻波**，换成 520 / 780 Hz 两根衰减正弦后，中频到 0.24、重心从 4926 降到 4313 Hz。
枪的"身"是音调，不是噪声。

**还有一条没解决**：`track` 的峰值因子只有 6.6，节拍被 RMS 定标和饱和一起压平了。
听感上"隆隆"够、"咔咔"偏弱，等有素材时候补一层真实履带板录音叠上去。

## 九、导入外部素材（`tools/sfx-import.js`）

素材站下载的原文件**不能直接丢进 `assets/sfx`**。差的不是格式，是四件事：

| 差什么 | 不处理的后果 |
|---|---|
| 头尾静音 | 点了开火，声音晚 50–300 ms 才响。手感全在这一段 |
| 电平不齐 | 不同站的母带差 10–20 dB，一发震耳一发听不见 |
| 太长 | 4 秒的炮声盖住下一回合的报点 |
| 容器 | 浏览器只认有限几种；仓库统一 ogg / mp3 |

一条命令全部处理完，并把 `ASSETS` 那一行改掉：

```bash
node tools/sfx-import.js rifle ~/Downloads/kar98k.wav     # 导入
node tools/sfx-import.js track ~/Downloads/tank_idle.mp3
node tools/sfx-import.js --list                           # 看每个槽的要求
node tools/sfx-import.js fire x.wav --dry                 # 只测量，不写盘
```

长素材要先定位，`--at 26 --dur 1.6` 是"第 26 秒起切 1.6 秒"；
`--pick` 让它自己找能量最集中的窗（省事，但窗口长度是槽位上限，不一定是你想要的长度）。

四个滤波开关，**功能不重叠，别互相替代**：

| 开关 | 做什么 | 什么时候用 |
|---|---|---|
| `--low <dB>` | 200 Hz 低搁架，抬/压低频的**厚度** | 摄像机/手机录的枪炮"轻"，像敲纸箱 |
| `--hp <Hz>` | 二阶高通 12 dB/oct，**砍掉**次声 | 远距离录音的次声占满 RMS（见第十节 airgun） |
| `--lp <Hz>` | 二阶低通 12 dB/oct，砍掉高频嘶声 | 现场混进泵机啸叫、反射嘶嘶 |
| `--also 文件@秒:增益` | 叠层（可写多次） | 步枪五发错开、舰船补推进、投弹配爆炸 |

`--low` 和 `--hp` 最容易用错：`--low -12` 只是把 200 Hz 以下整体压 12 dB，
20 Hz 的隆隆还在（只是小了点）；`--hp 120` 是把它**移出**通带。

它做的事，按顺序：**解码 → 定位/切窗 → 掐头尾静音（−55 dB 门限）→ 截到时长上限
（结尾 60 ms 淡出）→ 循环音补接缝淡变 / 一次性音补 20 ms 尾淡出 → 高通 → 低频搁架 / 低通
→ 叠层 → 按该槽口径归一到目标电平 → **测量成品** → 编码 ogg → 改 `ASSETS` → 报预算**。

**归一化有两套口径，不能混用**：一次性音效（枪、炮、UI）按**峰值**定标，
因为它们要在混音里顶出来；循环底噪（引擎、履带）按 **RMS** 定标，
峰值归一会让起振瞬间过冲。这条和 BGM 那节同源——
峰值型看峰值、持续型看 RMS，反过来做就是把炮声改小。

**文件名是 `<槽位>-take<N>.ogg`，递增不复用**。同名覆盖会撞浏览器缓存，
本地听着"没变"能查半天（这就是 `-v2` 后缀的由来）。旧 take 会留在目录里当历史，
每次导入结束会列出**已不再被引用**的文件，可以删。

**解码器**：`tools/decode-f32.py`，走 miniaudio。支持 wav / mp3 / flac / ogg-vorbis，
**m4a/aac 不支持**——那种先用播放器转成 wav。这台机器上没有 ffmpeg，
所以 node 那边不做解码，只做处理与编码（`wasm-media-encoders`）。

它报「解码失败」时要留个心眼：miniaudio 把"文件打不开"（`MA_DOES_NOT_EXIST`，−7）
也归到同一个报错里，提示却写着 m4a/aac。素材放 `C:/Users/.../Temp/` 下必失败，
复制到 `C:/tmp/` 就正常——**先换短路径试一次，再怀疑格式**。

同一个脚本还有个 `--f32` 分支：读裸流、只算指标不落盘。导入工具用它测量
**处理之后**的那一段（切窗、EQ、归一化都会改频谱，看处理前的数字定不了参）。

**导入后必跑 `npm test`**：会验素材存在、首屏 300 KB 预算、试听页内嵌块是否过期。
试听页 `audio-lab/sfx-demo.html` 里的文件名是写死的，导入新 take 后想在里面试听，
改 `ROWS` 里那一行的 `syn`，再 `npm run sfx:embed`。

### 炮击换发次（`shell-take1` → `take2`）

同一条 ZiS-3 录音里有十几发炮，要求"取前 2 秒"时先要看那 2 秒里是**哪一发**。

**先说 849766 为什么又否一次。** 上级曾提议用它取前 2s，深查后确认不能：

- **授权链四层，其中一层是 NC。** 849766 自己标 CC-BY 4.0，但它是
  「CC0 底 + 556134(ZiS-3, BY) + Robinhood76 swoosh(**BY-NC**) + Audionautics(BY)」
  再加工出来的。作者在署名里专门注了 `(1st three shots.)`——**前三发**用了那条 NC 的 swoosh。
  而这三发的落点是 **0.65 / 1.05 / 1.14 秒，全都落在"前 2 秒"里**。
  取前 2s 等于正好把 NC 那一段整个切进去，是最坏的一种切法。
- **声学上它也不像炮。** 实测整条 55.67 s 有 83 发，前 2 s 挤了 **9 发**（间隔 85–155 ms），
  那是机枪阵地的密度，不是炮兵阵地；重心 **2619 Hz**、低频只占 0.26、波峰因数 **11.5**、
  峰值顶在 **0.0 dBFS**。作者自己写的是 "Filter curve and distortion effects"——
  它就是 556134 加了失真，**比原素材更脆，也更不像炮**。

**再说 556134 前 2 秒里实际是什么。** 这一段是**一发完整的炮击**：

| 区间 | 内容 |
|---|---|
| 0.00–0.37 s | 现场静场（-52 dB 底噪） |
| 0.37 s | 起爆 |
| 0.49 s | 峰值 |
| 1.0–2.0 s | 余响衰减到 -31 dB |

**坑在这里：`trimSilence` 掐不掉那 373 ms。** 它的门限是**相对峰值 -55 dB**，
而这颗炮的峰值是 -0.3 dBFS，头部底噪逐样本峰值 -40.0 dBFS ——
比门限高 15.3 dB，**一个样本都掐不到**。原样导入，游戏里每次炮击都会晚 373 ms 才响。
（`fire-v2.mp3` 那 51 ms 是同一类问题的轻微版，来源不同：那个是 MP3 容器补齐。）

**解法是显式定位，不是调门限**：`--at 0.36 --dur 1.64`。
为此给 `sfx-import.js` 加了 `--dur`——槽位的 `maxDur` 是**上限**不是**目标**，
不管上限多大都会一路带到底，把后面第二发也卷进来。

| | take1（3.01 s 那发） | take2（开头那发） |
|---|---|---|
| 起振 | 4.2 ms | **12.4 ms** |
| 波峰因数 | 22.8 | **13.2** |
| 低/中/高 | 0.51/0.43/0.06 | **0.41/0.43/0.16** |
| 重心 | 556 Hz | **1082 Hz** |

右列更**脆**（2 kHz 以上 0.06→0.16）、余响更干净，代价是低频少一档、
动态更紧（波峰因数 22.8→13.2，那种"闷的推力"弱了）。
**这是同一门炮的两发不同弹，不是同一条音效的两种处理**——听感差别来自源，不是处理。

试过 +4/6/8 dB 低搁架：+6 dB 能把低频拉到 0.54、重心降到 828 Hz，
但波峰因数只有 12.5，补不回动态。**最后按"原素材"要求没加 EQ**，
要更沉就重跑一次带 `--low 6`。

**顺带一个编码坑**：写盘时峰值定在 -3.0 dB，OGG 解码回来是 **-1.5 dB**。
Vorbis 的 MDCT 在单样本尖峰处会重建出过冲，1–2 dB 属正常范围
（take1 那发没这现象，因为它的峰值比这发"圆"）。
所以别把 `target` 定在 -1 dB 附近——留 3 dB 余量是给编码器的，不是给混音的。

### 底噪：四发远处炮火垫进 `amb-take1.ogg`

| 项 | 值 |
|---|---|
| 底噪骨架 | `amb-synth.ogg` 同一套合成（从 `--keep-wav` 的无损 WAV 混，避免 ogg→ogg 二次损失） |
| 叠入素材 | [867030 Large Cannon Fire](https://freesound.org/people/raphavpires/sounds/867030/) · **CC0** |
| 落点 | 第 6.2 / 15.1 / 31.4 / 44.7 秒，四档不同距离（增益 0.30 / 0.21 / 0.17 / 0.13） |
| 电平 | 峰值 −10.2 dBFS，RMS −31.0 dBFS，60.00 s |

**为什么这条"闷"反而是对的。** 它 2 kHz 以上只占 0.04、重心 479 Hz，放在近距炮击槽里
是缺陷（就是换掉的 `shell-v2` 那个毛病）；但**远处炮声本来就只剩低频**——高频在空气里
衰减最快，50 米的炮和 5 公里的炮，差别主要就是高频没了。所以同一组数字，
近听是"闷响"，远听是"对"。

四发在 **60–200 Hz 上高出底噪 14–17 dB**：不是"听清"，是"感到"。
全频段上它和底噪里的碎裂声差不多响，靠的是频谱重心把它分开，不是靠音量。

**四发的间隔是刻意不均的**（8.9 / 16.3 / 13.3 / 18.0 s，含循环回绕）。
等间隔会听成节拍器，而且是"同一门炮在原地开火"；不等间隔才像"远处有几门在打"。

### 第二批（飞机 / 舰船 / 车辆）：三个机动词各自归位

这三条不是"音色不好听所以换"，是**槽位本身分不开**：航空与水面原来借的
是卡车的引擎声（见第十一节那张"一个槽顶三件事"的表）。上一轮只换四条，
是因为能用的实录只找到四条。

| 槽 | 素材 | 实际是什么 | 定参 |
|---|---|---|---|
| `engine` | 569837 消防车 | 18.08 s 连续怠速/行驶，全程 −27→−18 dBFS，没有孤立尖峰 | `--at 10 --dur 1.6 --low 8` |
| `prop` | 142897 三机滑行 | 47.35 s，Spitfire Mk.Vc / Mk.IXe / B-17G 依次滑过 | `--at 1.0 --dur 1.6` |
| `ship` | 61012 浪 + 合成 hull | **5.00 s 里只有 0–2.25 s 有内容**，之后是 −94 dBFS 数字静音 | `--at 0.35 --dur 1.6 --also hull-synth.ogg:2.0` |

#### 引擎：低频薄是摄像机的锅，不是车的锅

原段（10.0–11.6 s）能量口径 低 0.120 / 重心 706 Hz，**2 kHz 以上只 0.041**，
听起来是"中频嗡嗡"而不是柴油机低吼。

抬 8 dB 低搁架后：低 0.335 / 重心 521 Hz。为什么不是抬更多——搁架会把
200 Hz 以下的底噪一起抬，而这条录音的底噪本身不低（峰值 −4.3 dBFS 却
RMS −20 dB，动态很紧），抬多了是"把嘶声也抬高"。

**顺手发现旧合成版的问题**：`engine-synth.ogg` 能量口径 低 0.866 / 重心 **117 Hz**。
这意味着它的能量几乎全在次声段——笔记本扬声器 200 Hz 以下基本放不出来，
所以它"在混音里存在感低"不是电平问题，是**频率放不出来**。实录版 521 Hz
反而更适合小喇叭。

#### 螺旋桨：131 Hz 的叶频就是"天上飞的"和"地上跑的"分界

47 秒里有三次经过（三架不同的飞机），取哪一段决定了这条音效的"性格"：

| 段 | 机型 | 能量口径 | 包络调制 | 判读 |
|---|---|---|---|---|
| 1.0 s | Spitfire（Merlin） | 低 0.742 / 重心 234 Hz | **10.1 Hz** | 叶频 131 Hz 一片连续峰、侧带 1.2–13 Hz —— 单发高速桨 |
| 26 s | B-17（四发 Cyclone） | 低 0.366 / 重心 274 Hz | 4.4 Hz | 叶频分散到 126–190 Hz，四个桨互相拍 |

**取 1.0 s**：游戏里航空兵多是战斗机与攻击机，10 Hz 的"噗噗"更能听出
"桨在转"；四发那条更低沉，但拍频慢，短促的机动音里听不出是桨。
两条的高频都只有 0.01 上下（远场录音的空气吸收），所以**不要把 2 kHz 当成
这条的验收线**——桨叶信息全在 120–400 Hz。

#### 舰船：实录里只有浪，推进得自己补

61012 的标题是 `wave2`，作者描述写的是 "a wave crashing a side of a ship **or rocks**"。
它确实是舰船会发出的声音，但那是**船体与水**的界面声，不是推进。

能量口径：低 0.127 / 2 kHz 以上 0.246 / 重心 1560 Hz。**有"水"没有"船"**。

推进的低频（螺旋桨空化 + 主机）在浪里根本不存在，也从浪里提不出来，
只能补一层合成 `hull-synth.ogg`：

| | 单独 | 叠 ×2.0 后 |
|---|---|---|
| 低频（<200 Hz） | 浪 0.127 → hull **0.979** | **0.637** |
| 20–120 Hz | 浪 0.085 → hull 0.862 | **0.556** |
| 重心 | 1560 / 78 | **672 Hz** |

**hull 的关键约束是"不能有包络"**。engine 那层必须有起振（它是"点了一下移动"
的反馈），而 hull 是循环垫子：两端振幅必须一样，否则 loop 每次回头都"轰"一下。
呼吸用一个**周期整除时长**的 LFO（1.6 秒正好一整个周期），接缝处相位连续。

第一版 hull 出口没有低通，sat 把 45 Hz 锯齿推到十几阶谐波，重心落在
**2807 Hz**、低频只占 0.383——那是个"嗡嗡的电机"，不是"船在推水"。
加一道 220 Hz 二阶低通（`outL/outR`）之后才落在 78 Hz。

### 本轮顺带修的两个工具问题

**1. 报"解码失败"，其实是打不开文件。** miniaudio 对某些路径返回
`MA_DOES_NOT_EXIST`（−7），而 `decode-f32.py` 把它和真正的解码错误
一起报成「解码失败」，提示还写着"不支持 m4a/aac"——完全误导。
这次的素材放在 `C:/Users/.../Temp/fs/` 下必失败，复制到 `C:/tmp/sfx/` 就正常。
**遇到"解码失败"的 mp3，先把素材挪到纯 ASCII 的短路径再试**，别去怀疑编码。

**2. 谱宽口径会把人带沟里。** `decode-f32.py` 原来只算幅度口径（|X| 求和），
而窄带低频在幅度口径下被严重低估——同一段飞机录音高频 **幅度 0.294 / 能量 0.011**，
差 27 倍。按幅度口径判断"浪的高频占 0.55"，于是把叠层增益定成 0.62，
实际听感上低频根本起不来（能量口径只有 0.066）；改成能量口径一看，
要到 ×2.0 才够。

现在两边都输出：`low/mid/high`（幅度，历史表格用）与 `lowE/midE/highE`（能量，
判读用）。**导入时打印的"成品"行是能量口径，定参只看那一行。**

顺带给 `--dry` 接上了"处理之后"的测量——原来它只显示**切之前整段**的数字，
切窗、EQ、归一化都还没发生，等于没有参考价值。

### 第三批（航空攻击）：机炮与投弹

航空的攻击侧一直在借地面的枪炮——战斗机用 7.62 单响，轰炸机用 75 mm 炮响。
借的理由是"都是枪炮"，但**机炮与步枪最好分辨的地方不是口径，是射速**：
机炮连成一片，步枪一响一顿。这两条把航空的攻击侧补上了。

| 文件 | 槽位 | 原始素材 | 作者 | 授权 | 处理参数 |
|---|---|---|---|---|---|
| `airgun-take1.ogg` | 战斗机 / 攻击机攻击 | [161429 Anti Air Gun (3 Sounds)](https://freesound.org/people/ryanconway/sounds/161429/) | ryanconway | **CC-BY 4.0** | 取 2.133–4.00 s，**高通 120 Hz**，1.87 s |
| `bomb-take1.ogg` | 轰炸机攻击 | [398255 Bomb Dropping](https://freesound.org/people/morganpurkis/sounds/398255/) | morganpurkis | **CC0** | 哨音 0.80–2.30 s，叠 `shell-take2` @1.45 s ×0.85，3.09 s |

#### `airgun`：源素材 71% 的能量在 40 Hz 以下

161429 是 25.8 秒里的三段防空炮。取第二段 2.133–4.00 s。起点不是整 2.00 s，
因为 2.00–2.13 是**上一发的尾音**（−29 → −60 dB 的梳状起伏），
真起振在 2.132 s；不切掉就会把上一发卷进来。

| | 原样 | 高通 120 Hz 后 |
|---|---|---|
| 能量重心 | 82 Hz | **265 Hz** |
| 40 Hz 以下 | **71.1%** | 0.4% |
| 200 Hz–2 kHz | 17.9% | **75.8%** |
| 波峰因数 | 8.6 dB | **14.9 dB** |

**这是远距离录音的典型形状**：空气把 2 kHz 以上的吸光了（2k+ 测出来 0.000），
20–40 Hz 却一点没少——那一段不是炮声，是风噪与地面传导。
直接导入就是"在笔记本上听不见"，与上一版 `engine-synth`（重心 117 Hz）同一个病。

波峰因数 8.6 → 14.9 是这次滤波**做对了**的证据：占满 RMS 的次声没了，
每一发的瞬态才浮出来。听感从"远处在打雷"变成"有人在连射"。

为此给导入工具加了 `--hp`。它和 `--low` 是两件事，别用错：
`--low` 是**调量**（抬/压 200 Hz 以下的厚度），砍不掉 20 Hz 的隆隆；
`--hp` 是**砍频段**（12 dB/oct），专门用来切掉喇叭放不出来、却会占满 RMS 的次声。

**这条的已知不足**：2 kHz 以上只剩 0.001。录音距离决定的，补不回来——
除非叠一层高频激励，而那是"造音色"不是"修素材"。现在接受它"沉而不脆"，
理由是它带来了别的素材没有的东西：**连续一片的连射节奏**。包络上
0.232 秒一个循环（循环里四个起伏），发与发之间没有空档——这正是机炮
与四连点射的区别，也是 `rifle`（间隔 65–95 ms 的四发）替代不了的地方。

#### `bomb`：源素材只有哨音，没有爆炸

398255 的作者描述写得很清楚：*"The whistling SFX created when a bomb
approaches from the skies"*。实测也印证——5.4 秒全程光滑衰减，
重心从 10814 Hz 一路下扫到 646 Hz，**没有一个瞬态**。

所以它必须配一声爆。用已有的 `shell-take2`（ZiS-3）当爆炸，叠在 1.45 s：

- 哨音取 0.80–2.30 s：起点 −35 dBFS，到 2.30 s 已是 −17 dBFS，
  这一段才是"由远及近"。再往后（3.0 s+）重心掉到 951 Hz，
  是"贴着地面"的粗糙呼啸，留给更长的版本用
- 爆炸从 1.45 s 起振，比哨音结束（1.55 s）早 0.1 s——这样哨音的收尾淡出
  被爆炸盖住，不会露出一个空档

成品 3.09 s、波峰因数 17.1 dB、重心 601 Hz：有下扫，也有落地的爆。

#### 顺带：两个死槽不再进 preload

`move` / `hit` 现在没有代码引用（机动改走 step/engine/track，命中反馈改成按
攻击方口径选枪炮），只剩在试听页当对照组。它们留在 `ASSETS` 里是对的，
但没理由跟着进关传输——8.5 KB。加进 `FX._noPreload` 之后，
preload 从 272 KB 落到 **264 KB**。

预算门槛同时从 250 提到 **300 KB**：槽位从 17 涨到 20，多出来的两条

## 十一、还需外部素材的槽（2026-10 盘点）

按**已实装 6 关里真实出现的兵牌次数**排优先级，不是按兵种表个数排——
表里 38 种兵，只有 27 种在现在的关卡里出现过，没上场的兵种换不换不影响任何人的耳朵。

### 先分清三件事：这些槽不是同一种「缺」

处理成本差一个数量级，混在一起排优先级会一直挑错活干：

| 状态 | 槽 | 要做的事 | 代价 |
|---|---|---|---|
| **待替换** | `rifle` `step` `track` `engine` `prop` `ship` `airgun` `bomb` | 回 freesound 下**原始 WAV**，重跑导入 | 只花下载与重跑，不用再挑素材 |
| **缺槽** | — | **已清零** | — |

2026-10 第三批之后，**"缺槽"与"用合成音顶替"两类都已清零**：八个分派槽
全部有实录（`ship` 的推进层、`bomb` 的爆炸是叠在实录上的补层，不算顶替）。
剩下**只有一条**：有源，但源头是预览转码。

**待替换最省事，也最容易被一直拖着**——因为"能用"，所以没人会去动它。
但它的损失是全天候的：`rifle` 一局响一百多次、`step` 一百次上下、`track` 近五十次，
每一次都带着 148 kbps 的痕迹，而且和响 3 次的那条拿一样的处理预算。

### 待替换：八条实录的源头是预览转码

### 已解决：`engine` 原来一个槽顶了三件事

这一段留着是因为"怎么发现该拆"比"拆完了"更有用。

`engine` 曾是**最忙的一条**：6 关里 227 次机动音中有 **76 次**（33%）走它，
覆盖 13 种兵。更麻烦的是它同时被拿去给三种完全不同的东西配音：

| 实际是什么 | 兵种 | 6 关内次数 | 问题 |
|---|---|---|---|
| 轮式车辆 | 摩步营、侦察连、各班炮兵、防空 | 64 | 这条本来就该是它，需要真实柴油/汽油引擎 |
| **螺旋桨飞机** | 战斗机、攻击机、轰炸机 | 5 | 现在是**卡车声**——螺旋桨转速、桨尖啸叫、多普勒全没有 |
| **舰艇主机** | 驱逐舰、巡洋舰、战列舰 | 7 | 现在是**卡车声**——没有水声、没有低频推进轰鸣 |

所以实际要三条：`engine`（轮式）、`prop`（螺旋桨）、`ship`（舰艇主机）。
后两个当时没有槽位——导入工具现在会自动补行（见第九节的 `--list`）。

**2026-10 第二批已落地**：三条各就各位，`SONIC` 表里航空四种与水面九种的
`m` 全部改指 `prop` / `ship`。`selftest [37]` 加了两条断言守着——
一条正面验战斗机走 `prop`、驱逐舰走 `ship`，一条**反向**扫那 13 个兵种，
确认没有任何一个还留在 `engine` 上。只写正面的话，谁把其中一种改回 `engine`
照样能过。

### 已解决：航空攻击（`airgun` / `bomb`）

原来是 `fire`（地面 7.62 实弹）被战斗机、攻击机当机炮用，`shell` 被轰炸机当投弹用。
6 关内前者响 3 次、后者更少，所以一直排在最后。

**2026-10 第三批已落地**：`airgun` 走 161429 防空炮连射（高通 120 Hz），
`bomb` 走 398255 俯冲哨音叠 `shell`。细节见第十节的第三批。

补的时候发现一个当时没写下的判断依据：**机炮与步枪的区别在射速不在口径**。
上一版注释写的是"同属 7.62 级，差别在距离感和多普勒"——那只对了一半。
真正的辨识点是"连续一片 vs 一响一顿"，而这恰好是素材能给的东西；
多普勒在短促的机动音里根本听不出来。所以选材该看的是**包络有没有空档**，
不是频谱重心。

### 可选：两个死槽

| 槽 | 现状 |
|---|---|
| `move` | **无代码引用**。机动改走 step/engine/track/prop/ship 之后，它只剩"给试听页当对照组"这一个用途 |
| `hit` | **无代码引用**。命中反馈已改成按攻击方口径选枪/炮；而且它的高频占 **0.97**（像玻璃碎），本来也不适合做落点层 |

真要复活 `hit`，它该做的是**落点反馈**（现在打中/没打中听感完全一样，规则层有 `defLoss > 0`
可以直接判）。但那需要一条新的落点音，不是现在这条。

### 顺手：`alarm` 不是缺素材，是一条顶了两种语义

`alarm-v2.mp3`（Mixkit #1679，1.83 s，连续嚎叫式警报）本身是合格的：
起振 3.3 ms、波峰因数 16.1 dB，第四节那张表里它是少数"换完不用再动"的。

问题在用法——同一条音效现在同时是：

| 场景 | 触发点 | 该是什么 |
|---|---|---|
| 波次增援入场 | `LEVEL.waves` 里每波一次 | 集结哨 / 电话铃 / 传令，**不是警报** |
| 敌机空袭港区 | 事件 `air_raid`（轰炸机第一次开火） | 空袭警报，这条用对了 |

一局里前者出现的次数比后者多，于是"警报"被稀释成了"有事发生"的通用提示音。
真要分开，缺的是**增援那一条**（哨音或铃声，2 秒内），不是换掉警报。
优先级排在 `engine` 与三条原件之后——它不影响任何声音的质量，只影响语义。

### 拿到素材之后先看这两个数

| 槽 | 硬指标 |
|---|---|
| `engine` | **连续、没有节拍**。有节拍就听成履带了。能量重心 400–600 Hz 为宜，低于 200 Hz 在小喇叭上放不出来 |
| `prop` | 120–400 Hz 有一片**连续的叶频峰**（实测 Spitfire 131 Hz）。**别拿 2 kHz 当验收线**——远场录音的高频只有 0.01，桨尖成分是被空气吃掉的，不是没有 |
| `ship` | 40–120 Hz 推进轰鸣占主导，高频只有水声嘶嘶；**不能有金属敲击节拍**（那是履带） |
| `airgun` | 比地面枪声慢起振（>3 ms）、高频衰减快，听感"远" |

四条共同：先看 **2 kHz 以上占比**（0.05–0.4 是活的，低于 0.03 就是闷响），
再看**波峰因数**（枪炮要 18 dB 以上，低于 10 说明被压过头了）。导入工具会直接打这两个数。

**判断口径用能量，不用幅度**：工具现在两行都印，"成品"那行是能量口径——
理由见第十节「本轮顺带修的两个工具问题」。

## 十二、定标口径：一次性音看峰值，环境层看 RMS

这一条不写下来会反复踩。`tools/sfx-synth.js` 的 `SPEC` 和 `tools/sfx-import.js` 的 `SLOT`
是两张表，**同名槽的目标值必须一致**，否则"重渲染"和"导入新素材"会产出两个响度。

2026-10 就撞了一次：`event` 在合成器里是 `rms −18`，在导入工具里是 `peak −4`。
结果是合成版峰值只到 **−12**，进游戏再乘 `vol.sfx 0.65` → 输出 **−15.7 dB**，
比全库其余音效低约 10 dB，等于没有。改成 `peak −4` 后输出 **−7.0**，和其他一次性音齐平。

判据很简单，问一句"它要不要喊住玩家"：

| 类型 | 口径 | 例 |
|---|---|---|
| 一次性、要抢注意力 | **峰值** | 枪、炮、提醒、结算 |
| 一次性的 UI 小音 | 峰值（目标低一档） | 按钮、选中 |
| 持续、铺底 | **RMS** | 引擎、履带、底噪 |

反例说明为什么不能统一：`track` 按 RMS 定到 −21，峰值只有 −10.5、输出 −14.2；
若改成按峰值定到 −3，RMS 会飙升到 −13 左右，一局里履带会盖过炮声。
**持续音按峰值定标 = 把背景推成主体。**
