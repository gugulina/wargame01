> 检查范围：对白、道具与技能描述、界面提示、任务说明、版本公告、关卡简报与态势、兵种图鉴、菜单页/配牌页、发布包
> 方法：`tools/copy-report.js --json` 抽取结构化文案（**1,681 条 / 23,523 汉字**）+ 源文件词法抽取（**2,803 条**去重界面片段）→ 逐类人工审读 → 脚本扫描占位符/变量/格式符号/标点/术语/重复/副本差异 → 回原文复核

## 一、结论

| 严重度 | 条数 | 性质 |
|---|---|---|
| 阻断 | 6 | 数值自相矛盾、错误恢复指引、副本与真源不同步（含线上发布包）、`npm test` 当前为红 |
| 严重 | 14 | 错字、病句、代码层词汇、术语不一致、数值/分值冲突、断言假红 |
| 一般 | 16 | 标点、量词、格式、重复文本、换行、风格（合计 36 条） |

**一句话**：文案本体质量高（做过 docs/25 体检，错别字极少），**主要问题不在"写错字"，而在"同一句话有多个版本"**——`game/campaign.html`（真源）、`data/levels.js` / `data/cards.js`（菜单页副本）、`docs/24`（文案总表）、`www/` + `android/`（发布包）四套文本已经不同步。

**两项实测为红**（不是推断）：
- `node tools/export-levels.js --check`：`✗ data/levels.js`、`✗ data/cards.js`（引擎指纹 `581964:17vsq5c` vs 当前 `582067:rlzep8`）
- `npm test`：**通过 1218 项，失败 2 项，EXIT=1**，两条都是文案断言（详见 B6）

根因链：

```
game/campaign.html（真源，已改文案）
   ├─ 未重跑 export-levels.js → data/levels.js / data/cards.js 过期 → 菜单页/配牌页显示旧说法
   ├─ 未重跑 copy-report.js  → docs/24 过期      → 改稿依据与游戏不一致
   └─ 未重跑 build-www.js    → www/ 与 android/ 过期 → 线上玩家读到旧规则说明
```

另有 4 类**引擎真源内部**的问题与副本无关，必须单独改：C8 泵房数值、C10 站台分值、C6 术语，以及图鉴 15 条小数修正值（B6，当前 `npm test` 的两条红里有一条就是它）。

## 二、阻断级问题（优先处理）

### B1 · 同一关同一机制，两个数字：泵房失守「掉 8 点」vs「掉 5 点」

| 位置 | 文本 |
|---|---|
| `game/campaign.html:4269`（C8 战前态势 intro #10） | 泵房一丢，管道压力掉到底，**全场组织度立刻掉 8 点** |
| `game/campaign.html:4247`（同关注释） | 泵房一丢，全场组织度掉 8 点 |
| `game/campaign.html:4389`（C8 简报第 2 页） | **泵房一丢，全场组织度立刻掉 5 点** |
| `game/campaign.html:4394`（简报数字条） | 泵房失守 = −5 组织度 |
| `data/notes.js:64`（v5.0 公告） | 场上所有部队的组织度当场掉 5 点 |
| **实际实现** `game/campaign.html:4342` | `{ kind: 'org', side: 'blue', delta: -5 }` |

**问题**：玩家先读战前态势、再翻三页简报，同一条惩罚看到 8 和 5 两个数，实际生效是 5。`8` 疑似误抄了泵房要点的分值 `vp: 8`（`campaign.html:4307`）。这会直接影响玩家对"要不要死守泵房"的判断。

**建议**：`4269` 改为「掉 5 点」，`4247` 注释同步；并在 `docs/25` 第四节"过期文案"清单里补一条判例——**数值文案要对着事件 `effects` 核，不是对着 `vp`**。

### B2 · 关卡数据加载失败时，给玩家的"修复办法"是开发者命令

`index.html:562-565`：

> **读不到关卡数据（data/levels.js）。**
> 如果在浏览器里看到这一行，多半是文件缺失或浏览器禁用了本地脚本。
> 修复：在项目根目录跑 `node tools/export-levels.js`，然后刷新。
> 也可以直接进 `game/campaign.html`，那边不依赖这个文件。

**问题**：这是玩家在菜单页白屏时唯一能看到的指引，但「项目根目录」「跑 node 命令」「直接进 game/campaign.html」对 GitHub Pages 访客和 APK 用户都不可执行。同类开发者口吻还出现在 `index.html:538-539`（版本公告读取失败分支，「本地可以在项目根目录确认这个文件还在」）——玩家卡死且无法自救。同时把文件名、命令行直接印给玩家，违反 docs/25「文案不许出现代码层表述」。

**建议**：玩家侧只写可执行动作——「刷新页面重试；仍不行请重新下载完整游戏包（确认 data 文件夹一并保留）；已有存档可在菜单『存档管理』导入」。技术排查步骤移到 README 或 `console.error`。

### B4 · 线上发布包文本过期，且有一条规则说明与真源直接冲突

`www/` 与 `android/app/src/main/assets/public/` 是玩家实际运行的副本，与真源比对结果：

| 文件 | 状态 |
|---|---|
| `www/game/campaign.html` | **DIFF**，165 行中文差异 |
| `www/data/notes.js` | **DIFF**，2 处 |
| `www/index.html` / `cards.html` / `campaign.css` / `ai.js` / `data/levels.js` / `data/cards.js` | 一致 |
| `android/.../public/game/campaign.html` / `data/levels.js` | 同样含「第三方面军」等旧文案 |

**最关键的一处规则冲突**（`www/game/campaign.html:223` 教学说明）：

| 版本 | 文本 |
|---|---|
| 线上 www | 机动过的**单位**再射击会 −10%；**坦克、自行火炮不受这条限制**。 |
| 真源 `campaign.html:223` | 机动过的**部队**再射击会 −10%；**轻坦、中坦和两型自行火炮不受这条限制，重坦照样吃**。 |

按线上说明操作，玩家会以为重坦移动后不吃 −10% 惩罚，**实际会吃**。这是会直接改变战术决策的错误指引。

另两处公告差异：
- `www/data/notes.js` v5.0：「那 **2 点战力**等于白买」 → 真源：「那 **18 点组织度恢复**等于白买」（机制完全不同）

其余 160 余行主要是图鉴数值格式（线上 `+0.15 / +0.20 / −0.30`，真源 `+15% / +20% / −30%`），以及线上用 ASCII 减号 `-0.20` 与同页 `−0.10` 混排。

**建议**：`node tools/build-www.js` 重生成 `www/`，按 `Android-打包说明.md` 重新同步 assets 再出包；push 后线上加 `?cb=` 验证。**不要手 cp**（docs/MEMORY 明确 `www/` 只能由脚本生成）。

### B5 · 战术卡：配牌页与游戏内对同一张卡给出两套数值写法与两种称谓

`data/cards.js`（`cards.html` 配牌页数据源）与 `game/campaign.html:7013-7058`（`CARDS`）**11 处不一致**：

| 卡 · 字段 | 引擎（游戏内） | 配牌页副本 |
|---|---|---|
| `hold.short` / `.desc` | 防御 **+30%** | 防御 **+0.30** |
| `assault.short` / `.desc` | 攻击 **+30%** | 攻击 **+0.30** |
| `hasty.short` / `.desc` / `.note` | **+20% / +30%** | **+0.20 / +0.30** |
| `forced.note` | 已经走过一步的**部队** | 已经走过一步的**单位** |
| `barrage.short` / `.desc` / `.note` | 敌方**部队** / 一支 / 那支**部队** | 敌方**单位** / 一个 / 那支**单位** |

**问题**：`+0.30` 是代码层的小数修正值，玩家会理解成"加 0.3 点防御"，而游戏内显示的是"+30%"；同一张卡在"决定带哪三张"的页面和"用卡"的页面说法不同。配牌页是玩家配卡的唯一依据。

**建议**：同 B3 重跑 `export-levels.js`；长期应让 `cards.html` 也以引擎为真源，避免双份维护。

### B6 · 图鉴 15 条修正值仍是小数写法，`npm test` 当前为红

实测 `npm test`：**通过 1218 项，失败 2 项，EXIT=1**。两条失败都是文案断言（`tools/selftest.js:6400` / `6403`）。

**B6-a（真问题，阻断）** `✗ 玩家可见文案里没有小数修正值（一律百分数）`

`game/campaign.html` 的 `TYPE[].abil` 里仍有 **15 条**小数修正值，同页其他条目已改成百分数，这些是漏改的尾巴：

| 位置 | 现状 | 应改为 |
|---|---|---|
| `518` larm | 对中坦 −0.10，对重坦 −0.15 | −10% / −15% |
| `530` marm / `539` `540` harm / `549` art | 城镇进攻 −0.10、−0.15；行进间射击 −0.10；打城内林地 −0.10 | −10% / −15% |
| `559` sha / `564` spa | 直瞄攻击修正 −0.15，打城内、林地目标再 −0.10 | −15% / −10% |
| `633` fgt / `641` atk / `665` gbt | 对地 −0.50 / 对空 −0.40 / 对海 −0.30 | −50% / −40% / −30% |
| `679` ffg / `692` dd / `699` ca / `707` bb | 防空压制 −0.15 / −0.20 / −0.30 | −15% / −20% / −30% |
| `9909` 碉堡 `FORT.note` | 装甲部队进攻此格额外 −0.15 | −15% |

`selftest.js:6382-6385` 的注释已把理由写死：「引擎显示口径就是百分数（`fmtPct`、侧栏自筑工事、工事提示、特性徽章、战报里的多面进攻，全是 `Math.round(v*100)+'%'`）。图鉴写 `+0.15` 而面板显示 `+15%`，同一条规则两种写法，玩家得自己换算。小数形式只留给代码字段。」

**建议**：15 条全改百分数 → `npm test` 转绿；改完再重构建 `www/`（B4），否则线上拿到的还是小数版。注意 `−0.15` 用 U+2212，与全篇一致。

**S14（断言假红，别改文案）** `✗ 玩家可见文案里的减号是 −，不是 ASCII -`

命中 `game/campaign.html:1264` 的 C1 副官对白「师长，二线还在收拢。要不要把 **1-1 营** 拉出来看看正面？」——`selftest.js:6402` 的 `/-\d/` 把部队简称 `1-1` 的连字符当成了减号。而 docs/25 第七节战报体示例就是 `1-2 进至 K5`，**番号用 ASCII 连字符是全局约定**。

**建议**：收窄断言（先剔除 `\b\d+-\d+\b` 再判，或要求减号前不是数字），**不要**把 `1-1` 改成 `1−1`。

> 一个有用的反证：`selftest.js:6409` 的「文案里不再出现『第三方面军』」是**绿的**，但它只扫引擎 `allCopy`，**没扫 `data/levels.js`**——这正是 B3 里「第三方面军」能留在菜单页关卡卡上的原因。修完 B3 建议补一条针对导出副本的断言，否则同类漂移还会再发生。
