## 进游戏

**双击根目录 `index.html`** —— 这是给玩家用的门面：封面、战役进度条、关卡时间轴，
点哪一关直接进哪一关。它读 `data/levels.js`（由 `tools/export-levels.js` 从引擎导出），
并且自己读一次本机存档，所以能显示"继续推演 · 第 2 关 · 第 5 / 12 回合"。

**直接开 `game/campaign.html`** —— 也会进游戏，只是没人告诉它进哪一关，
它会自己挑"第一个可玩且还没通关的"。关卡表和存档导出导入现在只在菜单页和
游戏内的 HQ（?hq=1 直达存档页）。

进游戏之后顶栏的**菜单**按钮随时回菜单页。这一条是打包成桌面程序之后的
唯一退路——没有 F5、没有地址栏，缺了它玩家会被锁在地图里。

**键盘也能玩**（v4.6.2）：Tab 到地图，方向键移格（当前格是白蓝双环），
回车执行（等于点这一格），Esc 逐层退出（面板 → 移动模式 → 选中）。
空格仍是结束我方阶段，数字 1–3 选战术卡，Ctrl/⌘+Z 撤销。
焦点落在别处时方向键不会动地图——不然 Tab 到顶栏后按方向键，光标会莫名其妙地跑。

> 首页与引擎各写了一份解锁规则，`tools/levelcheck.js` 的 `[9]` 会把两边逐关比对。
> 这类复刻坏起来不报错——玩家在首页看到"进入"、点进去游戏说"未解锁"，
> 只会以为页面坏了。

## 战役线（8 章结构，v4.8 起）

> **版本号以引擎顶栏的 `#verTag` 为准。** 这一行标题、`package.json` 的 `version`
> 都是副本：`export-levels.js` 会校验后两者与顶栏一致，不一致直接退出码 1。
> 改版本只改一处——`game/campaign.html` 里的 `<span id="verTag">`。

全篇 **8 章，每章 5–6 个正关 + 2–3 个附属关**，加 1 个序章，共 67 个关卡入口。
完整关卡表在 `docs/01-战役设定.md` 第五节。

**章节只是分组，不是第二套解锁机制。** 解锁仍然只有一条链（`accessPrereq()`）：
章内按关序推进，章与章之间自然衔接——某章第一关的"前一关"就是上一章最后一个已制作的正关，
附属关被跳过。所以"上一章没打完就打不了下一章"不需要额外判一句，它是链式解锁的必然结果。
`tools/levelcheck.js` 的 `[10] 章节结构` 一节会盯着配比（每章 5–6 正 + 2–3 附）、
章号不倒退、附属关紧跟正关、以及"每章第一关紧接上一章最后一关"这条顺序。

### v4.22 改了什么：敌人开始算账，但核心要点照样往死里打

`docs/22` 三个机制实装（M5 / M1 / M2），**共同硬闸是核心要点必须打**：

- **M5 不打的仗不打**：`AI_STYLES.stopLoss` 给三种脾气各一条止损线（进攻 0.75 / 夺取 0.90 / 防守 1.05，口径是 `previewAttack().ratio`）。低于这条线的一枪不打——以前夺取型会在要塞城下把营一个接一个往 1:3 里填。
- **核心豁免 `CORE_STOP = 0.55`**：目标是核心要点上的守军时，止损线下调。**要塞必须打，但不在 1:2 以下填人**。站在要点上的部队完全不吃这条（守土有责）。
- **M1 攻其必救**：`aiObjPull` 按"守备强度 / 我方场上兵力"给非核心要点一个引力（空要点值 4 格，守备够强倒扣 3 格）。**核心要点直接返回 0 —— 不吃软硬判据**，要塞不会被"挑软的"绕过去。
- **M2 重心转移**：每两回合把候选要点按列号切三段，选防御最薄的一段当主攻方向（段内 −2.5 格、段外 +1.5 格，缓存在 `state.schwerpunkt`）。**候选段只保留含核心的那些**，否则重心一转就把全军带离要塞。
- **追击不再归零**：v4.21 的 `aiFireGate` 在追击时 `return 0`，而 C1 从第 1 回合就满足追击条件（兵力比 2.06）——于是"压要塞"变成"追着人送死"。现在追击只取消"性价比"那一层，止损线照旧。

实测（100 局/关，v4.21 基线 → v4.22）：**C1 北岭要塞 100% → 66%**，
蓝方损失 88%，事件「敌军突入要塞核心」从 0% → **9%**——第一关终于打出了"重围中拼死抵抗"。
C3 97% → 44%（达标边缘），C4 37% → 98%（**反向过头，待回补**：M5 让它凑不出够本的一仗，
于是干脆不打，缺的是旅顺那半段"用炮火把工事掀开"，即 `docs/22` §8 的 M6）。
C2 / C6 的 0% 是既有问题，不在本轮范围。

### v4.18 改了什么：炮弹覆盖整格，多面进攻撕得开死守

八条反馈一轮修完，机制层五条：

- **炮兵改为面覆盖**：榴弹打的是格子不是"选中的那一支"——目标格内所有敌方地面单位一起承担战力损失，**按各自当前战力比例分摊**（最大余数法取整，合计等于面上损失），全员掉组织度、清堑壕。堆一格的协同加成还在，但一发炮弹也是一起挨。被地形/工事削到 2 点及以下时改为"每支各 1 点"（`splashSplit`，故意不守恒：2 点炮弹落在三支残部中间打 3 点）。
- **多面进攻**：同一回合里，这格已经被**另一格**的敌军打过，防御叠放 −0.30（`FLANK_PENALTY`）——扎堆龟防有了出口，战报会标"多面进攻"。
- **指挥部防炮**：炮兵/舰炮打指挥部时攻击修正 −0.30，HQ 不再被炮火点名收割。
- **超额达成统一降难**：坚守关从"一个不损"放宽到**幸存兵牌 ≥ 初始七成**；突围关战力留存从 70% 降到 **60%**；计分关超额线照分数线走。教学关一律没有超额档（分数摸到线也按达成结算，菜单也不显示「★ 可超额」）。
- **第六关两段高地拆成两个独立要点**（lineW / lineE 各 10 分），只守一条防线拿不满这 20 分。

界面与内容三条：**战术卡配置独立成页**（菜单页 →「更换战术卡」，`cards.html`，跨关沿用），战斗内不再进 HQ 换卡；HQ 的其他功能从战斗内**设置 → 战时手册**进；**友军机制预留**（`side: 'ally'` 兵牌按绿色渲染）。AI 侧同步修了两条：面对扎堆防御时倾向多面进攻（吃 `FLANK_PENALTY` 的红利）、对无效接触（比值 < 0.35）的目标不再白送攻击。

### v4.6 改了什么：崩溃机制、战术卡进战场、防空阵地反击

**一、组织度崩溃。** 组织度跌破 25%（可配置）就**建制崩溃**：兵牌上出现红边和
「崩」字，这支部队本回合不能主动攻击，但**反击照常**——被咬住时枪还在手上。
要回到 40% 才算重新成军（滞回，避免在阈值附近来回跳）。
崩溃后脱离接触（2 格内无敌军）+ 补给未断，每回合额外恢复 10 点。

> 崩溃**不影响防御**。这是刻意的：溃退的部队确实该更脆，但同时砍进攻和防御，
> 一次崩就等于宣判死刑，玩家没有翻盘空间。

**二、战术卡搬进战场。** 右侧新增卡条，三张卡带数字键 1/2/3，点一下进"待放"状态，
再点地图上的目标就生效；再点同一张（或按 Esc）撤下。HQ 里的「立即使用」入口
和相关逻辑整段删掉了——**配牌留在 HQ，用牌只在战场**，两件事分开。

**三、防空阵地能打飞机了。** 站在我方防空阵地（工事 `F`）格上的地面部队，
被敌机攻击时可以按 **+0.55** 反击。三个条件：打的是飞机、自己不是防空兵
（`aac`/`aab` 本来就有对空修正）、脚下的阵地没被压制（格内混入敌军或耐久打光就失效）。
玩家因此多了一个动作：把步兵挪进防空阵地，让高炮替它补对空火力。

**四、修掉一个真 bug：移动还在"点格就走"。** 移动功能移进菜单之后，
`onHexClick` 里"选中单位后点可达格直接 doMove"那两处没跟着加守卫，
所以不进菜单也能走。现在只有 `state.mode === 'move'` 时点格子才会移动。

**五、体检表 P1 逐条修。** 见 `docs/10` 的修订记录。其中最值得说的一条：

> 菜单页和引擎各有一份解锁规则，`levelcheck [9]` 一直在比对——但它只测了
> "零进度"和"全通关"两种极端。**中间态没人测**：玩家通关第 3 关、没打附属关 C3B，
> 菜单页把他锁在"先通过「岚口机场保卫战」"上，而引擎里第 4 关早就开了。
> 现在前置关系由引擎算（`accessPrereq`）经 `data/levels.js` 带给菜单页，
> 规则只剩一份；同时 `levelcheck` 加了第三种状态，并做了反向验证
> （把菜单页改回旧写法，断言如期变红：`C4：首页 锁 / 引擎 可进`）。

**六、第一张立绘接进来了。** 第 1 边防旅旅长（`story.portBde1`，
`game/assets/story/port-bde1.webp`，480×640，27.5 KB）。它在两处露面：
第一关简报三段对话里旅长那一句（师长说完接的那句），以及「1-1 营离开工事」那条事件。

> 立绘卡位从此分两层：`portBlue` / `portRed` 是**通用位**（一整边共用，缺图显示「立绘位」），
> `port<番号>` 是**角色位**（有确定脸的人物，一人一槽）。
> **一个人有专属位之后就不能再挂回通用位**——同一张卡里旅长和师长对话，
> 共用一位等于把两个人画成同一个人。通用位空着是对的。
>
> 顺手补了四条断言（这条链路原来是完全裸奔的）：台词引用的 `portrait` 键必须存在
> ——写错一个字不会报错，只会静默渲染成「立绘位」，而玩家会当成"本来就该有图没做"，
> 不会当 bug 报上来；扫描确实命中过若干键（否则上一条是空转）；
> 填了的文件必须真在磁盘上；尺寸必须 3:4（比例不对 `cover` 会对称裁切，**头顶最先没**）。
> 四条都做了反向验证：改错键名、换成 480×480、换成不存在的路径，各自如期变红。

### v4.6.1 / v4.6.2 改了什么：体检的 P0/P1/P2，都是"出错时玩家什么都不知道"

完整清单和证据在 `docs/11-综合体检报告-v4.6.md`，这里只记结果。

**一、存档导入能执行任意脚本（真的复现过）。** 伪造一份存档，把兵牌名写成
`"><img src=x onerror=...>`，导入后脚本就在玩家页面上跑起来了（实测 `pwn1=1`）。
这是两道门同时没锁：

- **数据通道**：`validateSave()` 原来只看 `v` 和 `lv`，然后把整段 JSON 原样写进
  localStorage。现在兵牌名 / 简写 / 编制号不许带 `<>&"'` 与控制字符，地图逐行验长度
  和地形字符，战报限量限长，工事 `kind` 必须是真工事，`mods.label` 与牌组卡 id 走白名单。
- **渲染出口**：新增 `esc()`，修了 4 处拼接（兵牌 `title` / 简称、单位面板名、
  行动气泡简称、可攻击目标列表）。`renderLog()` 改成逐条 `textContent` + `cls` 白名单。

> 两道锁都要有。只修入口的话，老版本存下来的档、将来新加的字符串源照样能进来；
> 只修出口的话，脏数据会一直在内存里转，迟早撞上第 26 个 `innerHTML`。

**二、存档写失败是完全静默的。** 隐私模式 / 配额满时 `setItem` 直接抛错，
而 `saveGame()` 只 `return false` —— 17 个调用点没有一个看返回值。
玩家能安安稳稳打完一整局，关掉标签页回来发现还在第一关。
现在失败会：顶栏亮一个常驻「存档异常」胶囊（**点开就是 HQ 导出页**，因为写不进去时
读也是空的，"重试保存"按钮只会让人连点十次都是失败）+ 第一次失败时一条横幅 + 战报留一行。
连续失败**只提醒一次**，写成功之后胶囊自己收起来。

**三、错误兜底挂在脚本最后，救不了启动期崩溃。** 原来 `window.onerror` 注册在 8306 行，
语法错误时整段脚本根本不执行，监听器装不上——表现不是白屏，而是"骨架在、棋盘空、
按钮点不动"，而且没有任何解释。现在 `<head>` 里一段独立 `<script>` 先装监听和看门狗。

**四、顺手修的两件。** ①`tools/load.js` / `check.js` 抓"第一个 `<script>` 块"，
兜底脚本前移之后它就排第一，两个工具会去加载那 30 行然后报"未导出 `__WAR__`"，
改成取**最长**的那块；②页面允许浏览器缩放（去掉 `maximum-scale=1, user-scalable=no`，
WCAG 1.4.4），棋盘手势本来靠 `#boardView { touch-action:none }`，不需要牺牲整页。

**五、三级灰阶重排。** `--ink3` 是 `#9A968C`，只有 2.64:1，却被 31 处 10–12px 的
说明文字用着——等于一整层字都读不清。现在 `ink2 #55524C` / `ink3 #6E6B64`，
对 `#F4F2EC` 分别是 6.95 / 4.75，全部过 AA；层次还在，没把两级并成一级。

**六、键盘用户完全进不了核心玩法。** 引擎原来 `aria-*` / `role` / `tabindex` / `:focus`
全是 **0 处**：352 个 `.hex` 是 `<div>` + click，Tab 跳不到；即便 Tab 摸到了顶栏按钮，
屏幕上也没有任何变化。现在按钮有 `:focus-visible` 描边；棋盘 `tabindex=0`，
方向键移格、回车执行（复用**同一个** `onHexClick`，不是另写一套），
`aria-activedescendant` 指向当前格，`#kbSay` 用 `aria-live` 播报
"第几行第几列、什么地形、谁在这儿"；HQ 是 `role="dialog" aria-modal`，
打开时焦点进面板、关闭时还给来处。

没有把 352 个格子都做成按钮：Tab 要按 352 下才路过地图、`renderBoard` 每回合重建 DOM
会把焦点丢光、而六角格是二维的——方向键才是它的自然操作方式，不是 Tab。

**七、钩子和 CI 只管半张网。** 钩子原来只在引擎改动时跑 `check.js`，而上次那个真 bug
（菜单页把第 4 关锁死）落在 `index.html`，它根本不看。现在钩子的**真源进了版本库**
（`tools/hooks/pre-commit` + `npm run hooks`）：引擎/数据/工具一动跑全量，
纯文档只跑快照一致性（否则写一段 README 要等 50 秒，等两次人就开始用 `--no-verify`）。
`.github/workflows/test.yml` 跑同一套 + 覆盖率门槛。**`.git/hooks` 不进版本库**，
换台机器 clone 下来是空的——所以安装器不是可选件。

**这一条上线当天就回本了。** CI 首跑红在 `export-levels --check`，而本地一直绿。
真因是 `srcSig`（`长度:哈希`）把行尾字节也算进去了：Windows 工作区是 CRLF，
Linux 检出是 LF，同一份提交两边指纹差 8920 字节（正好是引擎的行数）。
现在读入即归一化、比对两侧都归一，`.gitattributes` 也统一成 `eol=lf`。
**这类"只在我机器上过"的 bug，本地全绿是必然的、钩子也拦不住**——
只有把代码放进另一个平台跑才看得见。

**八、覆盖率第一次有了数字。** `tools/cov.js`（`npm run cov`）跑三支脚本、按字节算覆盖、
列出从未执行的函数和它们的行号。现在 **90.3%**（426 个函数块，298 个跑到），
CI 门槛 `--min=85`。数字本身不是目的——目的是让"哪里没人测"有个答案，
而不是靠"我有六百项断言"自我安慰。

**测试**：selftest 427 → **447**，briefcheck 98 → **161**，变异 23 → **40 条**。
再往后 v4.6.3 补了防空反击与指挥部空袭门槛两条规则、并修了手册的加粗与文案，
selftest 447 → **471**，briefcheck 161 → **164**，变异 40 → **46 条**。
新增的断言全部做了反向验证：把 `esc()` 改成恒等函数 → 6 条红；`renderLog` 改回
`innerHTML` → 2 条红；`saveBroken` 直接 `return false` → 3 条红；键盘七条
（不夹边界 / 不画光标 / 移动后不重画 / 不设 aria / 回车失效 / 不判焦点 / 关 HQ 不还焦点）
各自如期变红。

> 这一轮最大的教训写在报告里：**"修过了"和"有断言"都不是证据。**
> P0-1 之所以还能复现，是因为上一轮修完之后加的断言检查的是 `applySaveFile` 返回的
> 提示文案里有没有 `<b` —— 而那段文案里从来不会有 `<b`（标签是渲染端拼的）。
> 断言必须打在**真数据路径**上：这轮 `briefcheck [13]` 干脆绕过 `validateSave`
> 直接改内存里的 `state` 再 `render()`，看 DOM 里到底长不长 `img`。

### v4.6.3 改了什么：防空炮能反击了，指挥部不再被隔空点名

两条都是玩家报上来的，而且都是**规则写了、代码没这么做**。

**一、防空单位对空不设近界。** 以前 `canCounter()` 有一句一刀切的守卫：贴到防守方
近界以内就不算反击。本意是"榴弹炮打不了自己脚下"，但它顺带把防空营也废了——
防空营射程 2，敌机压到同一格时距离是 1，于是**敌机贴脸时高炮干脆不还手**。
兵种说明里一直写着"对空目标不设近界"（`TYPE.aac` 的 `abil`），代码从没这么做过。
现在那条守卫只对**地表目标**生效。放开是安全的：上面已有一道闸拦掉"非防空单位
反击空军"，能走到这里的只剩 AA 兵种与 `F` 阵地驻军，炮兵照样打不了天上。

**二、空袭指挥部需要目标指示。** 指挥部是 `str 2 / rng 0` 的固定靶，
`scoreTarget()` 又给 HQ 加 0.8 权重，于是 AI 会拿飞机隔着一整个战场把师部点名抹掉——
玩家连把高炮挪过去的时间都没有。现在敌方空军打 HQ 需要有人替它指示目标：
**侦察单位 ≤2 格，其他地面/水面单位 ≤1 格**（已被贴到门口），航空单位不算指示者
（飞机自己给自己指示等于没这条规则）。另外 HQ 遭空袭时攻击方再 −0.20——
前者管"能不能看见"，后者管"看见了也炸不利索"。

规则改了就得给关卡补工具，否则永不生效：C4 给红方补了一支**旅属侦察连**（`R1R`，
摩步旅本来就有这个编制，之前只是编制表上缺一格），玩家也因此多了一件有回报的事
——**打掉摸上来的侦察连，指挥部就安全了**。同时删掉红方第 2 攻击机中队（`R3D`）
做平衡补偿：规则一上，红方飞机不再浪费架次砸 str 2 的师部，而是集中砸城里的炮兵营，
那是同一批飞机在干正事——**原来那 20 个点的达成率本来就靠"AI 浪费架次"撑着**。

> 自战对照（40 局固定种子）：改规则但不做补偿，蓝方达成率 90% → **67.5%**；
> 删掉 `R3D` 记的是回到 **80%**（v4.12 复现不出来，实际稳定在 70–72%；爽局区间已改成 65–90%）。
> 注意这不是"规则太狠"，是**原来那 20 个点本来就靠 AI 浪费架次撑着**——
> 同一批飞机改去砸炮兵营之后，浮出来的才是真实难度。

**三、手册的加粗一直是原样的星号。** 兵种说明里到处写着 `**重点**`（光第 4 关的图鉴就有 28 处），
而渲染时是直接拼进 DOM 的——玩家在手机上看兵种图鉴，满屏 `**行动域仍是地面**`。
数据一个字没错，错在渲染口少了一道转换：现在 `bold()` 在拼 HTML 的地方统一转成
`<b>`，成对的才转，落单的星号原样留着（宁可露一个星号，也不要吞掉半句正文）。

**四、文案里混进了代码层与超时代的东西。** 玩家看到的是
「（atk 里没有 air）」「（check.js 会拦）」「沿河流 `~` 与浅海 `s` 航行」，
以及战斗机"挂着空空导弹去打地面目标"——**本作的技术水平对标二战**，
螺旋桨战斗机用的是机枪与机炮，没有导弹这回事。这一轮把这类说法全换成玩家语言：
"不携带对地武器""贴着敌军不会被拦住""机炮打不穿装甲"。

> 这类错不是"写错数值"，读代码永远看不出来——它只在**渲染结果**上才现形。
> 所以断言也打在渲染口：`selftest [34]` 把兵种说明 / 地形说明 / 战术卡 / 副官问答
> 全收上来，扫"代码字段名 / 反引号 / 超时代装备 / 没转换的星号"四类；
> `briefcheck [16]` 在真 DOM 里数 `.dex li b` 的个数，并要求可见文本里不含 `**`。
> 扫源码不这么写是有意的：注释里也有同样的字眼，扫源码会逼着人改注释。

**五、战时手册挪到菜单页。** 它原来只是引擎顶栏的一个按钮——兵种说明、战术卡、
副官问答恰恰是**开局之前**才该看的东西，让人先进战场再点开，等于把说明书锁在驾驶室里。
菜单页现在有「战时手册」，跳 `game/campaign.html?hq=dex` 直接落在图鉴页
（`?hq=1` 仍是存档页，向后兼容）。页签名走 `HQ_TABS` 白名单，表外的值回落存档页，
不会打开一个空面板。

**测试**：selftest 447 → **471**，briefcheck 161 → **164**，变异 40 → **46 条**。
新增六条变异（对空近界例外 / 目标指示判定 / HQ 空袭减伤 / 加粗不转换 /
页签清单缺 dex / 文案塞回空空导弹），逐条确认会红。

### v4.7 改了什么：防空阵地开始「赶走」飞机了

之前 `F` 阵地只有两个作用，而且都发生在**挨打的时候**：削减敌机 25% 攻击修正、
让驻军能还手。飞机不动，玩家就看不出高炮有任何威慑——
"高炮是用来把飞机赶走的"这句话，在数值上从来没有被表达过。

现在是持续效果：**半径 2 格内的敌军飞机每回合组织度 −12，且当回合不能原地休整**
（正常静止能回 12 点）。组织度乘进有效战力，掉到 60 的飞机这一趟只能打出六成力气。
来一次掉一次、越打越虚，只能飞回自己后方缓——这就是「驱散」。

**关键是下限。** 第一版没有下限，实测红方战斗机进城两回合就撞崩溃线，
整支航空兵等于被删掉（C3 达成率 55.0% → 77.5%）。现在掉到 40 就止住：
**高炮负责削弱，不负责把飞机打垮**，打下来是战斗机与防空营命中修正的活。

**关卡侧必须有配套，否则规则永不生效**：第 3 关城区新增一座预置阵地（城心，
半径罩住岚口市三个城格），简报加一行说明。红方战斗机中队从北面来，
要打城区就得进伞——位置本身就是这一关的教学。

#### 途中挖出来的根因：航空兵一直在吃地面补给场

写这条规则时"伞下不升反降"测不出来，因为飞机**根本走不到休整那一支**。
`supplyOf()` 只有辎重和舰船两个特例，**航空兵没有分支**，于是落进通用逻辑：
补给场 BFS 从本方陆上据点往外扩，敌境上空必然判「断绝」——
每架飞机一出生就背着 −30% 战力、每回合 −10 组织度。

这和舰队那条是同一类坑（水面格进不了 BFS），区别是海军那个一开局战报就写着
"断绝"，**航空兵这个看不见**：自战报表的"补给断绝单位"只统计蓝方，
红方飞机烂在天上只会表现为"敌方损失多一点"。修法是加一支 `isAir` 分支，
给「紧张」而不是「充足」——原来那 −30% 里有一半本来就该收，只是收错了地方。

**平衡账**（固定种子，自战 80 局）：C3 55.0% → **51.2%**（区间内，无需补偿）；
C4 81.3% → 72.5%（掉出爽局下沿），补一座码头阵地 + 把红方轰炸机战力
12 → 10（折回原有效值 12×0.70 ≈ 10×0.88）→ **75.0%**。

**测试**：selftest 471 → **493**（新 [35] 20 条），briefcheck 164 → **169**
（新 [19] 在真 DOM 里验面板那三句话），变异 46 → **52 条**（新增 6 条 + 1 条 `brief`，
逐条确认会红）。细节与两条假防线的教训见 `docs/12`。

### v4.7.1 修了什么：一格两层时点下去打谁

玩家报的：**防空炮打不到"自己据点头顶上"那架敌机**——点那格只是把自己的守备营选中了。

地表（陆 + 水）与空中是两层，一格可以同时站着两支。而 `unitAt()` 是**地表优先**，
`onHexClick` 又先判"这格是不是我方单位"就 `return`，于是点永远落进选中分支，
空中那支轮不到。**更糟的是地图早就答应了**：这种格子已被圈成可攻击目标（`.atk`），
点下去却只是换了个选中对象。

现在"格内有当前选中部队打得到的目标"排在"选中"之前（移动仍优先——飞机不挡地面通行）。
顺手修了同一个根的另一处：`炮火准备` 这类**指向敌方的战术卡**也点不到同格飞机，
因为原来看的是 `unitAt()` 的地表那一支。规则写进 `docs/02` §4.8。

同一个函数里还踩了个新坑：`onHexClick(r, c)` 里原本 `const c = cardById(...)`，
参数 `c` 是列号——以前只调 `cardFitsUnit(card, u)` 没出事，一旦要写 `unitsAt(r, c)`
就被这张卡遮住了列号，查出 0 支单位、静默回到老路。改名 `card` 才对。

**测试**：selftest 493 → **503**（新 [36] 10 条，走真实点击：直接调 `doAttack`
抓不到这个 bug），变异 52 → **55 条**（开火退回选中 / 不看能不能打 / 战术卡只认 `unitAt`，
逐条确认会红）。

### v4.5 改了什么：第四关「波尔瓦萨港」

**这一关是海军框架的第一次实战。** v4.4 把领域、目标分类、舰炮射程全做完了，
但五张地图里一格浅海都没有，九型军舰没有一个能上场的舞台。现在有了：
港内泊着 4 驱 2 巡 1 战列，炮口对着岸上，射程从 8 格到 20 格。

**新地形 `p` 港口码头**（陆地，`cost` 2，防御 +0.50）。它不是泊位——舰队停在相邻的浅海里，
码头是舰队的**补给依托**。

**新兵种 `mrb` 海军步兵营**（港口守备精锐，战力 10，可占点）。它的 `dm` 仍是 `ground`：
这是"在海军基地里服役的步兵"，不是舰船，照常受地形与堆叠限制。

#### 三个被这一关逼出来的规则修补

写关卡时撞上的三个洞，都不是"新功能"，是原有规则的漏：

1. **舰船一出生就"补给断绝"。** 补给场的 BFS 只走 `cost < 99` 的地面格，水面格进不去，
   于是每条船开局就被判 −30% 战力——战报上只显示"断绝"两个字，看不出是规则漏了。
   现在海军单位单独判：离**我方控制的码头** 3 格内充足、6 格内紧张、再远断绝。
   码头被敌军占了就别想补给，"守港口"这件事因此有了价格。

2. **`survive` 关不能因为"敌军被清空"就提前通关。** 第 4 关的简报是
   "坚守 20 回合 **或** 敌军全灭"，两个条件并列。但第 4 回合把第一波打光就判胜，
   后面三波还在路上——所以加了 `allWavesIn()` 前置：**波次没全部入场，不算全灭**。

3. **附属关不该挡主线解锁。** `levelAccess` 原来倒着找第一个 ready 的关当门槛，
   于是第 4 关卡在"先通过岚口机场保卫战"上。现在 `sub:true` 的关直接跳过。

#### 平衡：这一关是「爽局」，自战 100 局 85%

设计定调很明确：**这一关是爽局，要让玩家爽一爽**。七条军舰在港内持续火力支援，
敌军一波接一波往上撞，最后被碾平。所以它不按正关的 45–60% 判，
而是单独一个区间——这件事写进了数据（`LEVEL.pace = '爽局'`），
自战脚本读它，报表里的区间文案也跟着变。

调平过程本身值得记一笔，因为它绕了一大圈才找对方向：

| 阶段 | 红方规模 | 达成率 | 当时的判断 |
|---|---|---|---|
| 第一版 | 29 牌 203 战力 | 100% | 偏简单，加红方 |
| 加了一倍 | 42 牌 324 战力 | 5% | 太难，蓝方要加 |
| 回撤 | 38 牌 277 战力 | 20 局测出过 55%，也测出过 5% | **采样噪声** |
| 查病根 | 同上 | 43.3%（100 局口径可复现） | 见下 |
| 修完 | 同上 | **85%** | 达标（爽局区间） |

**病根不在数值，在两处"舰队被自己废掉"。**

一次对照实验指明了方向：把 7 艘舰的 `str` 全改成 1，达成率从 100% 掉到 **0%（我方全灭）**。
舰队不是"锦上添花的支援"，它是这一关的胜负手。既然如此，问题就变成"舰队为什么没在打"：

1. **补弹条件写成了「这一回合没开火才算」。** 舰船每回合都开火，于是永远补不上——
   12 发打完，20 回合还剩 8 回合，舰队在场但不再开枪。
   改成"停泊 + 补给充足就补"（码头弹药库是持续吊装的，不需要歇一回合），
   43.3% → **90%**。
2. **自战脚本每回合把战列舰往岸上挪一格。** 走过就吃"行进间射击 −0.10"，
   还可能走出 3 格的补给圈。真人不会开着战列舰追步兵，脚本也不该——
   这不是削弱脚本，是把脚本从"明显不会玩的走法"修回"最省事的走法"，43.3% 里有一半
   是这么丢的。

**事件 `海军步兵营死守要塞` 挂错过三次条件**，全靠自战报表的「从未触发」抓出来：

- 「本营战力掉到 40% 以下」→ 3.3%。守备工事厚、舰队把火力顶在前面，这个营轮不到被打残。
- 「本营开火 3 次」→ 4.0%。它守在要塞里，射程只有 1 格，而红方到 2 格外就停下用炮轰。
- 「要塞进入争夺」→ **0%**。100 局里红方一次都没踩进要塞那 3 格，只围不攻。
- 「第 8 回合要塞仍在我手」→ **100%**。这是这一关最硬的事实（100/100 局守住），
  语义也正好是"海军步兵旅把墙守住了"。

**结论**：自战 100 局 85.0%，要塞 **100/100** 局守住，城市 85/100（其余判争夺）。
我方损失 53%、敌方 84%——打得惨烈，但赢得稳，这正是"爽局"该有的形状。

另外两处结构性修正（它们不是数值，改完就不再走回头路）：

- **城市用 `rule:'contest'`**（比城内兵力），不再要求"整片城区一格都不能有敌人"。
  7 格城区里红方一个营蹭进来就判争夺，20 回合的仗当场作废——C3B 的跑道踩过同一个坑。
- **空中 AI 从"绝不进防空圈"改成"进圈扣 60 分"**。原来只要目标在防空伞下，
  飞机就一架都不来，战报上永远不出现"驱逐舰重创"，玩家也就学不到防空伞的作用。

**这里有个反方向的教训**：脚本的 45–60% 是给正关用的。
把爽局也往那个区间里推，结果是"守着不动挨 20 回合"——那不是这一关要卖的东西。
设计意图一旦定下来，就该写进数据，而不是靠下次跑报表时某个人还记得。

### v4.4 改了什么：陆 / 空 / 绿水 / 蓝水

先做的是**容器**，再做**里面的东西**——两件事分两步，因为混在一起做完就分不清
"是机制错了"还是"是数值错了"。

第一步是「行动域」（domain）：以前"这支部队能走哪"散在三处硬编码
（`moveCost` 里认 `type === 'avn'`、防空压制里再认一遍、AI 里再认一遍），
加第二型飞机时三处都得改，漏一处就是"新飞机能飞，但不怕防空"。
现在只有一处：兵种表里一行 `dm`。

第二步是把 13 型航空与海军兵种填进去（`fgt`/`atk`/`bmb`/`trp` + 绿水 3 型 + 蓝水 6 型
+ 伞兵），并加了一套**目标分类**：能走哪（domain）和打谁（tclass）是两件事，
潜艇在水上机动但按 `sub` 算，所以没有对潜装备的战列舰打不了它。

| 领域 | `dm` | 走得的地形 | 和谁挤一格 | 谁能打它 |
|---|---|---|---|---|
| 地面 | `ground`（默认，可不写） | `cost < 99` 的一切 | 地表一格 2 支 | 所有兵种 |
| 空中 | `air` | **任何地形都是 1 点** | **一格 1 支，且不与地面互斥** | 只有 `aa:1` 的兵种和航空兵 |
| 绿水 | `green` | 河流、浅海 | 一格 1 支 | 所有兵种 |
| 蓝水 | `blue` | 浅海、深海 | 一格 1 支 | 所有兵种 |

**地形表加了第二个坐标 `nav`。** `cost` 是地面机动（99 = 地面过不去），`nav` 是水上机动
（有这字段就能航行）。刻意**没有**把河流的 `cost` 改成一个能走的数字——那会让布雷、
筑垒、地形面板这些地面逻辑悄悄把水域当成陆地，而且改的时候不会报错。

**两层的堆叠空间。** 飞机和地面部队在同一个格子里互不占位（`layerOf()` 分 air / surface），
所以机场上空盘旋的飞机可以压在满编守备营头顶。但**同一层里该挤还是挤**：
空中一格 1 支（`SLOT.air = 1`），水面也是 1 支——炮艇不是步兵，没法并排停。

**控制权 / ZOC / 工事 / 布雷一律只认地表。** `unitAt()` 改成"地表优先、空中回落"：
敌机飘在要点上空不改归属、不产生 ZOC（自己也不受 ZOC），这一点是刻意的——
否则一架侦察机飞过去就能锁死一整条走廊。

**空中不吃地形防御加成。** 城市 +0.20 是给躲在楼里的人，不是给飞在楼上的人。

**打谁由兵种表的三个字段决定，不再往战斗函数里塞 if：**

| 字段 | 作用 | 例子 |
|---|---|---|
| `atk` | **主动**能打哪些类别（`air`/`land`/`ship`/`sub`） | 轰炸机 `['land','ship']`——挑不了飞机 |
| `vs` | 对某一类的攻击修正 | 战斗机 `{air:+0.60, land:-0.50}` |
| `tc` | 目标分类改写 | 潜艇 `'sub'`——不是普通水面舰 |

反击**不看** `atk`。所以"轰炸机仅可对空反击"是两句话拼出来的：`atk` 里没有 `air`
（主动挑不了），`canCounter` 放行（挨咬时自卫机枪照响）。防空压制也从
"按代号认 `aac`/`aab`"改成读 `aaRange`/`aaPen`，舰载防空才真的生效。

**运输机是"关卡属性"不是"兵种属性"。** 载什么写在单位的 `load` 上
（`supply` 投补给 / `para` 投伞兵连），同一型运输机这一关运弹药、下一关运人。
空机不显示按钮——画一个点了没反应的按钮比没有按钮更让人困惑。
投不下去时**不扣载货**：算错位置只该损失这一回合，不该赔掉一整趟运输。

> **还没做的**：五关地图里**一格浅海 / 深海都没有**，海军框架暂时没有实战舞台；
> 伞兵与运输机也没有关卡在用。第三关的「敌航空连」已按新规格换成「敌战斗机中队」
> （射程 1 格），这是目前唯一在战场上的新兵种。
> 加一型新兵种仍然只需在兵种表里写几行——`selftest` 的 `[26]`（怎么动）
> 与 `[27]`（打谁）两节守的就是这个"自动"。

### v4.2 改了什么

**教学关从"打不赢"改成"靶场"。** 序章原来摆六支真兵在对面，红方第 1 回合就能抢下要点；更糟的是本关 `winScore` 等于全部要点分值，`checkEnd` 里那条 `redScore() > maxRed - winScore` 就退化成 `redScore > 0`——红方一占要点当场判负。实测 120 局达成率 0%、平均只走到第 1 回合，玩家连第 2 条教官提示都见不到。

按新手引导的通行做法（安全失败 / 一次只教一件事 / 靶场式练习）重做：

- 红方全部 `mov:0`、`rng:0`——靶子不会推进、不会抢点、不会主动开火，玩家不可能被打崩。只留一个 `rng:1` 的警戒班，用来让"攻击预览里的比值"有意义。
- 回合 6 → 7，第六科目之后留一个复习回合，不作弊也能按时走完。
- 新增 `LEVEL.drills` 科目表，常驻左侧「战役态势」面板，当前该练的那条高亮——战报会被后来的条目顶走，清单查得到。
- `checkEnd` 的即时判负加了一道守卫：`winScore >= maxRed`（要求全控）的关不走即时判负，交给回合末判，玩家还有打回来的机会。

**事件触发器从"看回合钟"改成"看玩家动作"。** 见上文触发词表。配套加了 `noteAct`（每个兵牌自己记一份动作计数器）与限时修正（`mod` + `turns`）。

**编制表一致性审计（`tools/orgcheck.js`）。** 按 `corps` 分组、用指挥牌名字当番号，比对各关编成。查出并修掉的真问题：

| 独立第 1 旅 | 第 3 关是 3 个**守备营**，机场关变成 2 个**步兵营** | 统一为守备营 |

### v3 改了什么

**兵种表 12 类 → 24 类。** 加入守备营、摩步营、装步营、旅/师两级自行火炮、反坦克连、工兵连、防空营、四级指挥牌。每个兵种有自己的能力清单，点兵牌就能看到。

**守备营「为了祖国」。** 战力 7（低于步兵营），在本方控制的城市或机场要点内、或与之相邻时，战力 +3（7 → 10）、防御 +0.20。离开要地立即失效。

这条替代了原来的「出生点 6 格内 +0.10」——旧规则看不出动机，现在直接绑在「守的是什么」上。**它也是守备旅不能当援军的唯一机制解释**：出圈就掉回 7，还少 0.20 防御。

> v3.6 把基础战力从 8 降到 7、要点加成从 +1 抬到 +3：原来出城的守备营和步兵营一样能打，
> 编制定位形同虚设。现在城内 10 / 城外 7，是 1.4 倍的差距，才看得出「守备」两个字。

**反坦克连。** 对坦克营、装步营攻击 ×1.8（+0.80），对步兵 −0.40；被装甲攻击时防御 +0.15。有了它，装甲部队在平原上不再无解。

**防空伞。** 防空连半径 2 压制 −0.30，军属防空营半径 4 压制 −0.35，全军只有一个。部队必须收拢在伞下，离伞的炮兵会被航空连零损失地拆掉。

**三级指挥光环。** 师部（半径 3，+10）→ 旅部/群部（半径 2，+8），多光环取最高不叠加。**脱指时我方恢复 7、敌方恢复 12**——一个数值拉开两军性格，不加额外规则。

**兵牌精简（方案甲）。** 团部、群部不独立成牌，职务并入所辖第 1 营。师级兵牌从 15 / 18 降到 12 / 15，指挥链变两级，师部被毁惩罚从 −25 加重到 −35。

**三波投入。** 敌方第 1 回合摩步第 3 旅 + 独立坦克营 + 航空连（9 牌 / 57），第 4 回合装甲第 4 旅（5 牌 / 39），第 8 回合第 6 战斗群（9 牌 / 55）。压力分两次跳升，第 8 回合到顶点但只剩 4 回合。

**要点控制权改为持久化。** 占领后写进状态，守军出城作战不会丢城；只有敌军实际占据才易手，双方都有部队才算「争夺中」。要点格子按控制方染色（蓝 / 红 / 斜纹）。配套把两个核心要点从 8 格压到 3 格——8 格时 3 个守备营铺不满，敌人占一格就判争夺，守方永远清不干净。

**事件触发器。** 通用「条件 → 效果」总线，数据写在 `LEVEL.events`，加新事件不用改代码。

v4.2 把触发器从"只能看回合钟和要点归属"扩成"能跟着玩家的动作走"：

| `when.kind` | 什么时候成立 |
|---|---|
| `turn` | `{turn, until?}` 回合数到了（`until` 可圈一个窗口） |
| `control` | `{obj, side}` 要点归属变化，`side` 可为 `blue` / `red` / `contested` / `none` |
| `allControl` | `{objs[], side, turn?}` 若干要点同时归同一方 |
| `corpsBelow` | `{corps, side, ratio}` 某军战力掉到初始的比例以下 |
| `unitDead` | `{ids[]}` 指定兵牌全部阵亡 |
| `unitActed` | `{id, act?, times?}` 某支兵牌做过某类动作（`move`/`fire`/`fort`/`eng`/`pack`/`card`） |
| `unitAt` | `{id, obj?\|cells?}` 某支兵牌站到了某个要点 / 某几个格子上 |
| `unitBelow` | `{id, ratio}` 某支兵牌战力掉到开局的 ratio 以下 |
| `sideBelow` | `{side, ratio}` 整条战线战力掉到开局的 ratio 以下 |
| `firstBlood` | 全场第一次交火 |
| `escaped` / `unitEscaped` | `{count}` / `{ids[]}` 突围关的撤出计数 |
| `inZone` / `nearObj` | `{side, r0,r1,c0,c1}` 有部队进入矩形；`{side, obj, dist}` 有部队逼近要点 |

`effects.kind`：`log` / `banner` / `sfx` / `bgm` / `say`（可带 `beats` 数组播一段对话）/ `story` / `org` / `str` / `mod` / `spawn`。`mod` 加 `turns` 就是限时修正，左侧面板会标"剩 N 回合"，回合末自动失效。

`when` 可以写成数组，任一成立即触发——"敌军踩上跑道"既可能是 `red` 也可能是 `contested`，不用为同一个事件抄两遍 effects。

**死事件会被自动抓出来。** `check.js` 校验每条 `when` 指向的兵牌 / 要点 / 编制是否真实存在；`autoplay-campaign.js` 跑完会列出「从未触发」的事件。这条机制是补血的：事件写错 id 不报错、不崩溃，只会安静地永不触发——"205 装甲旅伤亡过半"就以 0% 触发率躺了好几个版本。

**五类工事。** 工事分五类，格内显示字母角标：**H 堑壕 +15%**（步兵自己就能挖）、**B 碉堡 +28%**（装甲进攻额外 −15%，耐久 3）、**P 要塞炮 +22%**（驻守炮兵射程 +1，限城区/丘陵，耐久 5）、**A 岸防炮 +18%**（限临河格，耐久 4）、**F 防空阵地 +10%**（耐久 3）。复杂的四种必须工兵营。工事永久、归属建造方，敌人占了也用不了，一格只留一处，但己方工兵营可以把堑壕升级成碉堡或要塞炮。

**工事抗炮击。** 工事不只是一层防御加成——它对**远程火力**另有一层专门削弱：H 堑壕 −0.45、B 碉堡 −0.65、P 要塞炮 −0.50、A 岸防炮 −0.45、F 防空阵地 −0.30。判定条件是攻击方为火炮或射程 ≥ 2 的远程单位；近战、反坦克、坦克冲击照常结算，不受影响。

这条规则的意义在于：**堑壕本来就是按"扛住炮火"修的**，对子弹用处有限、对炮弹非常有效。它也天然偏向守方——本关蓝方有工事，红方不筑工事，所以红方的炮兵优势会被压制一部分。反过来说，**没挖工事的部队在炮口下就是活靶子**，这给了步兵"整回合不动换 +15%"一个真正的动机。

**炮台真的会开火。** B/P/A/F 有**耐久**：攻击的伤害先扣耐久，扣光才轮到守军——一个满编装甲营拆一座碉堡通常要 1–2 回合，这段时间守军几乎不掉血。**P 和 A 每回合自动开火**：要塞炮对 3 格内敌军 2 点伤害（不打相邻格），岸防炮对 2 格内渡口/河岸敌军 3 点，都是**固定伤害、不吃组织度、不被反击**。哑火条件只有两个：格内有敌军（炮位被压制）、耐久归零。所以守要塞炮要把步兵放在炮位旁边。F 不开火，只把半径 2 内的敌方空袭压制 −25%。设计细节见 `docs/07-工事体系.md`。

### v3.6 改了什么（机制反馈六条 + 比例尺）

**单位堆叠与穿越友军。** 一格最多 2 支同阵营部队；有友军挡路的格子可以穿过，只是不能停下。
**操作方式：先点自己的部队选中，再点目标友军格**——只要那格没满 2 支，点下去就是移动过去堆叠，
不会再变成「切换选中」。堆满的格子显示 `×2`，再点同一格在两支之间轮换。
以前 `computeReach` 里一句 `if (unitAt()) continue` 把所有友军格都堵死，40 支部队抢 4 格渡口，谁都过不去。
交战规则刻意保持简单：攻击仍指向具体某一支，同格友军按 **50%** 计入防御协同（相邻格 35%）——
堆着守更硬，但伤害不摊，所以堆叠是机动手段而非防御万能牌。

### 炮兵

射程按 **1 格 = 1.5 km** 从现实火力换算，不是拍脑袋定的：

| 类型 | 现实射程 | 格数 | 近界 | 机动 | 转移后射击 | 弹药 |
|---|---|---|---|---|---|---|
| 旅炮兵营 `art` | 3–8 km | 2–5 | 2 格（3 km） | 6 | 需架设 1 回合 | 8 |
| 师重炮营 `hr` | 12–15 km | 3–9 | 3 格（4.5 km） | 4 | 需架设 1 回合 | 5 |
| 旅自行火炮连 `sha` | 0.8–5 km | 1–3 | 1 格 | 8 | 当回合就能射 | 6 |
| 师自行火炮营 `spa` | 0.8–5 km | 1–3 | 1 格 | 8 | 当回合就能射 | 6 |
| 反坦克连 `at` | 0.8–1.5 km | 1 | 1 格 | 5 | — | 4 |
| 坦克歼击车 `td` | 0.8–1.5 km | 1 | 1 格 | 7 | — | 4 |

**近界是真实现象，不是平衡手段。** 榴弹炮打不了自己脚下的目标——野炮贴到 3 km 内、重炮贴到 4.5 km 内就完全够不着，连反击都不成立（`canCounter` 会先查近界）。所以炮阵地前面必须有步兵挡着，"用装甲直插敌炮阵地"依然是划算战术。

**牵引 vs 自行，靠节拍分开。** 牵引炮（`art` / `hr`）必须在**展开状态**才能射击、在**收炮状态**才能转移，两个动作各吃掉一整回合。一个完整循环是：

> 射击 → 收炮（1 回合）→ 转移（1 回合）→ 架设（1 回合）→ 再射击

4 回合一轮，12 回合的局里一门炮最多挪两三次。师重炮 9 格（13.5 km）的覆盖范围就是拿这个节拍换来的——**射程是节奏买的**。兵牌上的斜纹即"已收炮、现在打不了"，单位面板里有对应的收炮 / 展开按钮。

自行炮（`sha` / `spa`）不需要这一套，移动当回合就能开火，可打带跑。这是它们贵的原因，也是它们射程只有 3 格的原因。

**坦克歼击车 `td`。** 与反坦克炮同档射程（1 格），但用自行底盘：机动 7、被装甲攻击时防御 +0.30（反坦克炮是 +0.15），不需要展收。本关暂未部署，作为下一关的编制预留。

**装甲突击。** 坦克有火炮稳定器，自行火炮有射击指挥系统，所以**只有它们移动后射击不受惩罚**；其他兵种本回合机动过再开火 −10%。再叠加「射击不消耗机动」，装甲就能在一个回合内"到位 → 开火 → 撤到掩体后"。装甲的优势不在数值，在**节奏**——机动 10 的坦克跑得掉，机动 4 的步兵跑不掉。

### 保留的机制

1. **组织度** — 战力之外的第二血条。损失战力掉组织度，断补给每回合再掉 10，整回合休整才恢复。营级单位对损失极其敏感，连续作战三回合基本失去进攻能力。
2. **ZOC** — 进入敌方相邻格强制停止。战线由 ZOC 形成。
3. **补给线** — BFS 扩散，不穿过敌方 ZOC。3 格内充足、6 格内紧张、更远即断绝。
4. **核心要点自持** — 只要城市/机场还在手里，被完全包围也只降到「紧张」。没有这条，围城两回合守军就自行崩溃。
5. **协同攻击** — 与目标相邻的友军自动加入，每支按 35% 战力计入，最多 3 支。

### 进入游戏与存档

进游戏有两条路，都从**菜单页**出发：

- 菜单页点某一关 → 引擎带 `?lv=<id>` 开局（过场照播、进度照存）
- 菜单页点**继续推演** → `?resume=1`，从离开的地方接着打，按钮下方写着「第 X / 12 回合」

导出 / 导入存档在菜单页的**存档管理**（跳到 HQ 的存档页）。

**自动存档，不用手动点。** 每走一步、每次攻击、每次施工、每个回合结束都写一次，关掉浏览器再打开就在原处。存的包括兵牌位置与残血、工事与雷区、要点控制权、已触发的事件、以及**被架桥改写过的地形**（最后这条最容易漏）。

存档放在浏览器本地（`localStorage`），因此：

- 换设备 / 换浏览器 / 清缓存 = 没有存档
- 隐私模式可能写不进去；这时游戏照常能玩，只是「继续」一直是灰的
- 打出胜负后存档自动作废，下次进来是新局

「重开」要点两下（第一下变成「确认重开」，3 秒后自动还原），防止误触丢掉一局进度。

### 操作

- 点我方兵牌 → 兵牌旁弹出**「行动」**小按钮；红框（可攻击目标）选中就有
- 点「行动」→「移动」→ 脚下才亮起**蓝格**，点蓝格走过去；淡蓝是只能穿过、不能停。再点一次「移动」或按 `Esc` 收回范围
- 点红框攻击；**同一格里有两支以上可打的目标时先弹「选择目标」**，点哪支打哪支。只有一支时仍然点一下就打，不多问一次
- **点敌方兵牌看它的编制**——战力 / 组织度 / 射程 / 弹药 / 兵牌能力都在右侧栏。这是只读的，不会挤掉你当前的选中；同一格里有几支敌人时再点一次换下一支，`Esc` 退回
- 点空白格查看地形
- 选中工兵会列出可建的工事种类（H/B/P/A/F），点种类再点本格或相邻格施工；步兵类只能挖 H 堑壕。工事格有蓝/红描边，左侧字母角标标明种类
- 选中辎重可「建立补给点」
- 「结束我方阶段」交给 AI

### 手机

地图是 20×14 格、宽约 960px，屏幕放不下，所以窄屏（≤860px）单独做了一套：

- **进游戏先看全图**，点任意格子会**自动放大到能操作的倍数**并以该格为中心，不用先找缩放按钮
- **单指拖动**平移，**双指捏合**缩放，右下角 `＋ / － / ⤢ / ◎` 是放大、缩小、回到全图、回到选中单位
- 竖屏地图在上、面板在下；**横屏自动切成左右布局**，地图能耗满屏幕高度，比竖屏好用
- 全图状态下地图没有可拖的余量，此时在地图上竖划是滚页面而不是拖地图
- 缩放/平移只在窄屏生效，桌面端完全按原来的布局走

## 发布与分享

仓库根目录的 `index.html` 是入口页（菜单 + 文档链接），GitHub Pages 直接指到根目录就能出链接。

**本地仓库已经初始化并提交完毕**（`git log` 可见 `苍屿战役 v3.4`）。只差关联远程仓库：

```bash
# 先在 GitHub 网页上新建一个空仓库（不要勾选 README / .gitignore）
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

然后在仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存后等一分钟，地址是 `https://<用户名>.github.io/<仓库名>/`。

以后改动只要 `git add -A && git commit -m "..." && git push`，Pages 会自动重新部署。

要点：

- 纯静态，没有任何构建步骤，推上去就能跑
- `.gitignore` 已排除临时截图与调试脚本
- 文档是 `.md`，GitHub 会直接渲染；Pages 上点开也会自动转成网页

终局要点归属（200 局 ×2）：岚口市 **200 全在我方**、机场 **我方 137 / 敌方 63 / 争夺中 0**、
青溪镇与西渡口 200 全在敌方、东渡口 **我方 142 / 敌方 58**。
（铺满战术后蓝方甚至有余力反推东渡口，这是旧脚本从没做到过的。）

> **v3.7 复盘：36% 是怎么骗人的**
>
> 自战脚本的蓝方有两个缺陷，都不在游戏规则里，而在代打逻辑里：
>
> **① 机动打分完全不读 `fortAt`。** 工兵辛苦修好的碉堡，没有任何单位愿意进去。
>
> **② 更关键：「钻工事」和「占满格位」是互斥的。** 核心要点只有 6 格
> （城区 3 + 机场 3），堆叠上限 2，物理容量 12 个位置。而控制权判定是
> 「要点内只要敌我单位同时存在就 `contested`」——**哪怕只被挤进一格，机场立刻失去控制**。
> 所以两支都挤进同一个碉堡，等于白送一格。
>
> 中间试过只加工事权重、不管格位：达成率反而从 36.0% 掉到 **28.0%**，
> 存活数却从 16.8 涨到 **20.1**。**人活着，要点没了**——这是整个误判最直接的证据。
> 最终修法是「覆盖优先于加固」：本要点内的空格 +8 权重，压过碉堡的 +6，
> 先铺满每一格，再往工事里叠第二支。
>
> 结论：**关卡数值一直没问题，是代打脚本不会打仗。** 咕咕实机试玩反馈
> "依托据点防御比较轻松"，与修复后的 68.5–74.5% 完全吻合。
>
> 注意 68.5–74.5% 是**"完美占位"的上限**，真人会犯错、会漏格，真实难度大致落在 **50–65%**。
> 因此 v3.7 数值不再调整，三个降难度开关全部搁置。
> 若要加难度，方向是**红方 AI**（它目前不会避开工事、也不会集中突破一点），而不是动数值。

事件触发率（200 局 ×2，现脚本）：两处渡口失守 100%、方面军主力渡江完成 71.5~78.5%、
205 装甲旅伤亡过半 0%、独立第 1 旅旅部被歼灭 78.0~79.0%。
（旧脚本下旅部被歼灭只有 19.5% —— 铺满战术后红方火力更集中地砸在要点上。）

> **v3.6 平衡记录**：这一版同时动了四个会互相抵消的东西——炮兵射程 +1、守备营基础战力 −1 / 要点内 +3、
> 敌方第三波提前一回合、红方配属可架桥的工兵。
> 逐个测过：只加射程时达成率 73.0%（200 局，太简单），只把第三波提前一回合能压到 40%（100 局，又太狠）。
> 最终凑到 53.0% 是**四件事叠加的结果，不是任何一个单项的功劳**——
> 想复现或再调，必须整体看，单独回滚任意一项都会立刻脱出区间。
>
> **205 装甲旅伤亡过半从 38.5% 掉到 0%**：守备营在要点内更硬、炮兵打得更远，
> 蓝方装甲旅不再被迫顶到一线消耗。这条事件目前是**死代码**，需要重新设计触发条件。

> **三个降难度开关目前全部搁置**（v3.7 复盘后确认数值没问题，不需要用；改在 `game/campaign.html`）：
> ① `WAVE_AT = { 2: 4, 3: 8 }` 波次各延后一回合 —— 约 **+3~5 点**；
> ② `minRange` 里野炮 2 → 1 格 —— 约 **+2 点**，代价是"火炮有近界"这条设定被削弱；
> ③ 直接给蓝方加一个守备营或反坦克连 —— 最稳，不动任何既有规则。
>
> 不要反向调工事抗炮击系数：它是**守方**优势，调低只会更难。

蓝方由启发式 AI 代打，修复占位缺陷后已经是**上限基线**——它每格都铺满、回合不浪费，
真人做不到这个精度，实际达成率只会更低。**别再拿自战数字当"真人难度"用。**
如果一定要给自战结果加个换算，现脚本 68.5–74.5% 大致对应真人 50–65%。

## 多关框架（v4.0）

关卡数据从单个 `LEVEL` 常量改成了 `LEVELS` 数组 + 一个可变的 `LEVEL` 指针。
**引擎侧 74 处 `LEVEL.xxx` 引用一行都没改**——切关只是把指针指到另一个对象。

### 每关的结构

```js
{
  // 元信息（关卡选择页用，引擎不读）
  id: 'C3', no: 3, name: '岚口要地争夺战', type: '防御',
  when: '第 3 天 · 10 月 8 日', where: '岚口 · 岚江东岸',
  teaser: '主力东撤，你们留下。守住岚口市与机场十二个回合。',
  ready: true,          // false = 只在时间轴上占位，地图与编制还没做

  prev: {               // 与上一关的衔接，按上一关结果分叉
    win:  '青溪渡口撑够了六个回合……',
    fail: '青溪渡口提前失守……'
  },
  intro: [ '……' ],     // 开场战报，数据驱动，newGame 里不再写死本关文案

  // 以下同原来的关卡字段
  maxTurns, cols, rows, map, objectives, events, story, units
}
```

### 时间轴就是连续性的载体

关卡选择页按 `no` 排成纵向时间轴，每行显示 **日期 · 地点 · 一句话提要**。
玩家一眼能看出「第 1 天 → 第 2 天 → 第 3 天」是同一场战役，而不是三个互不相干的关卡。

C1 北岭哨所、C2 青溪渡口目前 `ready: false`，在时间轴上显示为「制作中」的锁定行——
**已经占到位置了，做的时候只填数据，框架不用再动。**

### 两层存档不能混

| 键 | 存什么 | 生命周期 |
|---|---|---|
| `wargame.lankou.save` | 这一局现在打成什么样 | 回合中反复覆盖，**分胜负立刻清空** |
| `wargame.campaign.progress` | 整条战役走到哪一关 | 只增不减 |

分开的原因很实在：通关会 `clearSave()`，进度要是也写在那份档里，玩家一通关进度就跟着没了。
进度里又分 `cleared`（只记通关，决定下一关能不能进）和 `played`（连失败也记，决定下一关引用哪句前情）。

### 几条不显眼但重要的规则

- **失败不解锁下一关**，但会记进 `played`。所以「打输过」和「没打过」在下一关开场是两种不同的前情。
- **`prev` 前情只在上一关确实打过时才出现**。从菜单页直接跳到后面的关，不会看到自己没经历过的事。
- **每局 `newGame` 都从 `mapSrc` 重拷地图**。架桥会就地改写 `LEVEL.map`，不重置的话上一局架过的桥会留到下一局——这个 bug 单关时代就有，只是没人注意到。
- `?lv=C3` 直达某一关，`?resume=1` 续档，`?hq=1` 开存档页，`?nointro=1` / `?demo=*` 跳过过场且不写存档。

## 怎么改关卡

关卡数据在 `LEVELS` 数组里（当前关卡是 `LEVEL` 指向的那一份），每关结构等同 JSON：

- `map` — 字符画，20 列 × 14 行
- `units` — `wave:1` 开局；`wave:2` 第 4 回合；`wave:3` 第 8 回合；`wave:0` + `group` 为事件预备队，只在事件 `spawn` 时进场
  （波次投入时刻在 `settlePhase` 里的 `WAVE_AT = { 2: 3, 3: 7 }`，数字是**上一回合末**）
- `events` — 事件表，`when.kind` 支持 control / allControl / corpsBelow / unitDead / turn，
  `effects.kind` 支持 log / org / mod / spawn（改数值）与 banner / sfx / bgm / say / story（只影响表现）
- `objectives` — 要点区域、分值、`kind`（city / air / town / ford，「为了祖国」只认 city 和 air）

地形字符：`.` 平原 / `f` 林地 / `h` 丘陵 / `t` 城市 / `a` 机场 / `#` 道路 / `=` 渡口 / `~` 河流

改完先跑 `check.js`，再跑 `selftest.js`（确认没破坏控制权/事件/工事），再跑自战看平衡动没动，最后跑 `roster.js` 同步编制表。

## 战前简报（剧本演绎）

点「开始新的战役」后不直接开局，先走一段过场：**三页作战公文 → 三句对话 → 接管指挥**。
内容全部写在 `LEVEL.story.briefing` 里，改剧本不碰任何逻辑。

```js
story: {
  briefing: {
    pages: [{
      order: '作战命令 · 第 3 号',   // 左上角文号，缺省「作战命令」
      kicker: '战役态势',            // 大标题上方的小字
      title: '主力走了，你们留下',
      paras: [                      // 段落；hl:true 会加左侧红线（引用块）
        { t: '正文……' },
        { t: '要强调的一句。', hl: true }
      ],
      nums: [{ k: '兵牌', v: '21' }, { k: '战力', v: '117', hot: true }]  // hot = 红字
    }],
    beats: [
      { who: '方面军司令部 · 电话', side: 'blue',
        text: '第 3 军今夜过江。\n守不住，西线就没有纵深了。' }
    ]
  }
}
```

- **翻页**：点「继续」/ 空格 / 回车。**跳过**：点「跳过」/ Esc → 整段跳过，直接开局。
- **打字机**在 `beats` 里（走 `FX.cutin`），公文页是整页淡入，不做逐字——公文逐字读起来太慢。
- **素材缺失只是降级**：`ASSETS.story.portBlue` 没有图时立绘位显示"立绘位"三个字，台词照常播。
  以后接配音，把 `FX._showCutin` 里的 `setInterval` 换成按音频 `currentTime` 推进即可，调用方不用改。
- **纸张在对话阶段故意不收起**：`#cutscene` 的 z-index（80）比 `.brief`（70）高，
  让对话直接压在纸上变暗。先收纸会露出地图再变暗，中间闪一下。
- **`?nointro` 与 `?demo=*` 一律跳过**整段过场，自动化跑局和截图都靠这个。
- 临时看某一页：`?demo=brief` / `demo=brief2` / `demo=brief3`；看对话：`?demo=briefbeat`。

> **v3.6 拆解**：
> 仅炮兵射程 +1 → **73.0%**（200 局。蓝方是防守方，射程变宽收益全落到守军头上）；

> 再叠第三波提前一回合 + 援军事件提前 → 56.0%（100 局）；
> 再叠红方架桥工兵 → **57.0%**（100 局）→ 200 局复测两次：**53.0% / 55.0%**，按 54% 计。
> 结论：**射程改动的代价必须用敌方节奏来还**，靠削自己人的数值还不回去。

四个教训：

1. **不要把「曾经拿到分」当「守住了分」。** 原判定在 `checkEnd` 里即时判超额，蓝方开局抢下西渡口（+5）就到 35 分，第 1 回合直接结束，自战 100% 且平均 1.00 回合。定位办法是逐步打印得分和单位坐标，发现装甲营停在渡口格上。现在超额只在第 12 回合末结算。
2. **两个相距 11 格的要点，守方是守不住的。** 蓝方 117 战力分成两半，红方集中打一侧。最后不是靠调数值，而是把机场地形防御从 0.10 提到 0.35（硬化道面加机库建筑群），让机场侧至少能站住。
3. **AI 的用法要写进 AI 里。** 装甲旅原本会主动前压到中场，两回合就被围歼；改成「敌人没逼近要点就不动」之后，它才真正起到机动预备队的作用。
4. **这套裁决在临界点附近极不稳定。** 城市防御 0.84 与 0.85 差 1%，达成率从 36% 跳到 72.5%；第二波提前 1 回合，从 44.5% 掉到 11.7%；推迟 1 回合，直接 0%。原因是七档 CRT 加固定损失，比值只要跨过 0.9 / 1.4 这些档位边界，战果就整体平移一档。**现在的平衡是「选点」而不是「调参」**——找到一个稳定点就锁住，别在附近微调。要根治得把损失值改成连续函数，属于下一版的事。
