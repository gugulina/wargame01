## 战役级 v3：岚口要地争夺战

双击 `game/campaign.html` 即玩，不需要服务器。

**局面**：20 列 × 14 行六角格。西部方面军主力正在后撤，岚江东岸只剩岚口预备役第 1 旅、西部军区独立第 1 旅和第 205 装甲旅。敌方先头部队已抢在撤退主力之前抵达东岸。12 回合（6 天），我方开局 21 个兵牌，敌方分三波共 22 个（148 战力）。

**目标**：终局控制 ≥26 分要点（总分 50）。26 分实际意味着两个核心要点都得守住，或者守住一个核心外加青溪镇和一个渡口。35 分算超额。

| 要点 | 分值 | 位置 |
|---|---|---|
| 岚口市 | 15 | 西南 |
| 岚口机场 | 15 | 东南 |
| 青溪镇 | 10 | 河北岸（守方基本拿不到，是诱饵） |
| 西渡口 / 东渡口 | 各 5 | 河上 |

### v3 改了什么

**兵种表 12 类 → 24 类。** 加入守备营、摩步营、装步营、旅/师两级自行火炮、反坦克连、工兵连、防空营、四级指挥牌。每个兵种有自己的能力清单，点兵牌就能看到。

**守备营「为了祖国」。** 战力 8（步兵营的 80%），在本方控制的城市或机场要点内、或与之相邻时，战力 +1（8 → 9）、防御 +0.10。离开要地立即失效。

这条替代了原来的「出生点 6 格内 +0.10」——旧规则看不出动机，现在直接绑在「守的是什么」上。**它也是守备旅不能当援军的唯一机制解释**：出圈就掉回 8，还少 0.10 防御。

**反坦克连。** 对坦克营、装步营攻击 ×1.8（+0.80），对步兵 −0.40；被装甲攻击时防御 +0.15。有了它，装甲部队在平原上不再无解。

**防空伞。** 防空连半径 2 压制 −0.30，军属防空营半径 4 压制 −0.35，全军只有一个。部队必须收拢在伞下，离伞的炮兵会被航空连零损失地拆掉。

**三级指挥光环。** 师部（半径 3，+10）→ 旅部/群部（半径 2，+8），多光环取最高不叠加。**脱指时我方恢复 7、敌方恢复 12**——一个数值拉开两军性格，不加额外规则。

**兵牌精简（方案甲）。** 团部、群部不独立成牌，职务并入所辖第 1 营。师级兵牌从 15 / 18 降到 12 / 15，指挥链变两级，师部被毁惩罚从 −25 加重到 −35。

**三波投入。** 敌方第 1 回合摩步第 3 旅 + 独立坦克营 + 航空连（8 牌 / 54），第 4 回合装甲第 4 旅（5 牌 / 39），第 9 回合第 6 战斗群（9 牌 / 55）。压力分两次跳升，第 9 回合到顶点但只剩 4 回合。

**要点控制权改为持久化。** 占领后写进状态，守军出城作战不会丢城；只有敌军实际占据才易手，双方都有部队才算「争夺中」。要点格子按控制方染色（蓝 / 红 / 斜纹）。配套把两个核心要点从 8 格压到 3 格——8 格时 3 个守备营铺不满，敌人占一格就判争夺，守方永远清不干净。

**事件触发器。** 通用「条件 → 效果」总线，数据写在 `LEVEL.events`。当前四件事：两处渡口失守（全军组织度 −3）、第 9 回合两核心仍在手（第 3 坦克军先遣支队进场）、205 装甲旅伤亡过半（该旅攻击 +12%）、独立第 1 旅旅部被歼灭（该旅组织度 −8、防御 −4%）。加新事件不用改代码。

**五类工事。** 工事分五类，格内显示字母角标：**H 堑壕 +15%**（步兵自己就能挖）、**B 碉堡 +28%**（装甲进攻额外 −15%，耐久 3）、**P 要塞炮 +22%**（驻守炮兵射程 +1，限城区/丘陵，耐久 5）、**A 岸防炮 +18%**（限临河格，耐久 4）、**F 防空阵地 +10%**（耐久 3）。复杂的四种必须工兵营。工事永久、归属建造方，敌人占了也用不了，一格只留一处，但己方工兵营可以把堑壕升级成碉堡或要塞炮。

**炮台真的会开火。** B/P/A/F 有**耐久**：攻击的伤害先扣耐久，扣光才轮到守军——一个满编装甲营拆一座碉堡通常要 1–2 回合，这段时间守军几乎不掉血。**P 和 A 每回合自动开火**：要塞炮对 3 格内敌军 2 点伤害（不打相邻格），岸防炮对 2 格内渡口/河岸敌军 3 点，都是**固定伤害、不吃组织度、不被反击**。哑火条件只有两个：格内有敌军（炮位被压制）、耐久归零。所以守要塞炮要把步兵放在炮位旁边。F 不开火，只把半径 2 内的敌方空袭压制 −25%。设计细节见 `docs/07-工事体系.md`。

### 炮兵

| 类型 | 射程 | 最小射程 | 机动 | 移动后射击 | 弹药 | 贴脸反击 |
|---|---|---|---|---|---|---|
| 旅炮兵营 | 2 | **1** | 6 | 可（−10%） | 8 | **可** |
| 师重炮营 | 3 | 2 | 2 | **不可** | 5 | 不可 |
| 旅自行火炮连 | 2 | **1** | 8 | 可（无惩罚） | 6 | **可** |
| 师自行火炮营 | 2 | **1** | 8 | 可（无惩罚） | 6 | **可** |

**直瞄 vs 曲射。** 旅炮兵营和两种自行火炮有直瞄镜，最小射程 1，可以放平了打相邻格，被贴脸也能反击——两条代价：贴到 1 格射击时攻击 −10%（目标在城镇/林地再 −10%，只在 1 格生效，正常 2 格曲射不受影响）；被贴脸反击时造成的损失减半。师重炮营保持纯曲射：最小射程 2，被贴脸零反击。

于是「用装甲直插敌炮阵地」依然是划算战术，但捅到轻型野炮或自行火炮身上会挨一口——不是白给。

**装甲突击。** 坦克有火炮稳定器，自行火炮有射击指挥系统，所以**只有它们移动后射击不受惩罚**；其他兵种本回合机动过再开火 −10%。再叠加「射击不消耗机动」，装甲就能在一个回合内"到位 → 开火 → 撤到掩体后"。装甲的优势不在数值，在**节奏**——机动 10 的坦克跑得掉，机动 4 的步兵跑不掉。

### 保留的机制

1. **组织度** — 战力之外的第二血条。损失战力掉组织度，断补给每回合再掉 10，整回合休整才恢复。营级单位对损失极其敏感，连续作战三回合基本失去进攻能力。
2. **ZOC** — 进入敌方相邻格强制停止。战线由 ZOC 形成。
3. **补给线** — BFS 扩散，不穿过敌方 ZOC。3 格内充足、6 格内紧张、更远即断绝。
4. **核心要点自持** — 只要城市/机场还在手里，被完全包围也只降到「紧张」。没有这条，围城两回合守军就自行崩溃。
5. **协同攻击** — 与目标相邻的友军自动加入，每支按 35% 战力计入，最多 3 支。

### 操作

- 点我方兵牌 → 蓝格可移动，红框为可攻击目标
- 点蓝格移动，点红框攻击，点空白格查看地形

- 选中辎重可「建立补给点」
- 「结束我方阶段」交给 AI

### 手机

地图是 20×14 格、宽约 960px，屏幕放不下，所以窄屏（≤860px）单独做了一套：

- **进游戏先看全图**，点任意格子会**自动放大到能操作的倍数**并以该格为中心，不用先找缩放按钮
- **单指拖动**平移，**双指捏合**缩放，右下角 `＋ / － / ⤢ / ◎` 是放大、缩小、回到全图、回到选中单位
- 竖屏地图在上、面板在下；**横屏自动切成左右布局**，地图能耗满屏幕高度，比竖屏好用
- 全图状态下地图没有可拖的余量，此时在地图上竖划是滚页面而不是拖地图
- 缩放/平移只在窄屏生效，桌面端完全按原来的布局走

## 发布与分享

仓库根目录的 `index.html` 是入口页（两个引擎 + 文档链接），GitHub Pages 直接指到根目录就能出链接。

**本地仓库已经初始化并提交完毕**（`git log` 可见 `苍屿战役 v3.4`）。只差关联远程仓库：

```bash
# 先在 GitHub 网页上新建一个空仓库（不要勾选 README / .gitignore）
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

然后在仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存后等一分钟，地址是 `https://<用户名>.github.io/<仓库名>/`。

以后改动只要 `git add -A && git commit -m "..." && git push`，Pages 会自动重新部署。

要点：

- 纯静态，没有任何构建步骤，推上去就能跑
- `.gitignore` 已排除临时截图与调试脚本
- 文档是 `.md`，GitHub 会直接渲染；Pages 上点开也会自动转成网页

## 怎么改关卡

关卡数据在 `LEVEL` 对象里，结构等同 JSON：

- `map` — 字符画，20 列 × 14 行
- `units` — `wave:1` 开局；`wave:2` 第 4 回合；`wave:3` 第 9 回合；`wave:0` + `group` 为事件预备队，只在事件 `spawn` 时进场
- `events` — 事件表，`when.kind` 支持 control / allControl / corpsBelow / unitDead / turn，`effects.kind` 支持 log / org / mod / spawn
- `objectives` — 要点区域、分值、`kind`（city / air / town / ford，「为了祖国」只认 city 和 air）

地形字符：`.` 平原 / `f` 林地 / `h` 丘陵 / `t` 城市 / `a` 机场 / `#` 道路 / `=` 渡口 / `~` 河流

改完先跑 `check.js`，再跑 `selftest.js`（确认没破坏控制权/事件/工事），再跑自战看平衡动没动，最后跑 `roster.js` 同步编制表。

四个教训：

1. **不要把「曾经拿到分」当「守住了分」。** 原判定在 `checkEnd` 里即时判超额，蓝方开局抢下西渡口（+5）就到 35 分，第 1 回合直接结束，自战 100% 且平均 1.00 回合。定位办法是逐步打印得分和单位坐标，发现装甲营停在渡口格上。现在超额只在第 12 回合末结算。
2. **两个相距 11 格的要点，守方是守不住的。** 蓝方 117 战力分成两半，红方集中打一侧。最后不是靠调数值，而是把机场地形防御从 0.10 提到 0.35（硬化道面加机库建筑群），让机场侧至少能站住。
3. **AI 的用法要写进 AI 里。** 装甲旅原本会主动前压到中场，两回合就被围歼；改成「敌人没逼近要点就不动」之后，它才真正起到机动预备队的作用。
4. **这套裁决在临界点附近极不稳定。** 城市防御 0.84 与 0.85 差 1%，达成率从 36% 跳到 72.5%；第二波提前 1 回合，从 44.5% 掉到 11.7%；推迟 1 回合，直接 0%。原因是七档 CRT 加固定损失，比值只要跨过 0.9 / 1.4 这些档位边界，战果就整体平移一档。**现在的平衡是「选点」而不是「调参」**——找到一个稳定点就锁住，别在附近微调。要根治得把损失值改成连续函数，属于下一版的事。
