# 防空压制（驱散）与航空补给口径

> 对应的版本：v4.7。规则正文见 `docs/02` §4.7，工事表见 `docs/04`。
> 这篇记的是**为什么这么定**，以及调平衡时量到了什么。

## 一、要解决的问题

原来的防空阵地（工事 `F`）只有两个作用，而且都发生在"挨打的时候"：

| 机制 | 作用点 | 玩家的感受 |
|---|---|---|
| `aaPenalty` | 敌机**攻击的那一格**在伞下 → 攻击修正 −25% | 飞机照样蹲在城上空不走 |
| `aaBack`（v4.6） | 驻军遭空袭时可对空反击 +0.55 | 只有贴上来才感觉得到 |

两件都是被动修正。飞机不动，玩家就看不到高炮有任何威慑——
**"高炮是用来把飞机赶走的"这件事，在数值上从来没有被表达过。**

这次加的 `FORT.F.suppress` 补的就是这一条：伞下的敌机每回合掉组织度，
而且当回合拿不到原地休整。

## 二、规则的形状

```js
F: { ..., suppress: { rng: 2, org: 12, floor: 40 } }
```

| 字段 | 含义 | 为什么是这个值 |
|---|---|---|
| `rng` | 生效半径 | 与 `aaPenalty`、`runAI` 的 `inAA` 同口径。三处都写 2，改一处不同步就会变成"面板说被压制、命中修正却不算" |
| `org` | 每回合掉多少 | 12 ≈ 一次"没休整"（正常静止 +12）。一进一出，这一趟白来 |
| `floor` | 压到哪儿为止 | **40**。见下一节 |

代码上分三个函数，各自只干一件事：

- `aaSuppressed(u)` — 这个空中单位在不在敌方伞下（返回罩住它的阵地）
- `aaSuppressTick()` — 伞下的飞机掉组织度，返回名单给战报用
- `settlePhase` 里的 `!aaSuppressed(u)` 守卫 — 封锁原地休整

`aaSuppressTick` 单独拆出来是为了**测得动**：`settlePhase` 里还夹着工事自动开火、
限时修正倒计时、崩溃收拢、雷区、波次入场，为了看组织度变化去调它，
等于一次动了五件事。这和 `aaBunkerBonus` 当初被拆出来是同一个理由。

## 三、下限：驱散 ≠ 歼灭

第一版没有 `floor`，实测数据（C3 固定种子）：

| 配置 | 达成率 |
|---|---|
| 基线（没有这次改动） | 67.5%（40 局）／55.0%（80 局） |
| 只加阵地，不掉组织度 | 56.3% |
| 阵地 + 每回合 −12，无下限 | **77.5%**（红方战斗机进城两回合撞崩溃线） |

77.5% 不是"规则太有效"，是**把红方航空兵整支删掉了**。红方战斗机一中崩溃就不能
发起攻击（`targetsOf` 空 + `doAttack` 二道闸），等于这一关再没有空中威胁。

所以加了下限 40：组织度掉到 40 就止住。40 意味着有效战力只剩四成，
飞机继续留在伞下每回合都得拿四成力气打仗——它自己就想走。
**高炮负责削弱，不负责把飞机打垮**；把飞机打下来是战斗机与防空营命中修正的活。

## 四、中途挖出来的根因：航空兵在吃地面补给场

做这条规则时发现 `settlePhase` 里"伞下不升反降"测不出来——因为飞机**根本走不到休整那一支**。

`supplyOf()` 只有两个特例：辎重自持、舰船按码头距离。**航空兵没有分支**，
于是落进通用逻辑：补给场 BFS 从本方陆上据点往外扩，敌境上空必然 `!e` → 判「断绝」。

后果是每架飞机一出生就背着：

- 有效战力 ×0.70
- 每回合组织度 −10（`断绝` 分支，且这一支永远不给休整）

这和舰队那条是同一类坑（`docs/02` §补给里记过：水面格 cost 99，BFS 进不去）。
区别是海军那个一开局战报就写着"断绝"，看得见；
**航空兵这个看不见**——`autoplay-campaign.js` 的"补给断绝单位"只统计蓝方（第 404 行），
红方飞机烂在天上，报表里只会表现为"敌方损失多一点"。

修法：`supplyOf` 里加一支 `if (isAir(u)) return { label: '紧张', mod: 0.88, dist: 0 }`。
给「紧张」而不是「充足」，是因为原来那 −30% 里有一半本来就该收（远离基地），
只是收错了地方。

## 五、平衡账（都是固定种子，自战脚本）

| 关卡 | 配置 | 达成率 | 结论 |
|---|---|---|---|
| C3 | 基线 | 55.0%（80 局 seed 11） | 区间内 |
| C3 | 阵地 + 压制 12 + 航空补给修正 | **51.2%** | 区间内，无需补偿 |
| C4 | 基线 | 81.3%（80 局 seed 5） | 爽局区间内 |
| C4 | 压制 + 航空补给修正 | 72.5% | 掉出爽局下沿 |
| C4 | 再加一座码头阵地 | 73.8% | 还差一点 |
| C4 | 轰炸机战力 12→10 | **75.0%** | 达标 |

C4 的补偿不是给飞机加数值，而是**把有效战力折回去**：
原来 12 × 0.70 = 8.4，现在 10 × 0.88 = 8.8，与当初调平衡时的那个数基本一致。
第三座防空阵地（码头南端 `13,17`）则是补设定上的漏洞——
这一关的主题是守港，防空伞盖不住外泊位本来就不对。

> 小样本会给出互相矛盾的数：同一组改动 40 局测出 77.5%、80 局测出 63.7%。
> 结论一律以 80 局为准；改数值后要复核 100 局。

## 六、关卡侧改动

| 关卡 | 改动 | 理由 |
|---|---|---|
| C3 岚口 | 新增预置工事 `{ r:12, c:3, kind:'F' }`（城心，第 1 旅第 3 营阵位上） | 半径 2 罩住岚口市三个城格。**规则改了必须给关卡补工具**，否则玩家永远看不到这条 |
| C3 简报 | 加一行"市区已构筑防空阵地……它打不下飞机，但能把飞机赶走" | 规则不写在简报里，玩家只会觉得组织度掉得莫名其妙 |
| C4 波尔瓦萨港 | 新增 `{ r:13, c:17, kind:'F' }`（码头南端） | 见上，补防空伞盖不住外泊位 |
| C4 红方航空兵 | 轰炸机战力 12 → 10 | 折回原有效值 |

C3 选城心而不是城郊：这一关要守的是**城区**，红方战斗机中队（`R7`）从北面来，
要打城区就得进伞。位置本身就是这一关的教学。

## 七、玩家看到的东西

三处出口，缺一处玩家就会觉得"组织度莫名其妙在掉"：

1. **单位面板**：选中被压制的飞机时，多一行「状态：被防空压制」，
   写明阵地坐标、每回合掉多少、以及"飞出去才缓得回来"。
2. **战报**：每回合逐支报（不合并成计数），红方飞机被压制用 `hi` 色，
   蓝方被压制用 `r` 色。逐支报是为了让玩家认出"就是那架 3-1 被赶走的"。
3. **副官问答**：`防空阵地除了挡飞机，还有什么用？`

## 八、测试

- `selftest [35]`（20 条）：半径内外、只压敌方、只压飞机、阵地失效两种方式、
  掉多少、下限两侧、伞外 +12 / 伞下 −12 的对照、半径三个出口同口径、
  航空兵在敌境不判断绝。
- `briefcheck [19]`（5 条）：真 DOM 里验面板那三句话，以及飞出半径后消失。
- `mutcheck` 新增 7 条变异（含 1 条 `brief`），逐条确认会红。

### 两条踩过的坑

- **假防线**：验"地面单位不吃压制"时，把地面单位放在**阵地格上**——
  那样 `fortSuppressed` 会先把阵地废掉，删掉 `isAir` 判定这条断言照样绿。
  必须放在**伞下的空地**（距阵地 1 格）。变异自检当场抓出来了。
- **`mutcheck` 的 `replace` 只替换第一处**。`if (!fortWorking(f)) continue;` 在
  `aaPenalty` 和 `aaSuppressed` 里各有一份，锚点只写一行会打到前面那份，
  变异等于没生效。锚点要带上下文（这里用了三行）。
