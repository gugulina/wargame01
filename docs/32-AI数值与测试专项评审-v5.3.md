## 零、一句话结论

三块都有真问题，但性质不同：

- **AI**：设计文档（docs/22、docs/23）里的机制**写得很细、实现也在**，可 **"原地待命"不是一个合法候选**这一条根因，让三个机制（封锁线、驻桥抢修、要点守备）静默半速。这是本轮最值得修的问题，已修。

## 一、敌人 AI：一个根因，三处半速

### 1.1 ✅ P1「原地待命」不是候选（已修）

`computeReach` 把**起点从 `stop` 里删掉**（`campaign.html:7781-7782`），而：

- `runAI` 的地面分支只遍历 `reach.stop`（`ai.js:1636`）；
- 引擎的 `stepToward` 也只遍历 `reach.stop`（`campaign.html:11499`）。

于是任何"目标就是脚下"的部队——被 `cordonAssign` 钉在封锁线上的营、被 `aiRepairGoal` 派去守桥的工兵、被 `aiGuardWork` 按住做工事的守备——**永远拿不到"不动"这个候选，必然挪一格**。

实测（探针，`newGame` 后手动跑 `runAI`）：

```
C2  R3A [2,7] → [2,6]   R3B [5,9] → [5,8]   R3C [4,13] → [4,14]
C7B 工兵站在断桥上：goal=[6,2](自己脚下) → 实际挪到 [6,1] → 回合末结算"不在桥上"→ 不修
```

**已改**（两处）：

```js
// ai.js：目标就是脚下时当作"待命"，不调 doMove（不花行动、不推快照）
const stay = goal[0] === u.pos[0] && goal[1] === u.pos[1];
let best = stay ? u.pos.slice() : null;
...
if (!stay) { doMove(u, best); await sleep(200); }
```

```js
// campaign.html stepToward：目标是脚下直接返回
if (goal[0] === u.pos[0] && goal[1] === u.pos[1]) return;
```

**后果一（C7B 平衡被打破，已顺带重调）**：修好之后敌方工兵按设计真的驻桥抢修，C7B 从 **62.5% → 30%**。
这不是回退，是"设计承诺的行为第一次真的发生"。把达成线 `need: 3 → 2` 后实测 **60%（达成）/ 40%（超额）**，回到带内；简报与预告文案同步改成"至少拆掉两座"。

**后果二（C2 无变化）**：C2 修好后仍是 12.5%——它的瓶颈不在"待命"，而在 `count: 4/14` 与 AI 逃离轴，见 §二 M5。

## 二、数值设计

### 2.1 CRT 七档的期望（六面等概率，攻/守损失）

| 档 | 比值 | 攻均 | 守均 | 交换比 | 与名义比值的偏离 |
|---|---|---|---|---|---|
| 3:1 | ≥3.00 | 0.50 | 5.50 | **11.0** | +267% |
| 2:1 | 2.00–3.00 | 1.17 | 4.50 | 3.86 | +93% |
| 1.5:1 | 1.40–2.00 | 2.00 | 4.00 | 2.00 | +33% |
| 1:1 | 0.90–1.40 | 3.00 | 3.00 | **1.00** | 0 |

### 2.2 组织度在战斗里根本触不到崩溃线（M1，🔴）

崩溃线 25 需要 **25 点战损**的组织度损失（`org -= loss × 3`），而全作最大 `str` 是 20（C4 战列舰）：
`3 × 20 = 60 < 75`。也就是说**靠战斗永远打不出建制崩溃**，崩溃只对"断粮 −10/回合"和事件惩罚生效。

口径二选一（不要两头都改）：
- **(a) 接受现状**：把 `campaign.html:7584-7588` 的注释与副官词条改成"断粮/被压制才会崩"，1 行文档；
- (b) 把系数 3 抬到 9.4+，全部 18 关的 org 曲线重算——不建议。

**建议 (a)**：这版先改口径，别动能改崩全部关卡的系数。
