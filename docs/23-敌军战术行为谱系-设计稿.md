# 敌军战术行为谱系 · 设计稿

> 前置：`docs/22` 定的是**决策**（打不打、打哪、多狠），本文定的是**打法**（这一仗怎么组织）。
> 两者是两层：22 号文档管"值不值得"，这份管"怎么打"。
> 现状：十关的敌人本质上是同一支军队换了三档 aggressiveness——玩家打完 C1 再打 C6，
> 看到的是"同样的敌人更凶了一点"，不是"换了一个对手"。

---

## 〇、先说什么叫"有区分度"

一条战术要能进这张表，必须同时满足三条（缺一条就只是改了数值，不是加了战术）：

1. **玩家看得出来**——不看代码、不看战报，只看棋盘就能说出"它在干什么"。
   每条战术因此必须有 `tell`（首见迹象），并且切换时写一条战报。
2. **玩家破得了**——至少有一种有效应对。破不了的战术不是战术，是惩罚。
3. **不用新造引擎**——能落在现有的 goal / moveScore / fireGate / scoreTarget / opts /
   波次 / 工事 / 补给场上。确实需要新能力的，单独标注成本，不许含糊过去。

按这三条筛，二十多个战例里只有十二条真正可做，其余进"只作参考"（§二 末表）。

## 一、战例矩阵：从战役里抽动作，不抽结论

抽的是**可执行的动作**，不是"某某以少胜多"这种结论。同一场战役常常抽出两条，
因为它的不同阶段是两种打法（三所里既是"断退路"，也是"行军纵队"）。

### 1.1 歼灭战

| 战例 | 关键动作 | 抽成什么 | 现有原语够不够 |
|---|---|---|---|
| 坎尼（前 216） | 中军弓形后撤诱敌深入，两翼骑兵完成合围；罗马 8 万被 5 万围歼 | **两翼卷击**：正面只钉不打，两股兵力绕到侧后 | 够。单位有 `corps`，可按兵团分组；缺一个"侧翼是否空着"的判据 |
| 坦嫩贝格（1914） | 德军一个军团正面吸住，另一个军团绕到俄军侧后 | 同 T1，但强调的是**时间差**（正面先动、侧翼后动） | 够，用 `state.turn` 错开即可 |
| 基辅（1941） | 两个装甲集群向心突击，合围 60 万级 | 向心合围：两路各打一半，在敌后某格会师 | 够，需要一个"会师点"（取两路中点最近的通行格） |
| 孟良崮（1947） | 从敌重兵集团的**接缝**楔入，把整编 74 师"剜"出来打；4 个纵队阻援，3 天全歼 | **虎口拔牙**：不打最近的目标，打最孤立的；同时分兵阻援 | 够。`scoreTarget` 加"孤立度"，阻援组走"援军来路" |
| 三所里（1950） | 113 师 14 小时 145 华里，先敌 5 分钟抢占，卡住南逃北援 | **断退路**：不追尾巴，抢在敌人前面占住出口 | 够。`escapeCells / inEscapeZone / escapeGoal` 已有，只差"堵口"这个用法 |
| 辽沈（1948） | 先打锦州"关门"，再回头歼灭援军 | 关门打狗：先取**唯一退路要点**，再回头打被隔断的部队 | 够，但要 `win.kind` 配合；本作多数关是"守/抢"，用得少 |

### 1.2 防御战

| 战例 | 关键动作 | 抽成什么 | 现有原语够不够 |
|---|---|---|---|
| 一战德军弹性防御（1916） | 前哨只放少量兵，主力在纵深；敌炮火延伸后从两侧反击 | **弹性防御**：让出第一线，纵深反击（= docs/22 的 M3，一直没实装） | 够。`aiHoldGoal` 加状态机 |
| 上甘岭（1952，43 天） | 表面阵地被毁后退守**反斜面坑道**，炮火一停就出来反击；表面只留观察员 | **反斜面**：主力躲到敌方炮兵打不到的位置 | 部分。我方火炮有**近界**（art 2 格 / hr 3 格）——"贴到炮跟前"就是现成的反斜面，不用新机制 |
| 库尔斯克（1943） | 8 道防御地带，每道后面有坦克军等着反突击；反坦克支撑点 = 3–5 门炮 + 机枪 + 工兵 | **反坦克支撑点 + 装甲反冲击**：炮不动、人不动，坦克留二线 | 够。`atAmbushState`（静止 + 掩体 + 未被发现）已有，AI 只是不会"该停就停" |

| 硫磺岛（1945） | 放弃滩头，全岛坑道化，纵深火力点互相支援 | 强点网：不打野战，退到工事群里 | 够。`FORT` 已有；需要"退到最近未满的工事格"这条判据 |

### 1.4 机动 / 遭遇 / 伏击

|---|---|---|---|

### 1.5 只作参考的（明确不做）

| 战例 / 类型 | 为什么不做 |
|---|---|
| 中途岛、日德兰这类海空决战 | 本作海军只有"码头—射程—弹药"三条，没有编队与航向；做不出区分度 |
| 诺曼底式战略登陆 | 关卡是 16×22 的战术地图，没有"第二梯队上船"的空间 |
| 游击战 / 群众支前 | 兵棋里没有"民心"这个量，强行做就是加一个隐藏数值 |
| 核生化、电子战 | 与本作的规则基调（二战前后的陆战）不兼容 |

## 二、十二条战术（T1–T12）

编号用 T，避免与既有机制 M1–M9 混淆。每条给：**场景 / 触发 / 流程 / 迹象 / 反制 / 落点 / 成本 / 风险**。

公共部分先说清楚，后面不再重复：

```js
// 每回合末算一次，缓存进 state.ctx（不要每支兵各算一遍——M2 踩过）
ctx = {
  turn, left: LEVEL.turns - state.turn,
  ratio: aiSidePoints('red') / max(1, aiSidePoints('blue')),
  orgR: aiAvgOrg('red'), orgB: aiAvgOrg('blue'),
  objs: LEVEL.objectives.map(o => ({ o, ctrl: objectiveControl(o),
                                     gar: objectiveGarrison(o, other('red')),
                                     d: 最近我军到该要点的距离 })),
  frontWidth,            // 我方与敌方"接触线"有多宽（有敌军相邻的我方单位数）
  flankFree: [左, 右],   // 两翼 3 格内没有敌军
  gapMax,                // 敌军相邻两支之间的最大格距（接缝）
  reserve: 未接敌、org > 70、可机动的兵牌数,
  supplyCut: 我方断绝补给的单位数,
  fort: 敌方工事耐久总和（目标格）,
}
```

所有战术都遵守三条纪律（这三条是踩出来的，不是想出来的）：

- **只能改目标函数，不能改规则**。战术不碰 `doAttack` 的结算，只碰"往哪走、打谁、打不打"。
- **必须能被 M5 拦住**。任何战术都不许绕过止损线——"敢打"是编制问题，不是战术问题。
- **没有进展就要认输**。每条带 `giveUp`，连续 N 回合没拿下目标就退回该脾气的基线行为。

### A 族 · 歼灭（围、割、堵）

#### T1 两翼卷击（坎尼 / 坦嫩贝格）

| 项 | 内容 |
|---|---|
| **场景** | 敌军主力挤在狭窄正面（正面接触宽度 ≤ 6 格），两翼空虚，我方总点数占优 |
| **触发** | `ratio ≥ 1.2` 且 `frontWidth ≤ 6` 且 `flankFree 两侧都成立` 且 `reserve ≥ 2` |
| **流程** | ① 按 `corps` 把兵力分三组：正面组 1/3（只做接触交火，不许推进）、左右翼各 1/3；② 两翼组的 `goal` = 敌军阵线**后方 2 格**的通行格（不是敌军本身），`foePull` 归零，走位只认"绕过去"；③ 到达后 `goal` 改为敌军背后的退路格/要点，完成合围；④ 合围成立（敌军两侧后方都有我军）后转 T1-收口：全军 `contact` 打开，逐格压缩 |
| **迹象** | 正面敌人突然不打也不动，两股部队从你防线两端绕过去——**这就是坎尼的那一下** |
| **反制** | 两翼留预备队；或趁它分兵时从正面突围（分兵后正面只剩 1/3） |
| **落点** | `aiGoalFor` 加 `tactic==='pincer'` 分支；新函数 `aiPincerGroups()`、`flankFree(side, dir)` |
| **成本** | 【AI 侧】约 80 行 + 3 条断言 |
| **风险** | **分兵被各个击破**。v4.17 试过"离开要点轴去追人"，C2 直接 0%。所以门控必须硬：只在 `ratio ≥ 1.2` 且正面已被钉住时开，且两翼组不接敌（遇敌绕行） |

#### T2 虎口拔牙（孟良崮）

| 项 | 内容 |
|---|---|
| **场景** | 敌军阵形里有"突出部"：一支（或一个据点）与左右邻的间距 ≥ 2 格 |
| **触发** | `gapMax ≥ 2` 且 该目标距我方主力 ≤ 4 格 且 `ratio ≥ 0.9` |
| **流程** | ① `scoreTarget` 加"孤立度"项（`gapMax` 越大、离敌友军越远，分越高）；② 全军目标轴临时改指那一支/那一格；③ 抽出 20% 兵力做**阻援组**：`goal` = 援军来路上、距被围目标 3 格的那一格（不是去打架，是站在那里制造 ZOC）；④ 围歼完成后立刻回原目标轴 |
| **迹象** | 敌人不打离它最近的那支，突然全军转向一个"看起来不该先打"的硬点 |
| **反制** | 别让部队突出；被围的那支立刻往回缩；援军不要走大路 |
| **落点** | 新函数 `aiSalient()`（算 gapMax 与候选）、`aiInterceptGoal()`（阻援位）；`scoreTarget` 加一项 |
| **成本** | 【AI 侧】约 70 行 + 3 条断言 |
| **风险** | 打成消耗战。`scoreTarget` 的孤立度权重必须小（≤ 0.25），否则会为了"孤立"去打一支打不动的硬点 |

#### T3 断退路（三所里）

| 项 | 内容 |
|---|---|
| **场景** | 玩家在"撤离/突围"关（`win.kind === 'reach'`），我方追不上也吃不掉，但可以先到出口 |
| **触发** | `win.kind === 'reach'` 且 `escapeCells().length > 0` 且 我方有 ≥ 2 支高机动单位（`mv ≥ 8`） |
| **流程** | ① 把撤离区按连通性聚成 2–3 个"口子"（相邻的撤离格算一个口）；② 最快的两支 `goal` 直接设到**口子外侧一格**（不是撤离格本身，那里进不去）；③ 其余部队保持接触压力，把玩家往口袋里推；④ 口子被占住后，堵口部队转入防守（`hold` 姿态：不动、不回追） |
| **迹象** | 敌人不在你屁股后面追，而是跑到你前面去了 |
| **反制** | 提前打通出口；换一个口子；用炮兵/空袭打断它的行军 |
| **落点** | `aiGoalFor` 的 hunt 分支加"堵口"模式；新函数 `escapeChokes()`（撤离格聚类取外沿） |
| **成本** | 【AI 侧】约 50 行 + 3 条断言 |
| **风险** | 堵口部队被反吃。要求堵口单位 org ≥ 60 且不单独行动（至少两支同去） |

### B 族 · 防御（让、藏、反）

#### T4 弹性防御（一战德军 1916 / docs/22 的 M3）

| 项 | 内容 |
|---|---|
| **场景** | 我方守要点，敌军已突入第一线 |
| **触发** | 脾氣为 `hold` 或 `seize` 且 `前沿守军 org < 45` 或 前哨要点已丢 且 `reserve ≥ 2` |
| **流程** | ① 第一线部队后撤 1 格（不硬守，撤到第二线工事）；② 预备队在敌突入方向**两侧**集结（不是正面顶）；③ 等敌军 `org < 60` 或突入 ≥ 2 格，两侧同时反击，把口子扎上；④ 反击得手后回原阵地 |
| **迹象** | 敌人让开正面，你的突击部队越走越深，然后两侧同时出现敌军 |
| **反制** | 别追着退却的敌人跑；保持一支预备队；突入后立刻巩固侧翼 |
| **落点** | `aiHoldGoal` 加 `elastic` 分支 + `state.elastic` 状态机（三态：守 / 让 / 反） |
| **成本** | 【AI 侧】约 90 行 + 4 条断言（这是 M3 的实装，设计稿已有） |
| **风险** | 让得太多直接丢要点。必须硬约束：**核心要点不许让**（`onCoreObjective` 豁免），只让边角 |

#### T5 反斜面 / 贴炮（上甘岭）

| 项 | 内容 |
|---|---|
| **场景** | 我方守，敌方有炮兵且在射程外轰我 |
| **触发** | 脾氣 `hold` 且 敌方 `art/hr` 在场 且 我方该格在敌炮射程内 |
| **流程** | ① 计算敌方每门炮的**近界**（art 2 格 / hr 3 格）——近界之内它打不到；② 守军 `goal` 改成"敌方炮阵地近界内的那一格"，也就是**往炮跟前凑**；③ 到了之后就地防御（工事优先）；④ 敌炮收炮转移时跟上去 |
| **迹象** | 守军不躲炮，反而往你的炮阵地跟前贴——因为它们知道你打不着近的 |
| **反制** | 用步兵保护炮兵；把炮撤远；用直射火力（`sha/spa` 没有近界） |
| **落点** | `aiMoveScore` 加 `artyDeadZone` 项（`minRange` 已是现成判据） |
| **成本** | 【AI 侧】约 30 行 + 2 条断言 |
| **风险** | 贴上去被步兵打死。门控：只在"敌炮 ≥ 1 且我方 org ≥ 60"时开，且贴的是**炮**不是步兵 |

#### T6 装甲反冲击（库尔斯克）

| 项 | 内容 |
|---|---|
| **场景** | 我方有装甲预备队，敌军突击部队已突入但组织度掉下来了 |
| **触发** | 我方有 ≥ 1 支装甲且未接敌、`org ≥ 80`；且 敌军突入 ≥ 2 格 或 敌军前锋 `org < 60` |
| **流程** | ① 装甲全程不守线，藏在二线（距接触线 ≥ 3 格）；② 触发后一次性压向突入之敌的**侧后**（`goal` = 敌军后方 1 格）；③ 打完一仗无论结果如何都退回二线（不许追击） |
| **迹象** | 你的突击刚打穿，敌人坦克从侧面出来了，而且只打一下就退 |
| **反制** | 反坦克炮掩护侧翼；不要孤军深入；用侦察找出它的藏身点 |
| **落点** | `runAI` 的装甲分支 + `state.counterAttack`（一次性，用过要冷却 3 回合） |
| **成本** | 【AI 侧】约 60 行 + 3 条断言 |
| **风险** | 坦克被反坦克炮吃掉。所以只能打"侧后"，不能打正面 |

### C 族 · 夺点（砸、绕、合）

#### T7 炮火准备（旅顺 203 / M6）

| 项 | 内容 |
|---|---|
| **场景** | 目标要点有耐久工事，直接冲比值 < 0.5 |
| **触发** | 目标格工事 `hp ≥ 2` 且 我方可用炮兵 ≥ 1 且 弹药 ≥ 2 且 `left ≥ 3` |
| **流程** | ① 进入"准备"态：步兵停在 3–4 格（敌炮近界外、自己不进接触），只让炮兵打工事，目标选择改成"工事耐久"；② 每回合记一次 `fortDamage`，累计 ≥ 工事总耐久 60% 才算准备完成；③ 准备完成后步兵压上，`contact` 打开，炮兵转打守军；④ `left < 3` 时无论准备成没成都要上（否则时间不够） |
| **迹象** | 敌人不进反退，炮兵连着两回合砸同一个点，然后突然一起压上来 |
| **反制** | 反炮兵（打它的炮）、出击打炮、抢先修工事 |
| **落点** | `state.prepare = { objId, turns, dmg }`；`aiGoalFor` 加"准备位"；`scoreTarget` 对炮兵改用"工事价值" |
| **成本** | 【AI 侧】约 70 行 + 4 条断言 |
| **风险** | 准备期间被玩家反推。门控：准备态下步兵仍保留接触交火（不许站着挨打） |

## 四、调度器：怎么选、怎么不抽风

十二条战术不可能同时生效。需要一个"导演"，否则就是十二个 if 打架。

### 4.1 数据结构

```js
const TACTICS = {
  pincer: {
    name: '两翼卷击', family: 'A', prio: 70, minTurns: 3, maxFail: 3,
    when: ctx => ctx.ratio >= 1.2 && ctx.frontWidth <= 6 && ctx.flankFree.both && ctx.reserve >= 2,
    /* 族内互斥：A 族（围）与 C 族（夺点）不能同时当主轴 */
    conflict: ['salient', 'choke', 'bypass', 'converge'],
    goal: (u, ctx) => { ... },       // 覆盖 aiGoalFor 的返回值
    move: (u, p, ctx) => 0,          // 加到 aiMoveScore 上
    fire: (u, def, pv, ctx) => null, // 覆盖 aiFireGate 的返回值（null = 不管）
    tell: '敌军两翼展开',
  },
  ...
};
```

### 4.2 选择算法（每回合末一次）

```js
function aiTacticTick() {
  const ctx = aiCtx();               // 见 §二 开头
  const cur = state.tactic;
  /* 1. 冷却：刚切过的战术至少待满 minTurns，避免"每回合换一种打法"。
        M2 的重心每回合重算会让部队来回摆，这条是从那儿学的。 */
  if (cur && state.turn - cur.turn < TACTICS[cur.id].minTurns) return cur;
  /* 2. 失败计数：同一战术连续 maxFail 回合没有进展（目标没变、敌损 < 阈值）就作废 */
  if (cur && !progressed(ctx)) cur.fail = (cur.fail || 0) + 1;
  if (cur && cur.fail >= TACTICS[cur.id].maxFail) cur = null;
  /* 3. 打分：优先级 × 门控（门控是布尔，不满足直接排除） */
  let best = null, bs = 0;
  for (const id in TACTICS) {
    const t = TACTICS[id];
    if (cur && t.conflict.includes(cur.id)) continue;
    if (!t.when(ctx)) continue;
    const s = t.prio;
    if (!best || s > bs) { best = { id, s }; bs = s; }
  }
  /* 4. 滞回：新战术要明显更好才换（差 15 分以内不动） */
  if (cur && (!best || bs < TACTICS[cur.id].prio + 15)) return cur;
  return switchTactic(best && best.id, ctx);
}
function switchTactic(id, ctx) {
  if (!id) { state.tactic = null; return null; }
  state.tactic = { id, turn: state.turn, fail: 0 };
  /* 玩家必须能看见。切战术不写战报，等于十二种打法在屏幕上没有区别。 */
  log('敌军' + TACTICS[id].tell + '。', 'r');
  FX.banner(TACTICS[id].tell, 'r', 1800);
  return state.tactic;
}
```

### 4.3 三条硬规矩

1. **战术不能绕过 M5**。`aiFireGate` 里战术只能**抬高**门槛（更谨慎），不能压低。
   想"更敢打"只能改编制（加梯队、加炮），这是 docs/22 §7.2 那条教训的延续。
2. **核心要点不受任何战术保护**。T4 可以让边角，T8 可以绕过边角，
   但 `onCoreObjective` 为真的那一格，任何战术都不许"绕着走"——否则第一关的围城感又没了。
3. **同一回合只允许一个战术当主轴**。允许叠加的只有"姿态"类（T5 贴炮、T12 设伏），
   它们是 `move` 的加权项，不是 `goal` 的替代。

### 4.4 与现有 AI_STYLES 的关系

| 层 | 管什么 | 谁定 | 变更频率 |
|---|---|---|---|
| 脾气 `AI_STYLES` | 多凶：开火门槛、止损线、挑不挑软、追不追 | 关卡类别 | 整局不变 |
| 战术 `TACTICS` | 怎么打：往哪走、打谁、分几路 | 每回合末评估 | 2–4 回合变一次 |
| 机制 `M1–M9` | 判据：这一枪值不值、这一格该不该去 | 代码常量 | 不变 |

一句话：**脾气是性格，战术是这一仗的打法，机制是物理定律。**

### 每条战术的验收（写测试前先定）

1. **门控断言**：`when()` 在"该开"的局面为真、在"不该开"的局面为假（成对，防假绿）。
2. **行为断言**：进入战术后的 `aiGoalFor` 必须指到**战术特有的那一格**
   （不是原来的要点格）——这条最容易被写假，因为两者常常重合，要挑分得开的局面。
3. **退出断言**：`giveUp` 触发后，下一回合的目标回到基线。
4. **变异**：每条战术至少一条"删掉它就该红"的变异，写进 `mutcheck`。
5. **自战**：改动涉及目标函数 → 必跑 200 局；只在 `moveScore` 加权重 → 跑 100 局。
   判定带仍是 45–60%（`pace:'爽局'` 65–90%）。

## 七、明确不做的

| 想法 | 为什么不做 |
|---|---|
| 让 AI "学习"玩家的打法（记上一局的部署） | 存档要跟着变，跨版本兼容成本极高；而且玩家会觉得"作弊" |
| 给每个战术单独配一套台词 | 文案量翻十倍，收益是零——玩家看的是棋盘，不是台词 |
| 战术影响结算数值（比如"两翼卷击 +10% 攻击"） | 那就成了十二种 buff，不是十二种打法。所有战术只改"往哪走、打谁" |
| 让 AI 也会用战术卡 | 卡是玩家的资源与节奏，AI 用了玩家会失去"我有一手"的感觉；等玩家侧玩法稳定后再议 |
| 一夜之间把十二条全实装 | 每条都要配门控断言、变异、自战，十二条一起上等于十二个变量同时动，出了问题定位不了 |

## 八、一页纸总结

- 现在的敌人只有"三档脾气"，没有"打法"。这份稿子补的是**打法层**。
- 十二条战术来自二十多个战例，按三条筛子（看得见 / 破得了 / 不用新引擎）过滤。
- 全部落在现有的四个钩子上（goal / moveScore / fireGate / scoreTarget），
  不碰结算、不碰规则、不许绕过 M5。
- 需要一个调度器（每回合末评估、minTurns 冷却、失败计数、滞回、互斥），
  它的三条硬规矩是：不绕 M5、核心要点不绕、一回合只有一个主轴。
- 先做四条：调度器骨架、T3 断退路（修 C2）、T5 贴炮（30 行）、T7 炮火准备（修 C4）。

## 九、实装记录（v4.24 · P0 前两条）

### 9.1 调度器

`ai.js` 里新增一节，四个概念：

| 名字 | 作用 | 落在哪 |
|---|---|---|
| `AI_TACTICS` | 战术表：`prio` / `minTurns` / `maxFail` / `when(ctx)` / `plan(ctx)` / `tell` | 常量 |
| `state.tactic` | 当前战术 `{ id, turn, fail, at, assign, pending, escAt }` | 状态（**不进存档**） |
| `aiTacticTick()` | 每回合红方阶段开头跑一次，在 `aiHuntTick()` 之后 | `runAI` |
| `aiTacticAssign(u)` | 部队 → 指派格，`aiGoalFor` / `aiMoveScore` 读它 | 钩子 |

三条硬规矩落到代码上的样子：

1. **不绕 M5**：战术表里**没有 fire 钩子**。将来要加也只许返回 `Math.max(g, …)`。
   现在 T3 根本碰不到 `aiFireGate`。
2. **核心要点不绕**：T3 的门写着 `ctx.win !== 'reach'` 直接 false。
   撤离关的胜负不在要点上，所以"堵出口"在那一关就是"守阵地"，两条规矩不冲突。
3. **一个主轴**：T3 是 `partial: true`——只改两支兵的目标，其余照旧走要点。

调度器比设计稿多了一条：**认输冷却**（`TACTIC_GIVEUP_CD = 8`）。
设计稿里"fail ≥ maxFail → cur = null"下一回合会立刻重挑同一个战术，
"放弃"就只是一句战报。现在是认输 → 记 `state.tacBan[id]` → 八回合内不许回来。

### 9.2 T3 断退路：门槛被实测改了三次

| 版本 | 门控 | C2 达成率 | 结论 |
|---|---|---|---|
| 设计稿原样 | 撤离关 + 有口子 + 两个机动营 | **0%**（100 局） | 出口是渡口村那一格的死胡同，两个摩步营一站，12 回合连门都摸不到 |
| v2 | 再加"已有人过江" | **10.7%**（600 局；基线 12.0%，差 1.3 点 ≈ 0.4σ，噪声内） | 收口卡在突破口上，先头过江、后队被关在江这边。触发 0.33 次/局 |
| v3 | 改成"只差一支就赢" | 18%（= 基线） | **一次都不触发**：蓝方常在一个回合里把最后两支一起送进撤离区，红方根本没有 `escaped = 3` 的那一回合 |

v3 的教训记在这里：**按局面数字写的门槛赶不上局面的速度**。
"再走一支就赢"在纸面上是最漂亮的时机，可撤离是玩家在一个回合里连续执行的，
中间没有红方插手的缝。最后落回 v2 的"已经有人过江"，
并把 C2 的平衡问题单列出来——**堵口只会加压，C2 现在缺的是减压**。

`--diag` 因此加了一行"战术切换 / 战术认输"计数。没有它，v3 那次"0.00 次/局"
根本看不出来：达成率是 18%（与基线相同），报表上一切正常，
只有数一下触发次数才知道这套机制整局都没响过。

### 9.3 变异自检抓到的两条假防线

- **「断退路不看关卡类型」单改一行不会红**：`escapeCells()` 在非撤离关本来就返回空，
  `ctx.chokes.length` 那条闸会顶上来。两个守卫互为冗余，
  所以那条变异改成**整段门控一起删**，名字也改成"门控整段失效"。
- **「口子可以落在撤离区里」不会红**：C2 的口子候选里，最近的永远是区外的 `[4,13]`，
  把 `inZone` 过滤删掉，输出一点不变。改成"直接拿撤离格当目标"（v1 那种写法）
  才真的会红——它替的是整个"选外沿"逻辑。

两条都是"改了实现但棋盘上什么都没变"，正是变异自检存在的理由。
