# 35 · 地块美术与素材管线（v5.4）

> 目标：地图从"纯色块"变成"有材质的地图"，并且这条管线**可复现、可替换、可扩展**。
> 现状：12 张地块贴图已接进引擎，18 关全部生效；纯色仍作为兜底（贴图缺失时自动退回）。

---

## 一、美术方向：材质，不是符号

六角格是**独立裁剪**的：每一格只显示自己那一张图。这决定了什么能画、什么不能画。

| 能画 | 不能画 |
|---|---|
| 颗粒、短笔触、小色块、细碎波纹 | 等高线、街区图、田垄、长波浪 |
| 尺寸 ≤ 8px 的细节 | 任何要跨格连接的东西 |

原因很直接：低频特征（一条等高线、一条路）在相邻格里接不上，玩家看到的是"一格一张贴纸"。
第一版就是栽在这上面——丘陵的等高线缩到 47px 之后变成"瓦楞纸"，城市的街区变成"砖墙"。

**结论**：地块贴图只提供"这块地是什么质感"，不提供"这块地的形状"。
形状本来由地形符号和格子边界承担，视觉上不需要贴图再说一遍。

## 二、产出

| 项 | 内容 |
|---|---|
| 贴图 | `game/assets/terrain/{plain,forest,hill,town,air,road,ford,river,shoal,deep,port,rail}.png` |
| 尺寸 | 96×110（六角格外接矩形；格子用 `clip-path` 裁边，贴图铺满矩形即可） |
| 体积 | 12 张合计约 **160 KB**（PNG，`optimize=True`） |
| 生成器 | `tools/terrain-tiles.py`（Pillow；固定随机种子，同一条命令必出同一套图） |
| 一览图 | `docs/ui/terrain-tiles-preview.png`（带地形名，用来对比调参） |

**为什么用脚本而不是手绘**：可复现（换机器也出同一套）、可调（改一个数就换对比度）、
可替换（手绘同名同尺寸覆盖即可）、零授权风险。

## 三、管线怎么接的

```
tools/terrain-tiles.py
        │  生成 12 张 PNG
        ▼
game/assets/terrain/*.png
        │
        ├─ ASSETS.ui.hexPlain … hexRail      ← 唯一的登记处
        │        │
        │        ├─ TILE_OF：地形 class → 文件名
        │        └─ build-www.js 自动打包（引用驱动，不用手写清单）
        ▼
renderBoard：每格写 --tile / --tx / --ty
        ▼
campaign.css：.hex { background-image: var(--tile, none); background-size: 205% 204% }
```

几个刻意的决定：

1. **登记在 `ASSETS.ui`，不在 CSS 里写死路径**。这样 `check.js` 会 stat 每个文件
   （路径写错 = 地图悄悄变回纯色，不报错），`build-www` 也会自动把图打进包。
2. **`background-size` 用百分比**（205% × 204% = 96/46.8、110/54）。以后改 `HEX_S`
   不用回来同步 CSS。
3. **±8px 的确定性偏移**（`(r*13+c*7)%17-8`）。贴图比格子大，平移不露边，
   但相邻同地形格看起来就不一样了——这是最便宜的去重复手段，不需要第二套图。
4. **贴图缺省 → 退回纯色**。`var(--tile, none)` + `.t-*` 的 `background-color`，
   所以删掉一张图不会崩，只是那一类地形变回原来的样子。

## 四、和旧视觉的关系

| 旧的 | 新的 |
|---|---|
| `.t-*` 用纯色 | 底色保留（兜底） + 贴图提供质感 |
| 上一轮加的 CSS 渐变纹理（城镇网格、林地圆点、丘陵斜纹…） | **已移除**——和贴图叠在一起会脏 |
| 撤离区 `background: #C6DCC0`（换底色） | `box-shadow` 叠半透明罩，不盖掉贴图 |
| 夜战 `filter: brightness(.56)` | 不变，贴图一起压暗（压的是地面，兵牌照旧清楚） |

## 五、性能与兼容

- 12 张图、每张 96×110，浏览器只解码一次，300+ 格共用同一批 URL；
- 全部走 `file://` 相对路径（`assets/terrain/x.png`），**不需要服务器**；
- APK 里这些图随 `www` 打包，包体 +约 160 KB；
- 1× 屏：贴图 96px 铺 47px 格 → 缩放 2×，清晰；
  2× 屏：47 CSS px = 94 设备 px，贴图 96px 几乎 1:1，正好。

## 八、冬季变体（v5.4 已实装）

**8 张雪地贴图**：`game/assets/terrain/winter/{plain,forest,hill,town,road,rail,river,ford}.png`，合计约 123 KB。

做的思路还是"材质换配色"：

| 地形 | 冬季处理 |
|---|---|
| 平原 | 雪面 + 露出来的枯草茬（深色短笔触） |
| 林地 | 深绿圆冠 + 上半截压雪（不是"变白"，是"雪落在树上"） |
| 丘陵 | 雪面 + 裸露岩脊的短斜线 |
| 城市 | 白顶 + 细灰檐口 + 屋脊线（第一版画成黑底白盖，缩下去像条形码） |
| 道路 | 雪地 + 两道断续车辙 |
| 河流 | **结冰**：淡蓝冰面 + 裂纹，不是水 |
| 渡口 | 冰面上一条被踩出来的过河点 |
| 铁路 | 道砟露出来，枕木钢轨压出深槽 |

**没做的地形**（机场/浅海/深海/港口）在冬天**回落到普通贴图**——第 3 章是内陆，
用不到它们；真要用时补一张 `winter/xxx.png` 即可，代码不用改。

### 怎么触发

```
关卡数据：  season: 'winter'      ← 第 3 章实装时写上（引擎已支持，关卡还没填）
预览开关：  campaign.html?lv=C1&season=winter
            campaign.html?lv=C1&winter=1        ← 别名
```

优先级：**关卡声明 > URL 预览 > 默认秋季**。顶栏的季节胶囊跟着走（冬季/春秋/夏），
以前它是 HTML 里写死的"秋季"。

预览开关是刻意留的：第 3 章还没实装，美术需要一个"不改关卡数据也能看雪地"的口子。

### 断言

- selftest `[70]`：冬季映射覆盖 8 地形、路径规范且登记在 `ASSETS.ui`、
  没做的地形会回落、`seasonOf` 优先级、`tileFor` 在冬/秋各给对图；
- briefcheck `[33]`：带 `?season=winter` 打开，**每一格真的吃到雪地图**，顶栏显示"冬季"。
