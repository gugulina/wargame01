> v1（2026-10-29）· 状态：**设计，未实装**（本文不含代码改动）
> 目标：把"看不见就不能打"做成一个通用地基，一次解开第 2、3、7 章的共同前置。
> 依据：`game/campaign.html` v4.15 的实际规则（引用以函数名为准，行号会漂）。
> 姊妹篇：`docs/16-装甲特色机制-设计稿.md`。本稿沿用它的五条约束（动词化 / 不新造系统 / 必配刹车 / 可测可变异 / 同步清单），
> 并**修正了它对存档机制的一处假设**（见第七节）。

## 一、现状：引擎里没有任何"看见"的概念

| 系统 | 是否存在 | 实测依据 |
|---|---|---|
| 视野 / 战争迷雾 | **不存在** | 全文无 `vision` / `fog` 字段，`LEVEL` 元数据里没有相关键 |
| 隐蔽 / 伪装 | **不存在** | 兵牌没有承载它的字段 |
| 夜战 | **不存在** | 只有两个事件 id（`night_start` / `night_drop`）放 log 和 banner，纯文案 |
| 观测 / 校射 | **半存在** | `recBonus` 是"3 格内有 `rec` → 命中 +0.15"，**纯修正，不影响能不能打** |
| 指示目标才可打 | **存在一个特例** | `hqAirSpotOk`：空袭指挥部必须有地面指示者。全项目唯一一处 |

`hqAirSpotOk` 长这样（语义，非原码）：

```
本方存在一个非空中单位，满足 hexDist(u.pos, pos) <= (u.type === 'rec' ? 2 : 1)
```

它已经包含了观测层需要的全部要素：**距离衰减、兵种差异化、空中单位不能给自己指示目标**。
本稿的核心主张就一句话：**把这个 HQ 特例泛化成 `spotted()`，观测层就完成了 60%。**

### ⚠️ 附带发现：`recBonus` 在已实装十关里从未生效

盘底的时候顺手验了一条，值得单列，因为它直接影响本稿的编制结论：

| 事实 | 实测 |
|---|---|
| 全项目 `type:'rec'` 兵牌 | **2 个，且都在红方**（`青巡` @C2、`47侦` @C4） |
| 蓝方 `rec` 数量 | **0** |
| 蓝方"侦察营"的真实兵种 | `abbr:'204侦' / '装侦'` 那些写的是 **`type:'larm'`（轻坦）**，不是 `rec` |

`recBonus(u, defPos)` 的第一行是 `if (!isArty(u)) return 0`，之后要求
`alive(u.side)` 里存在 `r.type === 'rec'`。蓝方没有 `rec` ⇒ **蓝方炮兵的 +0.15 校射加成
在现有十关里恒为 0**；红方虽有 `rec`，但唯一那门 `art`（`青炮`）与它相距 5 格，也够不着半径 3。

也就是说：**`docs/04` 与图鉴里描述的"侦察连为炮兵校射"，目前是一条写在代码里、
但被编制数据抽空了的机制。** 它不是 bug——`recBonus` 的实现是对的，缺的是兵牌。
本稿把观测层建在这条链路上，所以必须连带把编制补上（见 3.2 与第八节），
否则"没有 rec 就没有远程火力"会变成"蓝方从此没有远程火力"。

### 更要紧的是：这个泛化只需要改一个函数

`canTarget(att, def)` 是全站唯一的可打性闸门，三类调用方全都过它：

| 调用方 | 用途 |
|---|---|
| `inRangeTargets` ← `targetsFor` | 玩家单位面板的目标列表 |
| `runAI` 的 `targetsFor` | 红方 AI 选目标 |
| `doAttack` 的第二道闸 | 实际结算前的复查 |

在它里面加一条可见性判定，**面板、AI、结算三处同时生效，不需要任何分发代码**。
这是本稿最值钱的一条结构发现——反过来说，如果把判定写进 `previewAttack` 或 `doAttack`，就会出现"面板列得出来、点下去打不了"的裂缝，项目历史上这类"显示改了数据没改"的坑已经踩过多次。

## 二、设计目标与约束

| 目标 | 具体要求 |
|---|---|
| **动词化** | 玩家的决策是"把侦察资产派去哪"，不是"给对方叠一个命中修正" |
| **不新造系统** | 复用 `hexDist`、`recBonus` 的半径口径、`canTarget` 闸门、`state.flags`、`updateControl` 的渲染钩子 |
| **必配刹车** | 开火即暴露、遮蔽地形给敌人隐蔽、AI 也受同一套规则约束（不能"我方受迷雾、AI 全知"） |
| **可测** | 每条都能写成 selftest 断言，且能反向变异（改回错写法必须红） |
| **不能毁掉现有十关** | 观测层默认**关闭**，关卡显式声明 `vision` 才启用。已经调过平衡的十关一行代码都不受影响 |

最后一条是本稿的安全带。**必须先钉死**：如果观测层是全游戏默认行为，第 1 章十关的平衡数据全部作废、要重跑一万局自战。
默认关闭 + 关卡 opt-in，则改动面收敛到"新关"。

## 三、机制清单

优先级：**P0 = 建议本稿第一批**（地基 + 能玩）· **P1 = 紧随**（让地基有意义）· **P2 = 暂不做**（见第十节）。

### 3.1 观测判定 `spotted()`（P0 · 地基）

> 唯一的一条硬机制：能不能打，先问能不能看见。

| 项 | 内容 |
|---|---|
| **数据结构** | `state.seen[side]` = `{ 'r,c': { turn, abbr, name, type, str, org } }`。key 用 `kk(r,c)`（`renderBoard` 里已经在用它做格子索引） |
| **语义** | 记录"我方对敌方格子的最新情报"，**不是**"实时可见"。可见 = 本回合刚更新过 |
| **刷新时机** | 与 `refreshFields()` / `updateControl()` 同一节拍：任何移动、开火、工事动作之后，以及回合边界 |
| **观测源** | 见 3.2 的 `OBS` 表；每个观测源把自己半径内的敌方格写入 `state.seen` |

**为什么存快照而不是只存"可见/不可见"两个布尔**：
玩家对看不见的部队仍然需要知道"它上次在这、还剩多少战力"，否则"夜袭"会变成"瞎猜"，
而瞎猜不是玩法。**过期情报本身是一种资源**——这是整个观测层好不好玩的分水岭。

**代价与体积**：`state.seen` 是 state 级字段，`saveSnapshot` 里那些 `{...state.xxx}` 浅拷贝装不下嵌套，
得按 `mods` 的写法用 `JSON.parse(JSON.stringify(...))`。粗估一张 30×21 的图，
敌方在视野内的格子量级 100–200 个，每条约 60 字节 ⇒ 档案增量约 10 KB。
项目对档案体积有先例约束（战报只留最近 80 条、`amb` 必须跳过预载），这条要一起守。

### 3.2 观测源与半径 `OBS`（P0）

> 谁能看见多远。全部对齐现有口径，不发明新数字。

| 观测源 | 半径 | 依据 |
|---|---|---|
| `rec` 侦察连 | **3** | 与 `recBonus` 的 3 格校射半径同一个数 |
| `larm` 轻坦 | **3** | 见下方"编制现实"——蓝方的侦察兵种实际是它 |
| 一般地面部队 | **1** | 即"肉眼"。与 `hqAirSpotOk` 的非 `rec` 分支同一个数 |
| 空中单位 `fgt/atk/bmb/trp` | **3** | 现有规则已经禁止飞机给自己指示目标，作为**观测平台**才是它的新用途 |
| 指挥部 `hq*` | 2 | 比肉眼略远，符合"有观察所" |
| 舰艇 `ca/dd/bb` 等 | 4 | 桅杆高；且蓝方两艘巡洋舰的 `abbr` 已经自称"巡"（巡逻/巡航），半径 4 让舰载侦察有落点 |
| 工事 / 雷区 / 要点 | **永久可见** | 静态目标，不给它做迷雾只会添乱 |

### 编制现实：`larm` 必须进观测源，否则蓝方没有远程火力

蓝方 `type:'rec'` 数量为 **0**（第一节），其编制里的侦察单位全是**装甲侦察营（轻坦）**——
`204侦`、`装侦` 这些 `abbr` 的 `type` 是 `larm`。如果观测源只认 `rec`，
观测层一开，蓝方 `art`/`hr` 的间瞄就**永久打不了**，试点关会直接崩。

所以 3.2 把 `larm` 与 `rec` 并列成半径 3。这也符合史实与现有分工：
`rec` 是徒步侦察连（`str:2 mov:10`），`larm` 是装甲侦察（`str:10 mov:12`）——
**同一件事，两种载体**。而且轻坦在装甲稿 3.7 里已经拿到"收割残局"的定位，
再给它一个"眼睛"，三型坦克"轻坦是刀"的说法反而更立得住。

**关键设计：观测层第一次让侦察类单位不可替代。**
现在 `rec` 的全部价值是炮兵的 +0.15 命中（而蓝方根本拿不到，见第一节），
观测层上线后，**没有侦察就没有远程火力**（见 3.3）。
配套动作：第 2 章起蓝方编制要真的排进 `rec` 连（第八节同步清单），
把这条已经写空了的链路补实。

### 3.3 直射 / 间瞄分治（P0 · 决定手感的一条）

> 坦克和火炮对"看不见"的反应必须不一样，否则二战味全无。

现有分类可直接复用：`ARTY_TYPES = ['art','hr','sha','spa']`、`ARTY_DIRECT = ['sha','spa']`。

| 火力类型 | 成员 | 不可见时 | 理由 |
|---|---|---|---|
| **直射** | 其余全部（含 `sha`/`spa` 直瞄炮） | **不能打**，目标不进 `targetsFor` 列表 | 看见才能瞄。这是最干净的规则 |
| **间瞄** | `art` / `hr`（非直射的两型炮） | **不能打新位置**，但**可以打 3 回合内的过期情报格**，命中按 stale 程度惩罚 | 火炮按坐标表射击，不需要亲眼看见；但拿三分钟前的坐标蒙一个地方，本来就该打折 |

**间瞄的过期惩罚曲线**（写成常量表，别硬编码在函数里）：

```
OBSTALE = { fresh: 0, aged: -0.10, stale: -0.25, dead: 不可打 }
对应回合差 0 / 1–2 / 3 / ≥4
```

这条把 `recBonus` **从修正升级成资格**——`docs/04` 与图鉴里"侦察连给炮兵校射"那句话，
到这里才第一次成为规则而不是数字。

**刹车**：间瞄仍然允许打过路目标，所以侦察不是唯一解；重炮 `hr` 的 3 格近界（`minRange`）
原样生效，贴着它反而打不着。**夜战关里"火炮不能校射"的实现方式就是把间瞄的 `aged` 窗口压成 0**，
不需要新开关。

### 3.4 开火即暴露 `u.revealed`（P0 · 刹车，且是共享地基）

> 打了第一炮，位置就报出去了。

| 项 | 内容 |
|---|---|
| **触发** | `noteAct(u,'fire')` 已经在记账，跟着它写 `u.revealed = state.turn` |
| **效果** | 该单位进入敌方 `state.seen`，本回合内**无视遮蔽地形与夜战惩罚** |
| **清除** | 回合边界。落点就在那行 `state.units.forEach(u => { u.moved = false; u.fired = false; })`——**同一个 forEach 里加一个字段，不新增遍历** |
| **为什么必要** | 观测层如果没有它，最优解会退化成"躲在树林里永远不出手"，地图变成比谁更怂。有了它，开火这个动作自带风险，**"打不打"就变成决策** |

**与装甲稿 3.5 的合并建议（重要）**：
`docs/16` 的 3.5 反装甲暴露是 `u.exposed` 布尔，开火置真、下回合清空。
这和 3.4 是**同一件事的两种写法**。建议合并成单一字段 `u.revealed`（本回合），同时服务：

1. 观测层（暴露位置）
2. 装甲稿 3.5（暴露后 +15%/+30% 防御加成归零）
3. 未来的反炮兵（敌方炮兵还击的索引依据）

一处字段变更换三个机制，省一轮 `SAVE_VER`，也省一次"两个系统对同一个状态判断不一致"的事故。

### 3.5 遮蔽地形与环境（P1）

> 让树林和城镇不只是防御修正，而是"藏得住"。

| 项 | 内容 |
|---|---|
| **遮蔽地形** | `林地 / 城镇 / 复杂`（取 `t.cls`，`previewAttack` 里已经在按 `dt.cls` 分档）：敌方观测源半径 **−1**，且**夜战时不可见** |
| **夜战** | 关卡声明 `vision: { spot: 2 }`，把所有观测半径压到 ≤2，间瞄 `aged` 窗口归零 |
| **季节** | `mods` 的 `filter` 已支持按 `side / corps / type` 匹配，冬季给侦察类观测源半径 −1 是**纯数据**（见下） |

**季节是零代码这件事要说清楚**：`modMatch` 只按 `side` 和 `filter.corps/type` 判定；
`checkEvents` 里每条事件 `state.eventsDone[ev.id]` 后不再触发。
所以第 3 章"入冬/开春"**用两个 `when.kind:'turn'` 的一次性事件接力**即可，引擎一行不改。
（半径 −1 需要 `spotted` 读一次 `modAtk` 风格的聚合，这是本稿唯一要新写的小函数：`obsPenalty(u)`。）

**这一条的真实收益**：地形贴图本来是纯表现（而且 `ASSETS.ui` 那 12 槽引擎根本不读），
有了遮蔽之后，**地形第一次有战术语义，不依赖任何美术交付**。

### 3.6 AI 的对称性与难度档（P1）

> 不能"我方受迷雾、AI 全知"。这是公平问题，也是 `docs/09` 风险清单那条债的解。

AI 走的是同一个 `targetsFor → canTarget`，所以**它自动受观测层约束，不需要写任何 AI 代码**。
要处理的只有一个方向：AI 不能因为看不见就变蠢到原地不动。

| 设计 | 内容 |
|---|---|
| **红方观测源** | 与蓝方同一张 `OBS` 表。红方已有 `rec` 2 个、也有 `larm` 装甲侦察，**观测能力比蓝方现况更强**——这不是问题而是关卡作者的工具：`aiSpotBonus` 负值即可让低难度档的红方"看不远" |
| **`aiSpotBonus`** | 一张 `AI_PROFILE` 表加一项：简单 −1 / 普通 0 / 困难 +1 |
| **决策噪声** | `AI_PROFILE` 再加一项抖动概率，简单档让 AI 有小概率走次优格 |

注意方向：现状是红方有侦察、蓝方没有（第一节），所以**照搬对称规则会让试点关一边倒**。
两种处置选一：① 第 2 章起给蓝方排进 `rec` 连（推荐，顺带补实那条空链路）；
② 试点关单独给红方 `aiSpotBonus: -1`。①是正解，②只适合用来先跑通机制。

**这一条是难度档的最便宜落地路径。** 现状是 `runAI` 的权重全是字面量、`LEVEL` 里没有任何 `ai*` 键、
也没有噪声项——本稿不是绕开这个缺口，是**顺手把它补在观测层的延长线上**：
`AI_PROFILE` 表本来就为了 `aiSpotBonus` 而必须新建，难度档只是同一张表多几列。

## 四、边界情况

| 情况 | 处理 | 为什么 |
|---|---|---|
| 一格两层（地表 + 空中） | **分层各自判定**：打空中目标查空中层可见，打地表查地表层 | `layerOf` 已经分 `air/surface`；混用会导致"打飞机的视线被脚下步兵决定" |
| 敌军移动进入我方视野又立刻离开 | 只在**观测刷新那一刻**在半径内才算看见，不做"路过留下痕迹" | 否则等于给了免费侦察走廊 |
| 敌军从视野外增援入场（`LEVEL.waves` / `spawn`） | **入场即可见**（增援有 banner 和 `FX.sfx('alarm')`，玩家已经知道了） | 隐藏增援位置会让预警变成假警报 |
| 雷区、工事、要点 | 永久可见，不参与 `state.seen` | 静态目标做迷雾是纯烦人 |
| 撤离区 `esczone` | 区域本身永久可见，`inEscapeZone` 不改 | `renderBoard` 的注释写着"玩家必须先看见它，否则往东突围就是一句空话"——这条承诺要保留 |
| 被歼灭的单位 | 立即从其最后已知格清出 `state.seen` | 否则界面挂着一个不存在的敌军，且 `unitDead` 事件的 `everSeen` 判定会被干扰 |
| 存档读入 | `state.seen` 全部重新校验（见第七节） | — |
| 观测层关闭的关卡（现有十关） | `spotted()` 短路返回 true | **保证零回归** |

## 五、实现要点

**落点，按依赖顺序：**

1. **`OBS` 表**（新常量）：兵种 → 基础半径。放在 `SLOT` / `TYPE` 附近，方便 `levelcheck` 核对。
2. **`LEVEL.vision`**（新可选键）：`{ spot: n, obsMod: n }`。**必须同步 `tools/export-levels.js`**，
   否则 `data/levels.js` 快照里没有它，菜单页与引擎会出现"这一关有没有迷雾"两种认知——
   这正是 `export-levels --check` 存在的意义。
3. **`spotted(side, pos, layer)`**：查 `state.seen[side]` 是否在 `OBSTALE` 的新鲜窗口内。纯读，无副作用。
4. **`refreshSeen()`**：遍历观测源 → 半径内格写入。挂在 `refreshFields()` 旁边调用，
   **不要自己找时机**——`refreshFields` 已经在正确的节拍上了。
5. **`canTarget(att, def)` 加一条**（唯一的行为变更点）：
   ```
   若 LEVEL 启用观测层 && 目标不是静态目标：
     直射 → 要求 spotted(att.side, def.pos, layerOf(def))
     间瞄 → 允许 spotted 的 aged/stale 档，交 3.3 的惩罚
   ```
   放在 `isAir(def) && !canHitAir(att)` 那条**之后**、`attackClasses` 白名单**之前**。
6. **`previewAttack` 读 `staleOf()` 施加命中惩罚** ——
   **不要只把惩罚加在 `doAttack`**，否则面板预判比值和实际结算不一致，这是最容易被玩家发现的双标。
7. **`obsPenalty(u)`**：`spotted` 的半径先减掉它（遮蔽地形 / 夜战 / 季节聚合）。
   全项目唯一新增的小函数，写法参照 `modAtk` 的 reduce 形式。
8. **`renderBoard`**：格子 class 拼接处（`cls += ' esczone'` 那一段）加 `fog`；
   不可见但已知敌军所在格画"情报标记"（画最后已知的 `abbr`，配 `t-intel` 灰显样式）；
   与当前真实位置不符时，tooltip 写"上次目击：第 N 回合 · 战力 X"。
   **样式改动优先落在 `campaign.css`**（v4.9 起样式已经整块搬出引擎）。

**禁止事项（踩过的坑）：**

- ❌ 不要复用 `state.everSeen` 这个名字。它现在的语义是"**曾进入战场的兵牌**"，
  服务 `unitDead` 触发器（`w.ids.every(id => state.everSeen[id] && !units.some(...))`），
  和视野毫无关系。名字撞车会让后来人把两套语义接错。
- ❌ 不要把可见性写成单位字段挂在 `u` 上。可见性是 **(观测方, 格子)** 的关系，不是单位的属性；
  挂在单位上就没法表达"过期情报"和"一格两层"。
- ❌ 不要在 `doAttack` 里做主判定。`canTarget` 是三道闸的公共上游，绕开它就会面板/结算分裂。

## 七、⚠️ 对存档机制的一处修正（同时影响装甲稿）

`docs/16` 第 3.1 / 3.5 节都写着"新字段必须进存档白名单（`validateSave`）"。
实测 `saveSnapshot` 对部队用的是：

```
units: JSON.parse(JSON.stringify(state.units))
```

**这不是白名单，是整份深拷贝。** 后果是：

> 任何新增的 `u.xxx` 字段都会**自动落盘、自动读回**，而 `validateSave` 只逐条校验
> `id / side / type / name / abbr / corps / str / org / pos` 九个字段——
> 也就是说，**新字段会在没有任何校验的情况下从存档直接回流进游戏逻辑。**

这不是理论问题：`u.revealed` 如果从存档读进一个 `-9999` 或字符串，`spotted()` 的回合比较会静默失效；
`docs/16` 的 `u.chargeDir`（0–5）若被塞进 `17`，扇区判定会指向不存在的方向。

**两稿共同的处置建议：**

1. `validateSave` 新增一段"可选数值字段"通用校验：对声明过的字段做类型 + 区间检查，越界**归零而不是报错**
   （玩家存档坏了不该让他进不了关，这与现有"战报先限量再验内容"的思路一致）。
2. `saveSnapshot` 里 state 级嵌套字段（`seen`）必须显式深拷贝，参照 `mods` 那一行。
3. 动 `units` 的字段语义时同步 `SAVE_VER`；只加可选字段可以不动版本号（旧档读回时字段为 undefined，走默认分支）。

第 3 点需要明确一句：**本项目现有先例**是 `packed` 字段用 `u.packed === undefined ? false : !!u.packed` 兜底，
即"新增可选字段不升版本号"是既有做法。本稿遵循它。

## 九、平衡影响与复测要求

### 会往哪边动

- **⚠️ 试点关最大的单一风险不是"打不着"，是"蓝方炮兵饿死"**。蓝方 `rec` 为 0，观测源半径 3 现在只有 `larm` 一家；
  而 `art` / `hr` 的机动都很低、必须跟着侦察走。如果试点关的蓝方编制里没有半径 3 的观测源、或者轻坦被派去别的方向，
  蓝方远程火力会**整关归零**——达成率不是下降，是断崖。**开试点关之前先确认这一关场上有一个半径 3 的观测源，
  并且它到炮兵阵地的距离在两三格以内。** 这是第六节 #12 那条断言存在的全部理由。
- **启用观测层的关，蓝方达成率大概率下降**：守要点要派人看路，`rec` 变成编制刚需而它战力很低。
- **红方装甲/空中受益**：红方编制里侦察与空中单位存在，`aiSpotBonus=0` 下双方对称，但关卡设计偏防守时防守方天然更适应迷雾。
- **间瞄惩罚的强度直接决定重炮 `hr`（5 战力、机动低）的可用性**，这是最容易调过头的一项。

### 复测协议（按项目既有纪律）

```bash
node tools/autoplay-campaign.js game/campaign.html 100 --level=<新关> --seed=1234
```

1. **一次只上机制的一半**：先"3.1–3.4 地基 + 开火暴露"，AI 对称（3.6）单独一批。
2. 先两遍同种子确认骰子可复现，再动数值。
3. 30–40 局起步，改动复核 100 局；单轮 100 局之间也会差 5 个点。
4. **现有十关必须回归**：它们不启用观测层，达成率应与 v4.15 记录的数字逐关一致（`docs/09` 平衡表）。
   这条是本稿的安全带验证，**不能跳过**。
5. 先看输在哪，别急着改数值——屡次踩过的坑是我方主力被自己的新规则废掉。

## 十、不做 / 缓做清单

| 候选 | 判断 | 理由 |
|---|---|---|
| **连续视野网格 / 视线遮挡（LOS）** | 不做 | 要算六角格射线投射，与"复用已有系统"冲突；而且玩家对"山后面有没有人"的兴趣远低于对"能不能打"的兴趣 |
| **单位个体伪装值** | 不做 | 与 3.5 的地形遮蔽重复，两个维度叠乘会不可控 |
| **迷雾下 AI 全知** | 不做 | 公平性问题，且玩家一眼就能看出来（AI 精准打击了不该知道的位置） |
| **友军误伤 / 情报错误值** | 不做 | 挫败感高于趣味；兵棋受众要的是"信息不完整"，不是"信息是假的" |
| **动态侦察点 / 侦察技能** | 缓做 | 会引入行动额度之外的第二套资源，先让 `rec` 的被动半径跑出数据 |
| **把观测层默认打开到全部关卡** | 不做 | 见第二节：会让十关平衡作废、要重跑上万局 |
| **夜战作为全局开关而非关卡声明** | 不做 | 夜战必须能和中转场共存（C9B 是"断电之夜"，有入夜/天亮两段），`vision` 得是回合内可变的 |

## 十一、落地顺序建议

与装甲三片**错开**——两稿都动结算，同期上就分不清哪条把达成率抬上去了。

| 版本切片 | 内容 | 理由 |
|---|---|---|
| **v4.19** | 3.1 `spotted` + 3.2 `OBS` + 3.3 分治 + 3.4 开火暴露（观测层默认关）**+ 试点关的蓝方观测源编制** | 地基一次做完，默认关闭保证零回归。但编制必须同片落地：只写引擎不改兵牌，试点关会跑出一个"蓝方炮兵全程哑火"的数字，然后被误读成机制太强。这一片的试点关**先按 §3.6 的 ② 给红方 `aiSpotBonus: -1` 兜住不对称**，等第 2 章的 `rec` 排进编制再取消 |
