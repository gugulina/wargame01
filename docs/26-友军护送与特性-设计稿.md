## 一、友军（绿方）

### 1.1 为什么改口径：不进 `state.allies`

v4.21 预留的接口写的是"友军兵牌放进 `state.allies`，结构与 units 相同"。
真做的时候发现这是错的，原因只有一条：

> **`unitsAt` / `layerUnitsAt` / `stackFull` / ZOC / 补给场 / 工事 / 雷区 / 渲染，
> 全都只读 `state.units`。** 另开一张表，等于把这七八处各写一份"也看看 allies"，
> 漏一处就是"屏幕上没有这支车队，但它堵着路"这种查一天的错误。

所以绿方单位**就放在 `state.units` 里，`side:'green'`**。`alive('green')` 直接能用，
占格、堆叠、被攻击、吃地形防御，全都是现成的。`ai.js` 的 `alliedUnits()` 保留，
改成"从 `state.units` 里筛绿方"——接口名不变，点数口径不变。

### 1.2 敌我判定表

三阵营之后，`other(side)` 这个"非蓝即红"的老函数不够用了。新增两个判据，
**所有需要分敌我的地方都必须走它们**：

```js
friendlySides('red')   = ['red']
friendlySides('blue')  = ['blue', 'green']     // 友军：协同、堆叠、互相掩护
friendlySides('green') = ['blue', 'green']
foesOf('red')   = blue + green
foesOf('blue')  = red
foesOf('green') = red
```

| 位置 | 旧口径 | 新口径 | 不改会怎样 |
|---|---|---|---|
| `inRangeTargets` | `alive(other(u.side))` | `foesOf(u.side)` | 红方永远看不见车队，整关没有敌人来 |
| `helpers`（防御协同） | 同阵营 | `friendlySides` | 我军贴着车队也帮不上它 |
| `inEnemyZOC` | `u.side !== side` | 绿方**不产生** ZOC | 难民堵住补给线、堵住我军机动 |
| `supplyOf` | 按 `state.fields[side]` | 绿方恒「充足」 | 车队一出生就"断绝"，每回合掉 10 组织度 |
| `updateControl` | `if blue … else red` | 显式 blue / red，绿方不计 | 车队路过要点 = 被判定成敌军占领 |
| `canCapture` | 兵种白名单 | 绿方兵种不在白名单 | 难民占点（不该发生） |

### 1.3 绿方能做什么、不能做什么

- **不能**被玩家选中、不能移动、不能开火、不能占点、不建工事、不吃战术卡。
  点它 = 检视（和点敌军同一套面板，只是标签是绿色的「友军」）。
- **能**占格、被攻击、被歼灭、在被攻击时还手（`canCounter` 照常）。
  护送队有枪，难民没有——差别写在兵种表的 `rg` 上，不另开开关。
- **不进入 AI 的行动序列**：它由 `escortTick()` 按关卡路径推着走，不由任何一方指挥。

## 二、护送关（`win.kind:'escort'`）

### 2.1 关卡数据

```js
win: { kind: 'escort', need: 3 },        // 至少 3 支绿方单位走到终点
escort: {
  step: 2,                               // 每回合沿路径前进几格
  path: [[r,c], …],                      // 由东向西的公路，含终点
  exit: { zone: { r0, r1, c0, c1 } },    // 走进这个矩形 = 撤出（复用 reach 的写法）
  total: 4                               // 绿方难民总有几支（超额线 = 全部走到）
}
```

`path` 是**一条**路径，所有绿方单位共用；每支单位自己记 `escortIdx`（走到第几个点）。
为什么不让每支写一条：车队本来就是"跟着前车走"，一条路径 + 错开的起点就够了，
而且堵路、超车、被截断这些情况用"路径索引"判起来只有一处。

### 2.2 每回合怎么走

在 `settlePhase()` 里、红方打完**之后**推进（玩家下一回合看到的已经是新车位）：

1. 从 `escortIdx+1` 起，最多前进 `step` 个路径点；
2. 目标格地表已满（`stackFull`，2 支）就**停下等**——不绕路、不换道。
   这一条是整关的战术核心：敌人只要有一支兵站在公路上，车队就停在那儿；
3. 走完落点若在 `exit` 内：移除、`escortDone++`、播报；
4. 一支都没走成时写一条战报（"车队被堵在 X"），否则玩家只看到"这回合什么都没发生"。

### 2.3 胜负

| 时机 | 判定 |
|---|---|
| 任一时刻 | 我方全灭 → 判负（沿用旧规） |
| 任一时刻 | 绿方全灭 **且** 已撤出 < `need` → 判负（不用等到回合末） |
| 回合耗尽 | 已撤出 ≥ `need` → 达成；= `total` → 超额 |
| 中途 | 达成线到了**不结算**——和撤离关同一条口径：还能多送一支是一支 |
| 收尾（v5.2） | **全部车队走出去**才弹一段对话，并记下"最后一个回合"：再打满一个回合才结算。达成线不弹——那时还有人在路上 |

`judgeFinal` 与 `perfectHint` 必须同源（菜单页显示的超额条件要从同一处算），
这一条在 `docs/04` 十三节已经为 `reach` 付过学费。

### 2.4 AI 要会追车队

红方的推进轴历来是"要点"，因为 `aiGoalFor` 只认要点——**护送关没有要点可抢**，
不改就是全場站着不动。加一条：`LEVEL.escort` 存在时，红方目标 = 车队最前那支
（`escortIdx` 最大的一支）所在格。

三条约束，都是踩过的：

1. **只在这一关开**。C2 那次"离开要点轴去追人"把达成率从 45% 打到 0%，
   原因是追击让人离开了封锁线；护送关的封锁线就是车队本身，方向正好相反。
2. **目标取最前那支，不取最近那支**。取最近 = 全体围住尾巴，车队前半段照走不误。
3. **`scoreTarget` 给绿方一个固定加权**（+1.2），否则红方走到跟前会优先打旁边的
   蓝方掩护部队——"路过的车队不关我事"，看起来像 AI 不会打仗。

### 2.5 我方的活：在外围挡住

不新增"护卫"规则。玩家要做的事用现有规则就能表达：

- 站在车队与敌人之间（吃地形防御、吃堆叠协同）；
- 反坦克连 / 火箭炮摆在敌人必经之路；
- 敌人绕后时，用机动部队去截。

**不要**给蓝方加"贴着车队就减伤"的光环——那是把玩家的判断换成一个站位公式。

## 三、单位特性（buff 词汇表）

### 3.1 纪律（先看这条）

`TRAITS` 的每一个字段，**必须在引擎里有一个读取点**，否则就是数据里多一个没人读的
字段。这条不靠自觉：`selftest` 会扫引擎源码，确认每个字段都出现在
`traitSum(u,'x')` 或 `TRAITS[k].x` 的读取里；新加字段忘了接钩子会直接红。

第二条：一条特性要么在**面板**上看得见（数值/名字），要么在**战报**里看得见。
"战力 +5%"这种既不上面板也不进战报的软加成，一律不收。

### 3.2 已实装（6 个字段）

| 字段 | 作用 | 读取点 | 玩家在哪看见 |
|---|---|---|---|
| `def` | 阵地防御 +N | `terrainDefFor` | 单位面板「防御修正」 |
| `orgTick` | 每回合自恢复组织度（补给断绝无效） | `settlePhase` | 组织度条每回合自己涨 |
| `noBreak` | 永不进入崩溃态 | `isBroken` | 兵牌不会出现崩溃红边 |
| `atk` | 攻击修正 +N | `previewAttack` | 攻击预判的比值 |
| `ammo` | 弹药上限 +N | `makeUnit` | 面板「弹药 x / y」 |
| `zocFree` | 无视敌方控制区 | `moveCost` | 可达范围多出一圈 |

### 3.3 现有单位

| 特性 | 谁有 | 数值 | 一句话 |
|---|---|---|---|
| `steadfast` 死战不退 | 目前无（留给后续死守型单位） | def .15 / orgTick 8 / noBreak | 建制永不崩溃，阵地 +15%，每回合自恢复 8 |
| `cadet` 学员主官 | 军校生旅（C6–C10） | orgTick 6 | 每回合自恢复 6 点组织度 |
| `guard` 卫戍精锐 | 首都卫戍第 1 旅（C7–C10） | atk .10 / def .10 / orgTick 4 | 操典与装备都是全军最好的，缺点是没打过仗 |

**为什么卫戍旅是精锐**：原来 C7 的设定是"平时守仓库和电台，没挨过炮"，
把它写成了预备役。首都卫戍的定位应当是**阅兵与要地警卫**——装备最好、操典最严、
兵员从各师挑，但**没有实战经验**。所以给的是"素质高、恢复快"，不是"打得狠"：
`atk +10%` 是装备与训练，`def +10%` 是工事操典，`orgTick 4` 是纪律。
它仍然打不过老兵——同一关里的第 102 师残部才是打过硬仗的。

### 3.4 预留（只在文档里，不进代码）

下面五条是**候选**，不是字段。写在这里是因为下一个特殊单位出现时，
先要判断"它需要的是不是已经有的东西"：

| 候选 | 效果 | 落点 | 为什么现在不做 |
|---|---|---|---|
| `resist` | 受到伤害 ×0.8（重甲/掩体单位） | `doAttack` 损失结算 | 减伤不改变任何一次判定的可见结果，玩家只会觉得"这关敌人变硬了"；要做必须先有伤害数字飘字 |
| `repair` | 每回合恢复战力 +N（维修/医疗） | `settlePhase` | 与"补员"规则冲突：补员现在是事件效果，做成常驻会让久守关卡全部变简单 |
| `aura` | 半径 N 内友军 +X | 新增 `traitAura` | 现在 HQ 光环是写死的（`hqBonus`），做成通用光环要动组织度恢复链；等真有"补给连/医疗队"再说 |
| `firstStrike` | 被装甲攻击时先手结算 | `canCounter` | 反坦克连的"设伏"已经是这个效果的专用版（`atAmbush`）；通用化等于给它开后门 |
| `evade` | 撤离时不受 ZOC 影响 | `computeReach` | 只在突围/护送关有意义，先把护送关做出来看玩家怎么打 |

一句话总结：**能用一个已有字段表达的，绝不新开字段**。

## 四、火箭炮（`mlrs`）

### 4.1 数值

| 项 | 值 | 与同类比 |
|---|---|---|
| 射程 | 3–6 格（4.5–9 km） | 旅野炮 2–5、师重炮 3–9 |
| 近界 | 3 格 | 和师重炮一样：贴到 4.5 km 内打不着 |
| 弹药 | 3 | 一次齐射打空三分之一，全场最贵的一档 |
| 机动 | 5（牵引） | 比野炮还慢，展开/收炮各占一回合 |
| 战力 | 5 | 皮薄，被反炮兵盯上就没了 |

### 4.2 面覆盖

普通炮兵的面覆盖只覆盖**目标格**（v4.18 的"炮兵覆盖整格"）。
火箭炮多一条：

> 目标格吃全额损失，**相邻六格各吃一半**；每一格内部仍按现有 `splashSplit`
> 按战力比例分摊（最大余数法）。

为什么是半额而不是"每格全额"：一次齐射的炸药量是固定的，覆盖面越大、单位面积越薄。
全额会让火箭炮变成"七格同时挨一炮"，任何防线都撑不住两轮。

为什么值得单独做一个兵种：它把"扎堆"这件事的代价变了。以前堆叠是纯赚
（同格协同 +50%），火箭炮上来之后，堆在两格里的人会一起挨打——这是对
"堆着守更硬"（`docs/04`）的一次反向修正，也是玩家要学的新东西。

### 4.3 与 T7 炮火准备的关系

`docs/23` 的 T7「炮火准备」需要"同一目标连续两回合"。火箭炮只有 3 发，
天然不适合连着打同一格——它适合**开场砸一次**。所以 T7 留给师重炮，
火箭炮的角色是"一次把某一段防线打薄"，两者不抢活。

### 5.2 断言要打在真数据路径上

按 `MEMORY.md` 的纪律，每条断言先问"传错对象会不会静默通过"：

- **友军**：把红方放在车队旁边，断言 `targetsFor` 里有它（不是拿蓝方断言——
  蓝方本来就在列表里，删掉 `foesOf` 照样绿）。
- **堵路**：把一支无关单位放到车队下一格，断言这一回合 `escortDone` 不变、
  且战报里有一条"被堵"（只断言"没动"会被"路径算错"也满足）。
- **胜负**：`escortDone = need` 时 `checkEnd` 不结算；`judgeFinal` 才给 win。
- **火箭炮**：目标格 + 相邻格各放一支，断言两支都掉血、且**相邻那支掉得少**；
  对照实验：普通炮兵打同样的摆位，相邻那支不掉血。
- **特性**：`atk` 必须让同一支部队的 `previewAttack` 比值变大；
  `ammo` 让 `maxAmmo` 变大；`zocFree` 让可达格多出至少一格。

### 5.3 变异锚点

每条断言配一条变异（删掉实现看它红不红）。特别注意两类容易假绿的：

1. **多分支互顶**：`foesOf` 与 `scoreTarget` 的绿方加权都能让"AI 会打车队"成立，
   测一个必须把另一个中和；
2. **残留状态**：`state.escortDone` 是模块级还是 `state` 里的，决定换关后会不会带过去——
   一律放 `state`，并在 `newGame` 里归零。
