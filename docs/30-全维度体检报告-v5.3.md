## 三、规则与判定可达性（本轮新增的体检项）

"达成率低"和"这条线根本走不到"是两件事。这一节用**枚举推演**把后者找出来。

### 3.1 🔴 C3 的"达成"档数学上不可达

C3 是计分关，五个要点分值 **15 / 15 / 10 / 5 / 5**，达成线 `winScore = 26`，超额线 `perfectScore = 30`。

所有可达分数 = 这些分值的子集和，**全部是 5 的倍数**：

```
0 5 10 15 20 25 30 35 40 45 50
```

`winScore = 26` 意味着"≥26 且 <30"，而这个区间里**没有任何可达值**：

- 拿 25 分 → 25 < 26，判**失败**
- 拿 30 分 → 30 ≥ 30，判**超额**

所以 C3 的判定只有两种结果：失败，或者超额。**"达成"这个档位在这一关从来不会出现。**

**实测印证**：40 局自战里 达成 **0 次**、超额 26 次、失败 14 次（`_bal-C3.txt`）。

**文档三处口径还互相打架**：

| 来源 | 超额线 |
|---|---|
| `game/campaign.html`（`perfectScore`） | **30** |
| `docs/04-战役级规则.md:483` | **35** |
| `docs/24-游戏文案总表.md:204` | 30 分以上 |

有意思的是：**按 docs/04 的 35 反而能修好**——那样 30 分（两座核心）就是"达成"，35 分（两核心 + 一个渡口）才是"超额"，中间态回来了。反过来说，代码里的 30 很可能是后来"顺手降难度"时改的，没意识到把达成档挤没了。

**建议**（二选一，都是一行改动）：
- 把 `perfectScore` 改回 **35**（与 docs/04 一致，恢复中间态）；或
- 把 `winScore` 改成 **25**（达成 = 15+10 或 15+5+5，超额 = 两个核心 30）。

> 这条以前没人报过：`docs/27` 只发现了 C9 的档位问题（P2-1），没做子集和推演，所以漏了 C3。
>
> ✅ **2026-11-11 已修**：`perfectScore` 改回 **35**（与 docs/04 一致），简报与数字条同步。40 局复测：失败 35% / **达成 65%** / 超额 0%——中间档回来了。超额 0% 是因为自战脚本拿下两座核心就收手、不再去抢渡口；35 分在规则上可达（15+15+5）。

### 3.2 🟡 C9 的档位分布畸形（docs/27 P2-1 的复核）

C9 要点 **12 / 10 / 10 / 8**，达成 21、超额 30。子集和：

```
0 8 10 12 18 20 22 28 30 32 40
```

`[21,30)` 里其实**有** 22 和 28 两个可达值，所以 docs/27 说的"没有中间态"**不准确**——中间态存在，只是自战几乎不落在那里：40 局里达成 2 次（5%）、超额 29 次（72.5%）。

**结论**：C9 不是"档位不可达"，是"分值组合让超额太容易"（拿两个 10 分点 + 8 分点 = 28 就到了超额线附近；拿 12+10 = 22 只算达成，而 12 分那个点通常是主攻方向）。建议把 perfectScore 抬到 32 或 34，让"三个要点全控"才是超额。

### 3.3 🟡 `minAlive` 的分母把"白给增援"算进去了（`campaign.html:11149`）

```js
const base = (LEVEL.units || []).filter(u => u.side === 'blue' && (u.wave || 1) !== 0).length;
```

注释写的是"不含 wave:0 的增援（增援是白给的人，算进分母等于'越增援越难达成'）"，但 `(u.wave || 1)` 对 `wave === 0` 求值是 `1`，`1 !== 0` 恒真——**这个条件永远拦不住任何单位**。

实测存在 wave:0 的关：**C5（1 支）、C12（2 支）**。影响：

| 关 | 蓝方总数 | wave:1 | wave:0 | 当前 floor | 按注释应为 |
|---|---|---|---|---|---|
| C12 | 16 | 14 | 2 | `ceil(16×0.5)` = **8** | `ceil(14×0.5)` = **7** |
| C5 | 10 | 9 | 1 | 1（minAlive 未设） | 同 |

即 C12 的达成线比设计意图**多要一支存活**。同时超额线用的是 `wave === 1`（`11156`），两条线的分母不一致。

> `docs/27` 的 P3-2 提过这个"口径不同"，但判断是"当前所有关都是 wave 1，无影响"——**这个判断不成立**，C5/C12 有 wave:0。属旧账未收口。

### 3.4 🟡 C7B 的超额判据对增援不健壮（docs/28 §4.3 的旧账仍在）

`judgeFinal` 的破袭分支（`11176-11180`）：`startN` 只数 `wave === 1`，而 `alive('blue')` 包含后来进场的增援。C7B 蓝方目前没有增援，所以没事；**一旦给破袭关加增援，这条会变成"永远满足"**。属 P3 潜伏缺陷。

### 3.5 ✅ 其余判定口径核对无误

- `survive`：`keep` 要点保持 + 存活数 ≥ `ceil(base × minAlive)`；C7 / C8 / C11 / C12 的 0.4–0.5 生效正常。
- `reach`：撤出支数达标即结算，超额看撤出支数（v4.25 口径）。
- `escort`：`need` 支到位，超额看全员（C11B 实测 7.5% 超额，说明够得着）。
- `demolish`：C7B `need 3` / 4 座桥、10 份装药，`need < 总数` 保留取舍空间。
- 教学关 T1 无超额档（`isTutorial` 分流正确，两处同源）。

## 四、代码质量与安全（审计 A + 我的复现）

### 4.1 🔴 P0 · 导入存档可执行任意脚本（`turn` 未校验，且直接进 innerHTML）

`validateSave`（`campaign.html:8831-8947`）逐个校验了 `v / lv / map / units / log / forts / mods / mines / depots / deck / works`，**唯独没校验 `turn`**（也没有校验 `charges / mov / rng / ammo / maxAmmo / fort.hp`）。而 `turn` 有两个渲染口是裸拼 `innerHTML` 的：

| 口 | 代码 | 说明 |
|---|---|---|
| 菜单页「继续推演」副标题 | `index.html:600-603` 只查 `s.v` 与 `s.lv`；`:659` `'第 ' + save.turn + ' / ... 回合'` 交给 `btn()` 的 `b.innerHTML`（`:649`） | **无需进游戏**，回首页即触发 |
| HQ 存档页 | `campaign.html:13834` `readSave()` → `:13843` `'<b>' + … + '</b> · 第 ' + sv.turn + ' 回合'` | 进 HQ → 存档页触发 |

**我实测复现（jsdom）**：

```js
// 存档：v/lv/map/units 全部合法，只有 turn 是注入串
turn: '"><img src=x id=pwnTurn onerror=alert(1)>'

validateSave(evil)  →  { ok: true }          // 引擎认为这是合法存档
document.querySelector('#pwnTurn')  →  存在   // 首页按钮里已经多出一个 img 节点
```

首页实际产出的 DOM：

```html
<button class="btn btn-primary">继续推演<small>第 1 关 · 北岭要塞 · 第 "&gt;<img src="x" id="pwnTurn" onerror="alert(1)"> / 8 回合</small></button>
```

### 7.2 音频预载

### 7.3 🟡 每次 `render()` 整块重建棋盘

`renderBoard` 直接 `board.innerHTML = html`（`campaign.html:11763`），随后重绑 **352 个** `addEventListener`（最大关 16×22）；每次渲染每格做 4 次线性扫描（`unitsAt`/`layerUnitsAt` 是 `filter`），30 支部队约 **4.2 万次比较**、79 支约 **11 万次**。

放大到交互上：按一次方向键就调一次 `render()`（`:11451`），也就是**每按一次方向键重排 352 个带 `clip-path` + `inset box-shadow` 的格子**。桌面端测不出来，中低端手机会有掉帧。

另一个副作用是**焦点会被重建摧毁**：行动气泡 `box.innerHTML = h`（`:12263`），每个操作后 `render()`，焦点掉回 `body`，下一步 Tab 从页首重新数——目标选择器（`:12320`）做对了，气泡没做。

### 7.4 🟡 P1 · iOS Safari 放不了 ogg
