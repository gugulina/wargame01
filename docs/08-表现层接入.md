# 08 · 表现层接入：UI、素材、音乐、剧情

> 结论：**要预留，但只在四个地方预留。** 现在建一层薄的表现层总线就够了，
> 不要建资源加载器、不要拆模块、不要上引擎。理由和边界都写在下面。

## 一、为什么现在做这几处，而不是等素材到位再做

判断标准只有一条：**现在做便宜、以后做贵的事才做。**

| 事项 | 现在做的成本 | 素材到位后再做的成本 | 决定 |
|---|---|---|---|
| 素材路径集中成一张表 | 半小时 | 分散在十几处字符串里，路径一改就得全局搜替换 | **现在做** |
| 表现层单一出口 `FX.*` | 一小时 | 音效、震屏、飘字散落在 `doAttack` / `fortFire` / `removeUnit` 里，加一个效果要改五处 | **现在做** |
| 事件表预留演出类效果 | 十分钟 | 事件总线已经跑起来了，事后加 kind 要重新梳理触发时机 | **现在做** |
| 目录结构与命名规范 | 十分钟 | 中文名 + 大写混用，线上 404 排查半天 | **现在做** |
| 棋盘分层渲染 | 两小时 + 回归 | 现在没收益，纯增加 bug 面 | **等接图片时做** |
| 资源预加载 / 进度条 | — | 8 MB 素材才需要 | **等素材上量** |
| 拆模块 / 引构建 / 上引擎 | — | 单文件是现在最大优势（双击就能玩、Pages 直传） | **只拆了 AI 一个域**（见下） |

> **v4.21 修正**：上表最后一行原来是「不做」。实际拆了 `game/ai.js` 一个域，
> 但不是"上模块系统"——是**运行时 `<script src>`**，没有构建步骤、没有 import/export、
> 没有打包器。`campaign.html` 依然是双击就能玩的入口，只是多了一个同目录的脚本。
>
> 为什么破例：红方 AI 有 848 行、40 个顶层符号，全挤在 11,000 行的引擎里，
> 改一次脾气要在文件里翻半天。而它**恰好是一个内聚的域**——只依赖引擎的 41 个
> 查询/执行函数，不被渲染和输入反向依赖，边界天然干净。
>
> 边界仍然守死：**不再继续拆**。CSS 已经在 v4.9 出去，AI 现在出去，
> 剩下的引擎（规则 / 渲染 / 输入 / 存档）都互相咬合，再拆就得引构建。
> 判断标准是"这个域能不能只用引擎的公开函数当接口、并且不被引擎反向依赖"，
> 两个条件缺一个就留在原地。

一句话：**接口要预留的是"接缝"，不是"框架"。**

## 二、现在有三层

```
关卡数据 LEVEL（地图/兵牌/事件/剧情）
        ↓
规则层 doAttack / fortFire / settlePhase / checkEvents   ← 只管发生什么，不管看起来怎样
        ↓
表现层 FX（唯一出口）                                    ← 只管怎么响、怎么闪、怎么演
        ↓
素材 ASSETS（一张表，全是 null 也不影响运行）
```

规则层调用表现层是一行 `FX.xxx(...)`，反过来表现层**从不改规则数值**。
`FX.on = false` 可以把整层关掉，战斗结算完全不受影响——自测里有一条断言专门守这个。

## 三、已经埋好的接缝

改规则、调数值的时候不用管这些，它们已经在正确的位置上等着素材了。

| 时机 | 调用 | 素材槽位 |
|---|---|---|
| 一次攻击结算完 | `FX.hit({defLoss, attLoss, ...})` | `sfx.fire` / `sfx.shell` + 震屏 + 双方伤害飘字 |
| 任何兵牌被歼灭 | `FX.sfx('kill')` + `FX.pop('歼灭')` | `sfx.kill` |
| 要塞炮/岸防炮自动开火 | `FX.sfx('shell')` + 伤害飘字 | `sfx.shell` |
| 构筑工事 / 布雷 / 架桥 | `FX.sfx('build')` + 工程名飘字 | `sfx.build` |
| 回合切换、敌方阶段 | `FX.banner(...)` | 纯 CSS 横幅，不需要素材 |
| 敌方波次投入 | `FX.banner(...)` + `FX.sfx('alarm')` | `sfx.alarm` |
| 战役事件触发 | `FX.banner('◆ ' + desc)` + `FX.sfx('event')` | `sfx.event` |
| 开局 / 结算 | `FX.bgm('battle' / 'result')` + `sfx.win` / `lose` | `bgm.*` / `sfx.*` |
| 剧情演出 | `FX.cutin({who, text, side, portrait})` | `story.portBlue` / `portRed`，有脸的人物走 `story.port<番号>`（如 `portBde1`）|

注意「歼灭」只在 `removeUnit()` 里埋了一次——所有死亡路径（攻击、炮击、触雷、
事件）都会经过它，所以在那里埋一处就等于全覆盖。这是这套结构最省事的地方。

## 四、素材怎么加

**先看清是哪一个分支——它们的接入程度差得很远。**

| 分支 | 填个文件名就生效？ | 为什么 |
|---|---|---|
| `sfx` | ✅ 是 | `preload` / `play` 已接线，21 个槽就是在用的状态（按兵种分派） |
| `bgm` | ✅ 是 | `FX.bgm()` 已接线，5 首自制曲已就位 |
| `story` | ✅ 是 | 剧情卡的立绘位已接线 |
| `ui` / `unit` / `fort` | ❌ **不是** | 代码里引用次数为 0，见表下说明 |

对前三组，三步：

1. 文件放进 `game/assets/` 对应子目录，命名遵守 `game/assets/README.md` 的五条规矩
2. 打开 `campaign.html` 搜 `const ASSETS`，把对应槽位的 `null` 改成路径（相对 `ASSETS.base`）
3. 刷新

逻辑一行都不用动。

**对 `ui` / `unit` / `fort` 这 38 个槽位，第三步不存在——因为没有读它的代码。**
它们是"先把位置占好等美术"的占位，不是"就绪"。要让它们真的生效，得先接线：

- `ASSETS.unit`：在 `renderBoard` 拼兵牌的那一段里插 `<img>`，并处理加载失败回退到现在的
  中文缩写（约 20 行）。现在的兵牌是这样拼的：
  `'<span class="n">' + u2.abbr + '</span>'`
- `ASSETS.fort`：工事是用 CSS 类画的（`.fort.H` / `.fort.B` …），要改成按 `ASSETS.fort[kind]`
  写内联 `background-image`（约 15 行）
- `ASSETS.ui`：12 张地形贴图要在每个六角格上做背景，280 格/关，还得分清纯色块与贴图的
  叠加顺序（约 30–40 行，且**必须重做一次性能验证**——`renderBoard` 是全量重建 `innerHTML`）

**文档不能比代码乐观。** 上一版这里写的是"没有第三步。游戏逻辑一行都不用动"，
如果照那句话排美术工期，会得到"图都画完就能上线"的错误结论。

`ASSETS` 现在长这样，所有会用到素材的地方都在里面（`sfx` 一组已经填完）：

```js
const ASSETS = {
  base: 'assets/',
  ui:    { hexPlain: null, hexForest: null, ... },   // 六角格贴图，未填
  unit:  { inf: null, gdn: null, ..., hkc: null },   // 21 个兵种，键名与 TYPE 严格对齐，未填
  fort:  { H: null, B: null, P: null, A: null, F: null },   // 未填
  sfx:   { uiClick: 'sfx/ui-click.ogg', fire: 'sfx/fire-v2.mp3', ... },   // 21 个全部已就位
  bgm:   { menu: 'bgm/menu.ogg', battle: 'bgm/battle.ogg', ... },   // 5 首已就位
  story: { bgBriefing: null, portBlue: null, portBde1: 'story/port-bde1.webp', ... }
         // 背景与通用立绘未填；角色位 portBde1（第 1 边防旅旅长）已接
};
```

自测会校验 `ASSETS.unit` 的键与 `TYPE` 完全一致、`ASSETS.fort` 的键与 `FORT_KEYS`
完全一致——以后加了新兵种忘了补素材槽，测试会直接报出来。

`story` 另有四条（v4.6 起）：
**台词引用的 `portrait` 键必须在 `ASSETS.story` 里存在**（写错一个字不会报错，
只会静默渲染成「立绘位」，而玩家会当成"本来就该有图但没做"，不会当 bug 报上来）、
**扫描确实命中过若干键**（否则上一条是空转）、
**填了值的文件必须真在磁盘上**、**尺寸必须是 3:4**（比例不对 `cover` 会对称裁切，头顶最先没）。
读尺寸用的是 `selftest.js` 里 40 行的 `imgSize()`（认 WebP/PNG/JPEG），
不引 `sharp`——为了取两个整数装个解码库不值。

**音效这一组已经接完了**，用的什么、什么授权、多长，全记在
`game/assets/sfx/CREDITS.md`（游戏内「素材来源」页也有一份）；想听就打开 `game/audio-lab/sfx-demo.html`。
换音效只要同名覆盖文件，代码不用动。

### 挑音效时怎么判断"像不像"（2026-10 补）

耳朵会骗人，尤其连续听十几个候选之后。这时候量四个数：

| 指标 | 怎么算 | 真枪 / 真炮 | 合成音 |
|---|---|---|---|
| **起振时间** | 包络从峰值 10% 到 99% 的耗时 | **< 5ms** | 20ms 以上 |
| **峰值因子** | 20·log10(峰值 / 有效值) | **20–28dB** | 12–16dB |
| **频谱平坦度** | 几何均值 / 算术均值 | 偏高（宽频噪声） | 很低（窄带有音调） |
| **低频占比** | 200Hz 以下能量占比 | 炮 40%+，枪 10% 左右 | 看素材 |

`tools/audiostat.py` 一条命令打全表（`python tools/audiostat.py <目录>`），
`tools/audioviz.py` 另外吐出波形 + 频谱拼图（能直接看出是宽频爆裂还是规则正弦）。

三个实测结论，写下来免得以后重踩：

1. **mp3 编码不会拖钝起振**。112kbps 编码再解码，起振 1.5ms→1.5ms、2.9ms→2.9ms，零变化。
   体积却能差 6 倍。放心用 mp3。
2. **降采样会**。22.05kHz 把 `fire` 的起振从 1.5ms 抹成 2.9ms —— 所以统一 44.1kHz。
3. **改内容必须改文件名**（`fire.mp3` → `fire-v2.mp3`）。不改名浏览器拿缓存，
   本地听着"没变化"能查半天。

候选对比页在 `game/audio-lab/index.html`，15 条音效按槽位分组，左边是上一版、右边是候选。

## 五、剧情演出怎么写

`LEVEL.story` 和 `LEVEL.events` 是两套东西，刻意分开：

- `events` 管**规则上发生了什么**（谁被歼灭 → 全旅组织度 -8）
- `story` 管**这段戏怎么演**（谁说话、什么表情、配什么图）

写法：

```js
story: {
  briefing: {
    beats: [
      { who: '方面军司令部', side: 'blue', portrait: 'portBlue',
        text: '第 205 装甲旅留下，务必守住机场与市区。' },
      { who: '敌第 3 摩托化步兵旅', side: 'red', portrait: 'portRed',
        text: '先头营已经抵近岚江东岸。' }
    ]
  }
}
```

两种触发方式：

```js
// 一、挂在事件效果里（推荐，带上触发条件）
effects: [ { kind: 'story', id: 'briefing' } ]

// 二、关卡脚本里直接演
FX.cutin({ who: '敌方指挥官', side: 'red', text: '……' });
```

`beats` 靠 `FX._csChain` 排队，一张一张弹，不会叠在一起。点一下继续，
台词没打完时点击直接全部弹出。ESC 关闭。同一个 `id` 一局只演一次
（记在 `state.storySeen`）。

事件效果现在支持的 kind：

| kind | 作用 | 属于 |
|---|---|---|
| `log` / `org` / `mod` / `spawn` | 改规则数值 | 规则层 |
| `banner` / `sfx` / `bgm` | 提示、音效、换曲 | 表现层 |
| `say` / `story` | 单人剧情卡 / 整段演出 | 表现层 |

后五种全都不改任何数值，素材缺失时静默跳过，**不会卡住事件链**。

### 5.1 战前简报：`briefing.pages`（v3.8）

`briefing` 除了 `beats` 还能带一组 `pages`——把"战役背景 / 敌情 / 任务"做成几页
可以翻的作战公文，翻完再演 `beats` 的对话。**只在点「开始新的战役」时播**
（`startNew()` 里 `await runBriefing()`），继续存档、重新开始、`?nointro`、`?demo=*`
全都不会触发。

```js
briefing: {
  pages: [{
    order: '作战命令 · 第 3 号',  // 左上角文号
    kicker: '战役态势',           // 标题上方小字
    title: '主力走了，你们留下',
    paras: [
      { t: '普通段落……' },
      { t: '要强调的一句。', hl: true }     // hl = 左侧红线引用块
    ],
    nums: [{ k: '兵牌', v: '21' }, { k: '战力', v: '117', hot: true }]
  }],
  beats: [ /* 公文档次之后接的对话，走 FX.cutin */ ]
}
```

几个刻意的选择：

- **公文整页淡入，不逐字**。逐字打字机适合"有人在说话"，不适合读一份文件，
  所以 `pages` 不做逐字，`beats` 才有。
- **跳过是整段跳过**，不是翻过一页，也不退回开始页——玩家已经点过"开始"了。
- **对话阶段纸张不收起**。`#cutscene` 的 z-index 是 80、`.brief` 是 70，
  让对话直接压在纸上变暗。若先收纸，会先露出战场地图再变暗，中间闪一下。
- **`runBriefing()` 抛错不影响开局**（`startNew` 里有 try/catch）。
  过场再好看也只是壳，不能把开局一起拽下来。
- 键盘在过场期间用 `capture + stopPropagation` 截住，并在全局监听里加了一道
  "简报/剧情卡可见就直接 return"。少这一道，空格会漏下去，在开局之前
  就把「结束我方阶段」触发掉。

临时看某一页：`?demo=brief` / `demo=brief2` / `demo=brief3`，看对话：`?demo=briefbeat`。
整条流程的回归测试是 `tools/briefcheck.js`（jsdom + 真 DOM，22 项）。

## 六、还没预留的三件事（以及为什么）

### 1. 棋盘分层渲染 —— 接图片前必须先做

现在 `renderBoard()` 每次重绘都 `board.innerHTML = html`，把 280 个格子整个重建一遍。
纯 CSS 画格子时这没问题（浏览器很快），但一旦换成 `<img>`：

- 图片节点每次重建，即使有缓存也会闪一下
- 手机上一次 render 重建 280 个 `<img>`，掉帧明显
- 血条/耐久条的过渡动画每次被打断

**做法**：拆成两层——`#gridStatic` 画地形（只在开局和架桥时重绘）+ `#gridUnits`
画兵牌、工事、高亮（每回合重绘）。两层都绝对定位，坐标同源。

不现在做的原因：这改动会碰所有选中/高亮/点击逻辑，现在的 81 项自测和平衡数据
全要重跑一遍，而**没有图片素材时它带来零收益**。等第一张贴图进来那天再做，
配合截图对比最稳。

### 2. 音频自动播放限制 —— 已解决

浏览器不允许没有用户交互就自动播声音，`new Audio().play()` 会被拒绝。
代码里一直有 `.catch(() => {})` 兜着不会报错，但**音乐要等玩家第一次点击才响**。

**这个限制已经在入口处解决。** 菜单页点关卡 / 简报翻页 / 游戏里第一次点击，
都算浏览器要的交互；引擎另外挂了一次性的全局兜底（`pointerdown` / `keydown` 首次触发即
`FX.unlock()`），所以即使什么按钮都没点就进战场，第一次点地图也会解锁：

```js
function startNew() {
  closeStart();
  FX.unlock();     // 必须留在这次点击的同步调用栈里，脱离手势就解锁不了
  newGame();
  fitView(false);
}
```

`FX.unlock()` 会建一个 1 帧的静音 WebAudio buffer 并 `start(0)`，顺手 `resume()` 上下文。
现在 FX 用的还是 `<audio>` 元素（点击后 `play()` 本身就放行），这步是给将来换音效引擎留的。

**结论：BGM 素材放进 `ASSETS.bgm` 就能响，不用再改代码。**

### 3. 存档 —— 已实现

`SAVE_KEY = 'wargame.lankou.save'`，`SAVE_VER = 1`。

**存什么**（`saveSnapshot()`）：`turn / score / map / units / mines / depots / forts / ctrl / mods / flags / eventsDone / storySeen / everSeen / initStr / log 最近 80 条`。
**不存**：`selected / reachable / targets / mode / fields` —— 每帧重算。

两个容易踩的点：

1. **`LEVEL.map` 必须存**。`doBridge()` 是就地改写地图字符串的，不存的话读档后桥就没了。
2. **`eventsDone` / `storySeen` 必须存**，否则读档会重播已经看过的剧情。当初写存档时正是按这条提醒做的。

**写档时机**：`doMove / doAttack / doFort / doMine / doClearMine / doBridge / doDepot / endBluePhase / newGame`。
全部包在 `try` 里 —— 隐私模式、`file://` 直开、配额满都可能让 `localStorage` 抛错，
存档失效只该降级成"不能续关"，不该让游戏崩（自测有断言守着）。

**校验**：版本号或关卡 id 对不上就当没有存档。宁可不续，不能读半个坏局。

**作废**：`showOverlay()` 时 `clearSave()`，分出胜负的局不再续。

## 七、建议的推进顺序

按"性价比 / 依赖关系"排，不按工程量：

7. **剧情演出 + 立绘** —— 最后做，因为它依赖剧本，而剧本要等规则和关卡都稳定。

一句话：**先听觉，再视觉，最后戏剧。**

## 八、改界面与文案时的硬规矩（v4.17 从项目记忆归位）

这一节是从项目记忆里搬过来的：都是踩过一次就再也不想踩的坑。改 `campaign.html` 的界面层或任何一句玩家能看到的文字之前，先读一遍。

### 8.1 行动菜单

选中兵牌 → 兵牌旁出现「行动 N」小入口（`.uops.mini`），点开才是整组按钮，**默认收起**——
展开态有 250 px 高，压在棋盘上必然盖住可达格；一点地图就 `uopsOpen=false`。

三个键的语义**不能合并**：

| 键 | 语义 |
|---|---|
| `move` | 进入移动模式 |
| `__close` | 收起菜单，**保留当前选中** |
| `__cancel` | 收起菜单 + **清掉选中** |

**已经移动过的单位，「移动」整项消失，不是置灰**；可达范围只在 `mode === 'move'` 时画。

### 8.2 点击路由（要加功能只许在这一层加）

顺序固定：战术卡 → 施工 → **移动** → **开火** → 选中 / 轮换 / 取消。

判「这一格里有谁能打」只走 `targetAt()`（`state.targets` ∩ `unitsAt`），
**别用 `unitAt()`**——它是地表优先，守备营和敌机同格时永远取到地面那支，于是「点飞机却打了营」。

### 8.3 Esc 的层序

`HQ → 战术卡 → 设置 → 说明 → 目标选择器 → 作业气泡 → 模式 → 检视 → 选中`

少一层就会一路清到底，玩家按一次 Esc 丢掉整轮操作。

### 8.4 行动气泡的定位

`placeUops` 搜索半径 160 px，障碍只有兵牌；**缩小面板比扩大半径便宜**。
`syncUnitOps` 重建时要清 `left/top/bottom/transform/maxWidth` 整组，
`applyView()` 里必须调 `repositionUops()`，否则缩放后气泡停在旧位置。术语统一叫「行动」。

### 8.5 键盘操作

- 用 `:focus-visible`，不用 `:focus`（鼠标点一下也留个焦点框，很脏）。
- **别给 352 个格子加 `tabindex`**：`#board` 一个焦点 + `kbCur` 记当前格，回车走同一个 `onHexClick`。
- 上下只改行、左右只改列，贴边夹紧（别做八方向循环，玩家会迷路）。
- 光标用 `::after` 双层描边——`clip-path` 会把 `outline` 裁掉。
- HQ 是 `role="dialog"`，焦点返回走 `hqReturnFocus`。

### 8.6 要点标注

`.hex` 的 `::before` / `::after` **已经被占用**（要点染色 / 工事描边），新描边只能用真实元素
（`.ocore`）——抢位不报错，只会静默少东西。

标签按**连通簇**打（`objClusters`，判据 `hexDist === 1`）：分开的两块地如果直接取平均坐标，
标签会打到中间的空地上。核心要点给金边 + `★` + 「必守」。

### 8.7 文案三条

1. **`**重点**` 只有一个转换点**：渲染口的 `bold()`（图鉴 `<li>`、单位面板 `.abil`、地形 `note`）。
   新增渲染口要自己调，否则玩家看到字面的星号。
2. **文案里不许出现代码层表述**：字段名（`atk`）、文件名、地形字符（`~` / `s`）、反引号、`ZOC`。
   **技战术对标二战**：螺旋桨机用机枪机炮，不谈导弹；图鉴写「暂未编成」，不写「未登场 / 未实现」。
3. **按纯文本渲染的字段里不许写 HTML**：`name` / `when` / `where` / `teaser` / `type` / `intro` /
   `prev` / 事件 `desc` 与 `text`，`briefing` 正文例外。

配套还有两条纪律：

- **`bold()` 只管作者手写的静态文案**；存档来的必须 `esc()`，且**不许先 `bold` 再 `esc`**。
  战报是 `bold(esc(text))`——顺序反了会把转义符再当标记解析。
- **文案断言打渲染结果，不扫源码**（注释里也有 `atk` 这种词）：`selftest [34]`、`briefcheck [16]`。
- **图鉴里的格数会过期**：改机动 / 消耗一定回头改 `TYPE[].abil`。v4.17 三型坦克的「公路 2 点/格」
  就是上一版改规则时漏的，玩家看到的是两套互斥的数字。

### 8.8 地图缩放与撤销（v4.18 热补丁）

**缩放只有一份实现**：`vK / vX / vY` 三个变量 + `#boardView` 的 `transform`，
窄屏与宽屏走同一条路径，连适应倍数的判据也是同一套（`kw` 与 `kh` 取小、0.12～2 倍），
唯一的差别是 `mapCap()`：窄屏按屏高比例给地图留高度（下方还有面板），宽屏取 0.68 屏高。

**`mapCap()` 必须两个调用点共用**（`applyView` 算容器高、`fitView` 算适应倍数）。
分开写就会出现"按 A 算倍数、按 B 裁高度"，图的下沿被切掉——而且只在某一档窗口尺寸下出现。

**别再给桌面封顶 1 倍**：C1 的棋盘只有 584×378，容器有 975 宽，封顶 1 倍就是左右各空近 200 px，
看着像"图没加载完"。v4.18 之前桌面还有三处一起把它锁死——`applyView()` 里 `transform = ''` 直接
短路、`.zctrl` 基础态 `display:none`、`fitView()` 强写 `vK = 1`，于是**窗口比棋盘窄时右侧被切掉、
只能拖着看**。

三条纪律：

1. **判"缩放生效没有"要断 DOM 上的 `transform`，不能断 `vK`**——`zoomBy()` 本来就会改模块变量，
   旧实现下 `vK` 照样变、画面一动不动。selftest 的 stub DOM 读不到 `style`，这条只能在
   `briefcheck` 里验（`[27]` 那一节的末尾）。
2. **滚轮到底要放行页面滚动**：`vK` 已经等于 `vFit` 或 `vMax` 时不再 `preventDefault`，
   否则鼠标一停在地图上整页就滚不动，看着像卡死。`ctrlKey` 直接返回——触摸板捏合在 Chrome 里
   报成 `ctrl+wheel`，不返回会和 touch 手势各触发一次，一捏跳两档。
3. **左键拖动阈值 4 px，并复用 `supClick`**：拖动后要抑制紧跟的那一次点击，
   否则玩家想点格子、手抖两像素，就变成"图动了但什么都没选中"。松手后 30 ms 内解除抑制
   （click 排在 mouseup 之后的同一轮里）。

**撤销只返还"被撤销掉的那一步"用掉的卡**：`pushUndo()` 在 `state.cardUsed[id] = true` **之前**
压栈，所以快照里的 `cardUsed` 是"这张卡用掉之前"的状态，`doUndo()` 恢复它即可。
两个坑：

- **恢复不能写 `s.cardUsed || {}`**：快照里没有这一项时会把整局用掉的卡全退回来，
  连撤几步就能把卡刷满。旧版撤销栈按"不返还"处理（保留当前值）。
- **两个断言要分开**：只写"撤销后最后一张卡回到手牌"，`pushUndo` 记成空对象时照样绿。
  得用"两张卡连打 → 撤一次"的场景切出两条——先前用掉的**不**返还、这一步用掉的返还。
