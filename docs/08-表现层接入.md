# 08 · 表现层接入：UI、素材、音乐、剧情

> 结论：**要预留，但只在四个地方预留。** 现在建一层薄的表现层总线就够了，
> 不要建资源加载器、不要拆模块、不要上引擎。理由和边界都写在下面。

## 一、为什么现在做这几处，而不是等素材到位再做

判断标准只有一条：**现在做便宜、以后做贵的事才做。**

| 事项 | 现在做的成本 | 素材到位后再做的成本 | 决定 |
|---|---|---|---|
| 素材路径集中成一张表 | 半小时 | 分散在十几处字符串里，路径一改就得全局搜替换 | **现在做** |
| 表现层单一出口 `FX.*` | 一小时 | 音效、震屏、飘字散落在 `doAttack` / `fortFire` / `removeUnit` 里，加一个效果要改五处 | **现在做** |
| 事件表预留演出类效果 | 十分钟 | 事件总线已经跑起来了，事后加 kind 要重新梳理触发时机 | **现在做** |
| 目录结构与命名规范 | 十分钟 | 中文名 + 大写混用，线上 404 排查半天 | **现在做** |
| 棋盘分层渲染 | 两小时 + 回归 | 现在没收益，纯增加 bug 面 | **等接图片时做** |
| 资源预加载 / 进度条 | — | 8 MB 素材才需要 | **等素材上量** |
| 拆模块 / 引构建 / 上引擎 | — | 单文件是现在最大优势（双击就能玩、Pages 直传） | **不做** |

一句话：**接口要预留的是"接缝"，不是"框架"。**

## 二、现在有三层

```
关卡数据 LEVEL（地图/兵牌/事件/剧情）
        ↓
规则层 doAttack / fortFire / settlePhase / checkEvents   ← 只管发生什么，不管看起来怎样
        ↓
表现层 FX（唯一出口）                                    ← 只管怎么响、怎么闪、怎么演
        ↓
素材 ASSETS（一张表，全是 null 也不影响运行）
```

规则层调用表现层是一行 `FX.xxx(...)`，反过来表现层**从不改规则数值**。
`FX.on = false` 可以把整层关掉，战斗结算完全不受影响——自测里有一条断言专门守这个。

## 三、已经埋好的接缝

改规则、调数值的时候不用管这些，它们已经在正确的位置上等着素材了。

| 时机 | 调用 | 素材槽位 |
|---|---|---|
| 一次攻击结算完 | `FX.hit({defLoss, attLoss, ...})` | `sfx.fire` / `sfx.shell` + 震屏 + 双方伤害飘字 |
| 任何兵牌被歼灭 | `FX.sfx('kill')` + `FX.pop('歼灭')` | `sfx.kill` |
| 要塞炮/岸防炮自动开火 | `FX.sfx('shell')` + 伤害飘字 | `sfx.shell` |
| 构筑工事 / 布雷 / 架桥 | `FX.sfx('build')` + 工程名飘字 | `sfx.build` |
| 回合切换、敌方阶段 | `FX.banner(...)` | 纯 CSS 横幅，不需要素材 |
| 敌方波次投入 | `FX.banner(...)` + `FX.sfx('alarm')` | `sfx.alarm` |
| 战役事件触发 | `FX.banner('◆ ' + desc)` + `FX.sfx('event')` | `sfx.event` |
| 开局 / 结算 | `FX.bgm('battle' / 'result')` + `sfx.win` / `lose` | `bgm.*` / `sfx.*` |
| 剧情演出 | `FX.cutin({who, text, side, portrait})` | `story.portBlue` / `portRed` |

注意「歼灭」只在 `removeUnit()` 里埋了一次——所有死亡路径（攻击、炮击、触雷、
事件）都会经过它，所以在那里埋一处就等于全覆盖。这是这套结构最省事的地方。

## 四、素材怎么加（三步）

1. 文件放进 `game/assets/` 对应子目录，命名遵守 `game/assets/README.md` 的五条规矩
2. 打开 `campaign.html` 搜 `const ASSETS`，把对应槽位的 `null` 改成路径（相对 `ASSETS.base`）
3. 刷新

没有第三步。游戏逻辑一行都不用动。

`ASSETS` 现在长这样，所有会用到素材的地方都在里面（`sfx` 一组已经填完）：

```js
const ASSETS = {
  base: 'assets/',
  ui:    { hexPlain: null, hexForest: null, ... },   // 六角格贴图，未填
  unit:  { inf: null, gdn: null, ..., hkc: null },   // 21 个兵种，键名与 TYPE 严格对齐，未填
  fort:  { H: null, B: null, P: null, A: null, F: null },   // 未填
  sfx:   { uiClick: 'sfx/ui-click.ogg', fire: 'sfx/fire-v2.mp3', ... },   // 12 个全部已就位
  bgm:   { menu: null, battle: null, tension: null, result: null },   // 未填
  story: { bgBriefing: null, portBlue: null, ... }   // 未填
};
```

自测会校验 `ASSETS.unit` 的键与 `TYPE` 完全一致、`ASSETS.fort` 的键与 `FORT_KEYS`
完全一致——以后加了新兵种忘了补素材槽，测试会直接报出来。

**音效这一组已经接完了**，用的什么、什么授权、多长，全记在
`game/assets/sfx/CREDITS.md`；想听就打开 `game/assets/sfx/preview.html`。
换音效只要同名覆盖文件，代码不用动。

### 挑音效时怎么判断"像不像"（2026-10 补）

耳朵会骗人，尤其连续听十几个候选之后。这时候量四个数：

| 指标 | 怎么算 | 真枪 / 真炮 | 合成音 |
|---|---|---|---|
| **起振时间** | 包络从峰值 10% 到 99% 的耗时 | **< 5ms** | 20ms 以上 |
| **峰值因子** | 20·log10(峰值 / 有效值) | **20–28dB** | 12–16dB |
| **频谱平坦度** | 几何均值 / 算术均值 | 偏高（宽频噪声） | 很低（窄带有音调） |
| **低频占比** | 200Hz 以下能量占比 | 炮 40%+，枪 10% 左右 | 看素材 |

`tools/audiostat.py` 一条命令打全表（`python tools/audiostat.py <目录>`），
`tools/audioviz.py` 另外吐出波形 + 频谱拼图（能直接看出是宽频爆裂还是规则正弦）。

三个实测结论，写下来免得以后重踩：

1. **mp3 编码不会拖钝起振**。112kbps 编码再解码，起振 1.5ms→1.5ms、2.9ms→2.9ms，零变化。
   体积却能差 6 倍。放心用 mp3。
2. **降采样会**。22.05kHz 把 `fire` 的起振从 1.5ms 抹成 2.9ms —— 所以统一 44.1kHz。
3. **改内容必须改文件名**（`fire.mp3` → `fire-v2.mp3`）。不改名浏览器拿缓存，
   本地听着"没变化"能查半天。

候选对比页在 `game/audio-lab/index.html`，15 条音效按槽位分组，左边是上一版、右边是候选。

## 五、剧情演出怎么写

`LEVEL.story` 和 `LEVEL.events` 是两套东西，刻意分开：

- `events` 管**规则上发生了什么**（谁被歼灭 → 全旅组织度 -8）
- `story` 管**这段戏怎么演**（谁说话、什么表情、配什么图）

写法：

```js
story: {
  briefing: {
    beats: [
      { who: '方面军司令部', side: 'blue', portrait: 'portBlue',
        text: '第 205 装甲旅留下，务必守住机场与市区。' },
      { who: '敌第 3 摩托化步兵旅', side: 'red', portrait: 'portRed',
        text: '先头营已经抵近岚江东岸。' }
    ]
  }
}
```

两种触发方式：

```js
// 一、挂在事件效果里（推荐，带上触发条件）
effects: [ { kind: 'story', id: 'briefing' } ]

// 二、关卡脚本里直接演
FX.cutin({ who: '敌方指挥官', side: 'red', text: '……' });
```

`beats` 靠 `FX._csChain` 排队，一张一张弹，不会叠在一起。点一下继续，
台词没打完时点击直接全部弹出。ESC 关闭。同一个 `id` 一局只演一次
（记在 `state.storySeen`）。

事件效果现在支持的 kind：

| kind | 作用 | 属于 |
|---|---|---|
| `log` / `org` / `mod` / `spawn` | 改规则数值 | 规则层 |
| `banner` / `sfx` / `bgm` | 提示、音效、换曲 | 表现层 |
| `say` / `story` | 单人剧情卡 / 整段演出 | 表现层 |

后五种全都不改任何数值，素材缺失时静默跳过，**不会卡住事件链**。

### 5.1 战前简报：`briefing.pages`（v3.8）

`briefing` 除了 `beats` 还能带一组 `pages`——把"战役背景 / 敌情 / 任务"做成几页
可以翻的作战公文，翻完再演 `beats` 的对话。**只在点「开始新的战役」时播**
（`startNew()` 里 `await runBriefing()`），继续存档、重新开始、`?nointro`、`?demo=*`
全都不会触发。

```js
briefing: {
  pages: [{
    order: '作战命令 · 第 3 号',  // 左上角文号
    kicker: '战役态势',           // 标题上方小字
    title: '主力走了，你们留下',
    paras: [
      { t: '普通段落……' },
      { t: '要强调的一句。', hl: true }     // hl = 左侧红线引用块
    ],
    nums: [{ k: '兵牌', v: '21' }, { k: '战力', v: '117', hot: true }]
  }],
  beats: [ /* 公文档次之后接的对话，走 FX.cutin */ ]
}
```

几个刻意的选择：

- **公文整页淡入，不逐字**。逐字打字机适合"有人在说话"，不适合读一份文件，
  所以 `pages` 不做逐字，`beats` 才有。
- **跳过是整段跳过**，不是翻过一页，也不退回开始页——玩家已经点过"开始"了。
- **对话阶段纸张不收起**。`#cutscene` 的 z-index 是 80、`.brief` 是 70，
  让对话直接压在纸上变暗。若先收纸，会先露出战场地图再变暗，中间闪一下。
- **`runBriefing()` 抛错不影响开局**（`startNew` 里有 try/catch）。
  过场再好看也只是壳，不能把开局一起拽下来。
- 键盘在过场期间用 `capture + stopPropagation` 截住，并在全局监听里加了一道
  "简报/剧情卡可见就直接 return"。少这一道，空格会漏下去，在开局之前
  就把「结束我方阶段」触发掉。

临时看某一页：`?demo=brief` / `demo=brief2` / `demo=brief3`，看对话：`?demo=briefbeat`。
整条流程的回归测试是 `tools/briefcheck.js`（jsdom + 真 DOM，22 项）。

## 六、还没预留的三件事（以及为什么）

### 1. 棋盘分层渲染 —— 接图片前必须先做

现在 `renderBoard()` 每次重绘都 `board.innerHTML = html`，把 280 个格子整个重建一遍。
纯 CSS 画格子时这没问题（浏览器很快），但一旦换成 `<img>`：

- 图片节点每次重建，即使有缓存也会闪一下
- 手机上一次 render 重建 280 个 `<img>`，掉帧明显
- 血条/耐久条的过渡动画每次被打断

**做法**：拆成两层——`#gridStatic` 画地形（只在开局和架桥时重绘）+ `#gridUnits`
画兵牌、工事、高亮（每回合重绘）。两层都绝对定位，坐标同源。

不现在做的原因：这改动会碰所有选中/高亮/点击逻辑，现在的 81 项自测和平衡数据
全要重跑一遍，而**没有图片素材时它带来零收益**。等第一张贴图进来那天再做，
配合截图对比最稳。

### 2. 音频自动播放限制 —— 已解决

浏览器不允许没有用户交互就自动播声音，`new Audio().play()` 会被拒绝。
代码里一直有 `.catch(() => {})` 兜着不会报错，但**音乐要等玩家第一次点击才响**。

**这个限制已经在入口处解决。** 菜单页点关卡 / 简报翻页 / 游戏里第一次点击，
都算浏览器要的交互；引擎另外挂了一次性的全局兜底（`pointerdown` / `keydown` 首次触发即
`FX.unlock()`），所以即使什么按钮都没点就进战场，第一次点地图也会解锁：

```js
function startNew() {
  closeStart();
  FX.unlock();     // 必须留在这次点击的同步调用栈里，脱离手势就解锁不了
  newGame();
  fitView(false);
}
```

`FX.unlock()` 会建一个 1 帧的静音 WebAudio buffer 并 `start(0)`，顺手 `resume()` 上下文。
现在 FX 用的还是 `<audio>` 元素（点击后 `play()` 本身就放行），这步是给将来换音效引擎留的。

**结论：BGM 素材放进 `ASSETS.bgm` 就能响，不用再改代码。**

### 3. 存档 —— 已实现

`SAVE_KEY = 'wargame.lankou.save'`，`SAVE_VER = 1`。

**存什么**（`saveSnapshot()`）：`turn / score / map / units / mines / depots / forts / ctrl / mods / flags / eventsDone / storySeen / everSeen / initStr / log 最近 80 条`。
**不存**：`selected / reachable / targets / mode / fields` —— 每帧重算。

两个容易踩的点：

1. **`LEVEL.map` 必须存**。`doBridge()` 是就地改写地图字符串的，不存的话读档后桥就没了。
2. **`eventsDone` / `storySeen` 必须存**，否则读档会重播已经看过的剧情。当初写存档时正是按这条提醒做的。

**写档时机**：`doMove / doAttack / doFort / doMine / doClearMine / doBridge / doDepot / endBluePhase / newGame`。
全部包在 `try` 里 —— 隐私模式、`file://` 直开、配额满都可能让 `localStorage` 抛错，
存档失效只该降级成"不能续关"，不该让游戏崩（自测有断言守着）。

**校验**：版本号或关卡 id 对不上就当没有存档。宁可不续，不能读半个坏局。

**作废**：`showOverlay()` 时 `clearSave()`，分出胜负的局不再续。
