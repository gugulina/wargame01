## 〇、三条口径（先看，否则表会被读错）

**1. 每轮的 bug 反馈是固定项，允许「本轮无」，不许留空。**
写"无"必须带**日期 + 来源**（`本轮无（10-31 收，来源：问卷 + 三名试玩）`）。
原因：留空的格子下一次会被读成"忘了排"，和"排了但没做"分不清；
而"没人反馈"和"没去收"是两件事，后者是流程故障，得能被看见。

**2. 机制列决定这一版要不要跑自战。**
动了规则就必须跑——十关全跑，30–40 局起步，刀刃关（C5 / C3）看合并 200 局；
只动文案 / 素材 / 界面 / 打包**不跑**（这条是 v4.15 定下的规矩）。
表里带 ⚙ 的版本要跑，带 🎨 的不跑。

**3. 素材列写的是"这一轮能不能落地"，不是"这一轮想不想要"。**
72 张待补图里有 **58 张必须先写代码**，图先到也没用，见第三节。

## 二、逐轮说明

### v4.17 · 玩家反馈批（实际执行，已发）✅

| | |
|---|---|
| **为什么插队** | 这一版原定做"刹车与地基"。v4.16 的正式反馈进来之后，9 条里 **5 条动引擎语义**（公路机动、弹药预测、AI、要点标注、超额判定），它们彼此耦合，拆开做只会让每一片都要重跑一次十关自战。反馈批整批做，比按原排期硬分片便宜 |
| **为什么版本号往前推而不是塞回 v4.16** | v4.16 已经提交推送过两条装甲机制（履带压制、突破跟进）。同名版本再塞新内容，玩家看到的"v4.16"就有两种行为，反馈没法归因 |
| **出口条件** | ① 十关达成率回到带内（按 100 局判定，40 局噪声 ±12）② 每条反馈都能在界面上点到 ③ 新断言逐条反向验证会红 |

**机制**：
- **公路只对轮式是捷径**。轮式（摩步、装步、指挥部、辎重、炮兵、反坦克连）公路上每格 0.7 点；坦克照常 1 点。加成**只在脱敌时成立**——身边一格有敌人就回到 1 点。理由与 A/B 记录写在 `moveCost` 上方注释里：无条件生效会把追击与突围两关的时间表整体前移，十关全要重调。
- **弹药补弹预测**。`ammoTick()` 一份判定，`endTurn` 与兵牌面板共用，面板显示 `+1` / `不补` + 原因（满弹 / 断绝 / 已移动 / 不在码头圈）。
- **超额条件**。`perfectHint(lv)` 由引擎算、导出给菜单页，与 `judgeFinal` / `reachResult` 同源，避免"菜单说可超额、打完不给"。
- **要点按连通簇标注**。`objClusters(o)` 用 `hexDist === 1` 切簇，C6「北郊防线」两段高地各出一个标签；核心要点加 `.ocore` 金边与「必守」后缀。
- **敌方 AI**：辎重不叠堆、贴身护卫改开火优先级（**不改走位**）、炮兵提前一回合转移。三组"更激进"的改法全部 A/B 否决，数字写在 `redGoal` 上方。
- **补漏**：C6 补蓝方师属高炮连；C3 的敌第 8 摩步旅原来 `wave:0` 且没有任何事件 spawn，**整关不存在**——补齐旅部与三个营并由事件投入。

**文案**：手册「公路」条重写（轮式/履带、脱敌与否）· 三型坦克公路文案与实际数值对齐 · 公告 v4.17。

**Bug 反馈**：9 条全部闭环。另修两条自查发现的数据失效：C3 预备队永不进场（现在 `check.js` 会拦）、`moveCost` 对最小入参崩掉（校验器踩到）。

**顺延**：原定的油料续航、反装甲暴露、剧情背景渲染口、`docs/15` 问卷改题全部顺延到 v4.18，本轮未动。

## 五、Bug 反馈怎么进版（固定项的流程）

| 环节 | 规则 |
|---|---|
| **入口** | ① 已发布的玩家问卷 ② 试玩口头反馈 ③ 自查（体检报告 / `npm test` 红了） |
| **判级** | **P0** 存档损坏 / 进不了关 / 静默失声 → **当轮修，不排期**；**P1** 机制做错、数值明显不对 → 下一轮；**P2** 文案 / 手感 → 排进就近的 🎨 版 |
| **落点** | 每条反馈必须落到某一轮的"Bug 反馈"格子里，**不许悬空**；当轮修不掉的写"→ vX.YZ" |
| **留痕** | 拒绝要写原因（例：`P3-1 同名兵种规模差 → 有意设计，不改`），否则下一轮会被重新提一次 |
| **空值** | `本轮无（MM-DD 收，来源：…）`。**不许写 `-`** |

**为什么这条规矩值得单独写**：`docs/17` 里 `P3-3`（mutcheck 未覆盖 5 条）挂了三个版本没人销项，就是因为它没有落点。写进格子里，才有人问"这条怎么还没动"。

## 六、验收与发版

| 版本类型 | 必跑 | 不必跑 |
|---|---|---|
| ⚙ 动机制 | `npm test`（七步）+ 十关自战 + 变异验证新断言 | — |
| 🎨 动文案 / 素材 / 界面 | `npm test` | 自战 |
| 任意版本出包 | 上面的全量 + `build-www` + `cap copy` + `gradlew **clean** assembleDebug` + 解包 `diff` 对 `www` | — |

**出包时机**（按你的要求，均待线上反馈后再定）：

| 候选点 | 理由 |
|---|---|
| v4.19 后 | 装甲三件套齐了，机制面第一次完整；也是反馈已经攒够一轮的时候 |
| v4.22 后 | 难度档是能直接感知的东西，比单出一版修 bug 划算 |

**发版一律 `clean assembleDebug`**：增量打包会虚胖（v9 实测差 42 KB），而且体积只在 clean 之间才可比。验收看内容不看体积。
