## 三、P2 — 可排期

### P2-1 · 10 个死音效仍入库（119 KB）

`game/assets/sfx/` 磁盘 31 个音频文件，`ASSETS.sfx` 21 个槽全部有在役文件，剩下 **10 个从未被引用**：

```
shell-take1.ogg 23KB   alarm-synth.ogg 19KB   track-synth.ogg 16KB
engine-synth.ogg 13KB  build-synth.ogg 12KB  rifle-synth.ogg 10KB
event.ogg 9KB          step-synth.ogg 7KB     fire-synth.ogg 6KB
ui-move.ogg 5KB
```

> **上一版报告在这条上错得最危险**：它列的 14 个里包含 `fire-v2` / `hit-v2` / `kill-v2` / `alarm-v2` 四个，
> 而这四个正是 `ASSETS.sfx` 的 `fire` / `hit` / `kill` / `alarm` 槽**在役文件**。
> 照那份清单删，`FX` 内部的空 catch 不会报错，只是这四种声音永远消失——项目里专门为这个坑立过规矩。

其中 8 个 `*-synth.ogg` 是 `tools/sfx-synth.js` 的合成产出（OUTDIR 直指该目录），删除后 `npm run sfx` 可重新生成；
`shell-take1` / `event` / `ui-move` 三个是旧版实录，删了不可重生，建议留作备选。
`www/` 只带在役的 21 个，发布物**不受影响**，纯仓库膨胀问题。

### P2-2 · 试听页的备选毛料仍入库（14 个 mp3 / 297 KB）

`game/audio-lab/` 入库 19 个文件、合计约 **360 KB**，其中 `cand/*.mp3` 原始备选素材 14 个占 297 KB。

> 上一版报告写「19 个文件 1.5 MB」，那是 `du -sh` 整个目录的结果——**未入库的 `*.embed.html` 占了 1.09 MB**。
> 入库部分只有 360 KB，出库能省的也就这么多。

**但整目录出库是错的**：`bgm-tracks.js` 是 5 首 BGM 的**唯一真源**（`npm run bgm` 从它渲染），
`sfx-demo.html` / `bgm-demo.html` / `index.html` 是当初刻意入库的骨架（内嵌版才走 `.gitignore`）。
该出库的只有 `cand/*.mp3` 那 14 个毛料——它们违背了「毛料不进库」的原则（`game/_cand/` 就是被忽略的）。
