## 一、现状：三型坦克共用一套动词

轻型坦克营 / 中型坦克营 / 重型坦克营目前的差异，只有**两条规则 + 一张数值表**：

| 项 | 轻坦 larm | 中坦 marm | 重坦 harm |
|---|---|---|---|
| 战力 / 机动 | 10 / 12 | 12 / 10 | 15 / 7 |
| 平原·道路攻击 | +10% | +15% | +20% |
| 城镇攻击 | −10% | −10% | −15% |
| 行进间射击（机动后开火） | 无惩罚 | 无惩罚 | **−10%** |
| 3:1 击退 | ✗ | ✓ | ✓ |
| 对反坦克火力承伤 | +90% | +80% | +55% |
| 坦克互殴 | 对中 −10 / 对重 −15 | 对轻 +15 / 对重 −10 | 对轻 +25 / 对中 +10 |

两条规则是：

1. **装甲突击**（`ARM_FIRE`）：机动后开火不受 −10% 惩罚。
2. **击退**（`canPushBack` + `PUSH_BLOCK_ORG=8`）：比值 ≥ 3:1 时把守军顶出一格；退路堵死改扣 8 点组织度。

**问题不在数值平衡，在玩法**：玩家面对任何一型坦克，可选的只有「走到哪、打谁」。
没有哪个决策是"只有坦克能做、而且做出来不一样"的。三型坦克的手感差异，
最后都落在"这块铁厚不厚、跑得快不快"上——这是装备差异，不是战术差异。

## 二、设计目标与约束

| 目标 | 具体要求 |
|---|---|
| **动词化** | 每条机制都必须是一个玩家主动做的选择，不是被动加成的数值 |
| **编制分工** | 三型各有唯一擅长的活儿，做错场合要赔本（沿用现有"没有升级版"的原则） |
| **不新造系统** | 只复用组织度、击退、补给场、工事、反击这五套已有系统 |
| **可测** | 每条都能写成 selftest 断言，且能反向变异（改回错写法必须红） |
| **能刹车** | 加进攻手段的同时必须加一条负反馈，否则装甲会变成无脑解 |

技术对标仍按二战：没有火控计算机、没有主动防护，一切从"车长探出头看"这个精度出发。

## 三、机制清单

优先级：**P0 = 建议下一版做**（低成本高收益）· **P1 = 同批或紧随**（刹车与对手戏）· **P2 = 暂不做**（见第六节）。

### 3.1 冲击（P0）

> 坦克最像坦克的那个动作：一脚油门怼上去。

| 项 | 内容 |
|---|---|
| **触发条件** | ① 本回合**尚未开火**；② 本回合的移动路径是**连续同向 ≥2 格**（中途转向即失效）；③ 目标位于该方向的扇区内（正前方 ±1 个邻居方向） |
| **效果** | 攻击修正 **+10% 轻 / +20% 中 / +25% 重**；命中后目标额外 **组织度 −6** |
| **代价** | 自身 **组织度 −6**；直到下个本方回合开始，**防御 −10%**（车体侧面与后部暴露） |
| **为什么是特色** | 它是唯一"用安全换战果"的动作——不冲击的话，坦克可以**先开火再撤**（现有规则允许开火后再移动），冲击则必须先把车开进对方火力范围。这个取舍是玩家每回合都要做的判断 |

**边界情况**

- 目标在**城市 / 林地 / 丘陵**时不吃冲击加成：坦克冲不进巷子和树林，这是它最该有的限制。
- 目标有**带耐久工事**（碉堡 / 要塞炮 / 岸防炮）时，冲击加成**减半**；重坦另享有 3.6 的破障加成，两者独立相加（先算破障的 +10%，再算冲击减半，不要连乘）。
- 与 3.3 履带压制的额外组织度**不叠加**，取较高值（−6），否则一次冲锋能把满编营直接压到崩线。
- 冲击只影响**本次攻击**，不改变装甲突击（机动后开火无惩罚）这条既有规则。

**实现要点**

- 需要在移动时记录"当前直线方向"与"已连续走的格数"：`u.chargeDir`（0–5）、`u.chargeLen`（0–6）。
  转向或本回合结束即清零。
- **这两个字段必须进存档白名单**（`validateSave`）：越界值一律归零，不能信存档。
- 判定放在 `previewAttack` 里（与现有 `ARMOR_PROFILE` 同一段），不要写进 `doAttack`——
  否则面板上预判的比值和实际结算会不一致。

**验收**

- 直线 3 格后攻击：`previewAttack` 的 `attMod` 比不冲击高 0.20（中坦）。
- 走 1 格 / 中途转向 / 本回合已开火：加成必须为 0。
- 目标在城内：加成必须为 0。

### 3.2 突破跟进（P0）

> 现在击退只是"把敌人推走一格，自己原地站着"——缺口一合，等于白打。

| 项 | 内容 |
|---|---|
| **触发条件** | ① 击退已成功（现有条件不变：比值 ≥3:1、中/重坦、目标战力 >0）；② 目标退走后原格**空出**（地表层无部队） |
| **效果** | 攻方**自动进入该格**，不消耗任何行动额度；随后刷新该格要点控制权 |
| **代价** | 自身 **组织度 −3**（追击的消耗） |
| **为什么是特色** | 一回合最多推 **两格**（移动一格 + 跟进一格），这是"突破"第一次在规则上真的成立。原来只有"顶出一格"，现在是"顶出去并占住"，缺口才叫缺口 |

**边界情况**

- 攻方本回合**已经移动过也可以跟进**——追进去本来就得靠走。这条不做限制，否则"冲击 + 跟进"这条最典型的连招会被掐死。
- 目标退路被堵死（无空格）时**不跟进**，走现有的 `PUSH_BLOCK_ORG` 分支。
- 跟进**不再触发**击退、不触发岸防炮与雷区结算——那一格是敌人刚踩过的格子，判定已在那时做过。
- 攻方战力已归零（同归于尽）时不跟进。
- 跟进后本回合已无任何可用动作（已开火、已移动），不再额外限制。

**实现要点**

- 位置更新放在 `doAttack` 的击退分支之后，复用 `retreatCell` 已经算好的落点，不要重算。
- 跟进会改变控制权，必须调用与正常移动同一套控制权刷新，否则要点归属会停在旧状态（这类"显示改了、数据没改"的坑项目里踩过多次）。

**验收**

- 构造 3:1 击退且落点空：`def.pos` 变为原目标格，且 `att.pos` 等于该格的原位置。
- 退路堵死：攻方位置不变，目标组织度 −8。
- 跟进后该格要点控制权归属正确（不能只读界面，要读 `state`）。

### 3.3 履带压制（P0）

> 坦克在开阔地上冲步兵，杀不完，但能把一个营打散。

| 项 | 内容 |
|---|---|
| **触发条件** | ① 攻方是装甲（三型皆可）；② 目标是**步兵类**（步兵 / 守备 / 摩步 / 装步 / 海军步兵 / 伞兵）；③ 目标所在格是**平原 / 道路 / 机场**；④ 目标脚下**无工事** |
| **效果** | 伤害照旧，目标额外 **组织度 −6** |
| **代价** | 无额外代价（这是装甲的常态能力） |
| **为什么是特色** | 它把"坦克杀步兵"改成"坦克把步兵打崩"。崩了不能主动进攻、反击照常——于是坦克的正确用法是**推开步兵、让己方步兵去占点**，而不是用坦克清场。这条也让反坦克连变得更重要：唯一能把坦克挡在开阔地之外的东西 |

**边界情况**

- 城市、林地、丘陵一律无效（坦克在遮蔽地形里看不见也压不住）。
- 目标有工事（堑壕 / 碉堡等）时无效——这正好把"步兵整回合不动就自动 +15% 防御"那条隐性激励接上。
- 与 3.1 冲击的额外组织度取较高值，不叠加。
- 组织度下限 0，不会因为压制直接消灭单位。

**验收**

- 平原打步兵营：目标 `org` 比现值多掉 6。
- 同一场攻击，把目标换到城内 → 额外组织度必须为 0。
- 把攻方换成反坦克连（非装甲）→ 额外组织度必须为 0。

### 3.4 油料续航（P1 · 刹车）

> 坦克跑得快，但腿短。不加这条，三件套会让"全员坦克平推"成为最优解。

| 项 | 内容 |
|---|---|
| **触发条件** | 装甲单位，按现有补给场判定（≤3 充足 / ≤6 紧张 / >6 或线路被切 断绝） |
| **效果** | 「紧张」：本回合**机动 −2**；「断绝」：**失去装甲突击**（机动后开火回到 −10%），且每回合额外 **组织度 −3** |
| **边界** | 核心要点自持（城内/机场被围仍算"紧张"）对装甲同样生效——守城的坦克不该比野外的更惨 |
| **为什么必要** | 装甲的所有新能力都指向"往前冲"，必须有一条随距离递增的成本。它也是关卡设计者的刹车：想削蓝方装甲，不必改数值，把补给点往后挪两格就行 |

**实现要点**

- 机动扣减**不要写进 `u.mov`**：`computeReach` 已经在用 `u.mov + u.cardMov` 的加法形式，照这个模式再加一项，
  否则会污染存档、面板显示和下一回合的基数。
- "失去装甲突击"不要改 `ARM_FIRE` 常量（那会波及自行火炮），在 `previewAttack` 的行进间射击判定处加条件。

### 3.5 反装甲暴露（P1 · 对手戏）

> 反坦克炮是埋伏的武器。打了一炮，位置就暴露了。

| 项 | 内容 |
|---|---|
| **触发条件** | 反坦克连 / 歼击车**本回合开过火** |
| **效果** | 现有防御加成（+15% / +30%）归零，直到下个本方回合开始 |
| **为什么必要** | 3.1–3.3 全在加强装甲，必须让防守方有一手。这条让"什么时候开这一炮"变成决策：早打能救急，但下一轮对方的反扑会硬很多 |

**实现要点**：`u.exposed` 布尔字段，开火时置真、本方回合开始时清空。**同样要进存档白名单**。

---

### 3.6 重坦破障（P1 · 一行）

| 项 | 内容 |
|---|---|
| **触发条件** | 重坦攻击**带耐久工事**的目标（碉堡 / 要塞炮 / 岸防炮） |
| **效果** | 现有 −15% 改为 **+10%**（相对现值净差 25%） |
| **边界** | 只对重坦生效，中/轻坦维持原惩罚；工事耐久吸收伤害的规则不变 |
| **为什么** | 现在重坦只是"厚"，没有一个非它不可的场合。攻坚关（C4 / C6 一类）里给它一个位置，它才配得上 15 战力、机动 7 的代价 |

---

### 3.7 轻坦追击（P1' · 补偿）

| 项 | 内容 |
|---|---|
| **触发条件** | 轻坦攻击**已崩溃**（组织度 ≤25）或战力 ≤4 的目标 |
| **效果** | **+15%** |
| **为什么** | 3.1 与 3.2 都要求"有吨位"，轻坦拿不到击退也拿不到跟进。三件套上线后它会明显更边缘——它需要一条只有它能干的活：**收割残局**。这也贴合史实：轻坦追歼退却之敌，正面硬撞不是它的活 |

## 四、做完之后的分工

| | 轻坦 | 中坦 | 重坦 |
|---|---|---|---|
| 核心动词 | **追**（追击已崩目标） | **冲 → 破 → 跟**（冲击 + 击退 + 跟进） | **顶 → 破障 → 跟**（冲击最猛、吃得最住） |
| 最佳目标 | 炮兵、辎重、指挥部、残部 | 战线上的步兵与薄皮，撕缺口 | 有工事的要点、正面装甲 |
| 最怕 | 任何坦克、反坦克火力 | 反坦克连卡在道路上 | 纵深机动、脱离步兵与工事 |
| 典型错误 | 顶正面 | 无 | 让它长途奔袭 |

一句话：**轻坦是刀，中坦是锤，重坦是凿子。** 现在三样都是"更重的锤"。

## 五、对平衡的影响与复测要求

### 会变强的

- **有装甲的关卡**：蓝方编制含三型坦克的正关（C2 起的主力关），达成率预计上抬。
- **红方装甲**：红方同样有中坦营与装步营（C4 / C6 的近卫装甲师），3.3 履带压制对蓝方步兵一样生效，方向不完全是单向的。

### 复测协议（按项目既有纪律）

```bash
node tools/autoplay-campaign.js game/campaign.html 100 --level=C5 --seed=1234
```

1. **一次只改一条机制**，每条单独跑；不要三件套一起上再跑。
2. 先跑两遍同种子，确认数字完全一致（说明骰子可复现），再动数值。
3. **30–40 局起步，改动复核 100 局**；单轮 100 局之间也会差 5 个点。
4. 判定带：普通关 45–60%；`pace:'爽局'` 的关按 65–90%。
5. **先看输在哪，别急着改数值**——屡次踩过的坑是我方主力被自己废掉（例如守备营扔下要点跑去钻碉堡），不是数值不够。
6. 不动关卡机制的版本不跑自战；这份设计一旦实装，属于**动机制**，必须跑。

### 可能需要的后续调整

- 三件套叠加后 C5 / C6 这类刀刃关可能整体上抬 10–20 个点，届时优先调**关卡**（补给点位置、红方编制、keep 格地形），而不是回头削机制。
- 若上抬幅度过大且集中在"坦克数量最多的关"，说明 3.4 油料续航的强度不够，先加严它。

## 六、不做 / 缓做清单

| 候选 | 判断 | 理由 |
|---|---|---|
| **编组协同**（坦克与装步相邻互换减惩罚） | 暂不做 | `helpers` 已有同格 50% / 相邻 35% 的协同，再加一层会叠乘爆炸；且它奖励"堆着不动"，与坦克要往前冲的定位相反。等三件套的数据出来再评估 |
| **轻坦接触侦察**（给炮兵校射） | 不做 | 与侦察连的半径 3 校射直接撞车，`rec` 会失去存在意义 |
| **合围切补给**（装甲切断敌方补给线） | 缓做 | 好玩但昂贵：需要先让"补给线"在界面上可见，否则玩家看不见自己在断谁的粮 |
| **坦克王牌 / 老兵成长** | 不做 | 关卡制游戏，不做跨局成长 |
| **燃料作为独立资源** | 不做 | 会引入新系统，与"复用五套已有系统"的约束冲突；3.4 用补给场表达已经够 |

## 八、落地顺序建议

| 版本切片 | 内容 | 理由 |
|---|---|---|
| **v4.16** | 3.2 突破跟进 + 3.3 履带压制 | 都是"小改动、直接改变玩法"；且不动移动语义（`actedThisTurn` 那套最容易踩坑的地方） |
| **v4.17** | 3.1 冲击 + 3.4 油料续航 | 冲击要新增移动轨迹状态与存档字段，与油料同批做，正好一次把新增字段的校验补齐 |
| **v4.18** | 3.5 反装甲暴露 + 3.6 重坦破障 + 3.7 轻坦追击 | 三个小项，收尾与补偿；此时应按数据判断轻坦是否真的需要这条 |

每片单独出包、单独跑自战；不要把一个版本的改动攒两个切片再一次性评估。
