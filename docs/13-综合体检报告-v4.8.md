## 三、P1 · 该尽快处理

### P1-1 ✅ 已收口 v4.8 的全部改动还没提交，线上是 v4.7.1

```
$ git status --short | wc -l        → 10 个文件
$ git diff --stat | tail -1         → 2678 insertions(+), 86 deletions(-)
$ git rev-list --count origin/main..main → 0
```

`origin/main..main` 是 0 说明**没有"已提交但没推"的提交**，而工作区有 2,678 行改动——
也就是说这批改动连 commit 都还没有。按项目既有经验，玩家看到"没更新"时先查这个数，
现在这个数会骗人：它是 0，但确实没上线。

**收口时发现"拆四批"这个建议不成立**：引擎、`data/levels.js`、`export-levels`、
`levelcheck [10]`、菜单页是**互相咬着**的——只提交 `CHAPTERS` 不提交占位关，
配比断言当场就红；只提交数据不提交导出，`--check` 就红。硬拆只会拆出一串
"每个提交都是红的"，那比一个大的绿提交更难 bisect。
所以按**关注点**拆成两批，每批自己跑通全量：

| 提交 | 内容 | 覆盖的问题 |
|---|---|---|
| `c5c352a` | 结构：引擎 + 数据 + 菜单页 + 导出 + 章节断言 + 文档 | 首轮改造 + P1-2 的断言 |
| `0b2eb01` | 修复：顶栏「附属」重复 + 断言 + 变异 | P2-1 |

### P1-2 ✅ 已收口「跳过未实装关」这个设计，在乱序实装时会改掉老玩家的解锁结论

`accessPrereq()` 往前扫时有两个 `continue`：

```js
if (!pre.ready) continue;   // 占位关不挡路
if (pre.sub) continue;      // 附属关不是台阶
```

第一条当前是**对的**——61 个占位关已经在数组里排好了位，现在跳过它们，等于
"还没做的关不存在"，玩家打完 C4 就是这条线的尽头。

但它同时默默允许了**中间挖空**：假设先做第 2 章的 `C8`（不做 `C7`），
`C8` 的前置会是 C4；等 `C7` 做出来，`C8` 的前置变成 `C7`——
**已经通关 `C8` 的玩家，会发现自己那关又锁上了**。这类"内容更新锁住老进度"
是存档型游戏最难受的一种 bug，而且不报错、不崩溃，玩家只会以为存档坏了。

现在没踩，是因为实装顺序恰好是从头往后。**但没有任何断言守着这个顺序。**

已按建议在 `levelcheck [10]` 落地（`c5c352a`）：

> 每一章里，**已实装的正关必须是从第 1 关起连续的一段**（附属关可以缺）。

反向验证过：把第 2 章的 `C8` 改成 `ready:true`（`C7` 仍是占位）之后，这条立刻红，
提示 `第2章：C8（第2关） 已实装，但它前面还有没做的正关`。
这条断言等价于把"按顺序做"这个口头约定钉进数据，它比"实装总数"有用得多。

## 五、本次动手的两处

**5.1 附属关顶栏「第 3 关 · 附属 · 附属 · 防御」**（`0b2eb01`）——同一个事实说了两遍。

- 成因：`levelNoText()` 在 `sub` 时返回「… · 附属 · 」，而 `type` 字段本身写作「附属 · 防御」，
  两个渲染口直接相连。**从 v4.7 就存在**，8 章之后前面又多一段「第 1 章 ·」，更刺眼。
- 为什么之前没发现：顶栏副标题**从来没有断言**。它不影响判定、不报错，只是难读。
- 改法：在拼接点剥掉 `type` 的「附属 · 」前缀（新函数 `levelTypeText()`）。
  **不改数据**——`type` 在菜单页是一枚独立标签，砍成「防御」会丢掉"这是支线"的信息；
  真正多余的只是"连着说两遍"。
- 配套：`briefcheck [17]` 进真 DOM 读 `#lvSub`，断言「附属」只出现一次；
  `mutcheck` 新增一条变异（退回旧写法）确认它会红。

**5.2 章内实装连续断言**（`c5c352a`）——P1-2 的那条，二十行，见上。

除此之外**一律只报告、不改代码**——体检的价值是把清单交出来，
一次性改完会让"改了什么、为什么改"混成一团。P2-2…P2-6 与 P3 全部照旧待办。

## 六、做得好的地方（这次改造尤其明显）

1. **67 个关卡入口一次性排进数组，而不是"做一关加一条"**。这条决定了 P1-2 现在是
   "将来可能踩"而不是"已经在踩"：占位关占住了位置，实装只是翻 `ready`，
   数组顺序不会变，`accessPrereq()` 往前扫的结果也就不会变。
2. **没有第二套解锁规则**。8 章分组只活在展示层（`CHAPTERS` + `ch`），
   `levelAccess` / `accessPrereq` 一行没动。跨章门槛靠"第 N 章第一关紧挨第 N−1 章末关"
   这个数组性质，`levelcheck [10]` 直接断言它——顺序一乱就红。
3. **首页与引擎的一致性测了三种状态**（零进度 / 全通关 / 跳过附属关的中间态）。
   上一版正是栽在中间态上。
4. **`id` 不编章号**。章号是随剧本变的展示信息，`id` 是存档的键——这个分离让
   v4.8 一个老存档都没作废。
5. **导出的章表是算出来的**（`main` / `sub` / `ready` 全由 `levels` 统计），不是手抄的副本。

### 9.1 拆 CSS 为什么是个"体检项"而不是洁癖

拆文件本身零风险，**风险全在"引用对不对"**：`href` 拼错、文件忘了提交、`?v=`
没跟着版本走——三种都能让页面变成一坨裸文本，或者让玩家一半新一半旧，
而 JS 侧一条断言都不会红（所有测试读的是磁盘上的两份文件，不是浏览器的加载结果）。
所以 `check.js` 加了 `[1b/4]`：验 `<link>` 存在、验 `?v=` 与顶栏版本一致、验文件真在磁盘上。

联动修了一处测试：`briefcheck [15]` 原来读 DOM 里的 `<style>` 文本查 `touch-action`。
jsdom 不开 `resources:'usable'`，外部样式表根本不会加载，拆完 `<style>` 一个都没有，
那条会**永远红**（或者更糟：被人改成恒真）。改成读磁盘上的 CSS 文件，反而多验一层。

### 9.2 P2 之外的一条真 bug：战报里的 `<b>` 字面量

拆完 CSS 顺手截了张引擎图做目视核对，右下角战报里明晃晃挂着
`<b>舰队打不到飞机。</b>` —— 同一个事实说了两遍？不，这次是**标签本身被当文本显示**。

- 成因：第 4 关 `intro` 里作者按 HTML 写了 `<b>…</b>`，而 `intro` 是逐条塞进战报的，
  战报渲染是 `textContent = text`。两边的假设不同，谁也不报错。
- 挂了多久：**从 v4.5 到 v4.9**，三个版本，因为**战报的可见文案从来没有断言**。
- 改法：数据统一写 `**重点**`（全项目同一套），渲染口改 `innerHTML = bold(esc(text))`。
  `esc` 不能省——战报是存档的一部分，`validateSave` 只验类型与长度、不验字符集；
  顺序也不能反——先 bold 再 esc 会把 `<b>` 一起转义掉。
- 护栏：`briefcheck [13]` 两条（星号变 `<b>` / 存档里的标签仍是文本，**必须分开**，
  否则删掉其中一个照样绿）；`levelcheck [1]` 一条数据面检查（纯文本字段不许出现
  `<` `>`，红了直接点名 `C4.intro[5]`）。

> 这一条不是体检报告里的原条目，是**做 P3-1 时从截图里看出来的**。
> 记在这里是因为它正好印证报告开头那句：数字全绿不代表玩家看到的是对的。

### 9.3 菜单页滚到底部，左栏压进页脚（v4.9.1）

现象：把窗口拉矮一点再滚到页面底部，「战役进度」和说明文字直接糊在页脚的
「怎么玩」第 1 条上，两边的字叠印成一片。

成因：左栏是 `position: sticky`，而**它的包含块被 Blink 算成了整个 `.shell`**，
不是它自己那一格。于是它不会在右栏结束处停下，而是一路粘到 `top: 34px`，
压进第 2 行的页脚区域。左栏没有背景色，所以表现出来是"文字叠印"而不是"遮挡"。

- **只在矮视口下才看得见**：视口 700px 高时重叠近 200px；视口要 896px 以上
  才恰好错开——实测数字，不是设计。所有 DOM 断言、所有常规截图都照常绿。
- 改法：给左栏包一层 `.col-left` 并 `align-self: stretch` 撑满整行，包含块
  就变成"这一列"，粘到列尾自然停住。页脚另加 `z-index` 与向上铺 `box-shadow`，
  填掉方框之间和行间距那两条缝——那只是兜底，不是主修。
- 护栏：`levelcheck [9]` 断言 `.masthead` 的父元素必须是 `.col-left`。这条
  **守的是结构不是样式**（jsdom 算不出 sticky），因为删掉包裹层是唯一会退回
  原状的路径，而它不会让任何别的断言变红。已反向验证：拆掉包裹层后报
  「父元素是 shell」，随即失败 1 项。
