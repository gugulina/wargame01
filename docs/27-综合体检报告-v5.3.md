**这个数字偏保守**：`cov.js` 只合并 `selftest` / `briefcheck` / `levelcheck` 三支，不跑 `autoplay`。AI 的分支（`aiRepairGoal` / `aiGuardWork` / `aiEscortGoal` 等）因此永远显示"从未执行"——它们其实在自战里每局都跑。工具自己的提示也承认："另有 8 份引擎覆盖没合进来，数字偏残"。

## 二、P0 —— 本轮已修

### P0-1 · 变异测试的分片并行产出错误数据（工具缺陷，已修）

`tools/mutcheck.js` 从 v5.1 起支持 `--shard=k/n`，注释写着"各自独立进程，彼此只读自己的临时文件，互不干扰"。**实际不是**：

```js
const TMP = path.join(ROOT, 'game', '_mut_campaign.html');   // 固定路径
const AI_TMP = path.join(ROOT, 'game', '_mut_ai.js');        // 固定路径
```

四个分片共用同两条临时文件。时序是这样的：A 片写入自己的变异 → B 片覆盖成 B 的变异 → A 片拿它去跑测试，**读到的是 B 的代码**。

症状有两种，都很隐蔽：

1. **假防线数字乱跳**：同一份代码，第一次跑出 49 条假防线，第二次 17 条，差三倍。
2. **进程崩溃**：`finally` 里 `unlinkSync` 撞车，报 `ENOENT`（mut2 分片实测）。

**修复**：临时文件名带分片号（`_mut_s0_campaign.html`），`htmlPointingToMutAi` 不再写死 `_mut_ai.js`，改用 `path.basename(AI_TMP)`。

修完重跑：**235 条全部真会红**。

> **教训**：并行工具的第一条验收标准是"两个实例同时跑，结果与单实例一致"。
> 这条没验过就写进注释"互不干扰"，等于把错误数据当成了成果——v5.2 的
> "变异 237 条全红"（记在 docs/19）**结论可能是对的，但那份数据不能作数**。

### P1-2 · v5.3 的两套新机制原本没有变异锚点 ✅ 本轮已补

发布时 `MUTANTS` 表 237 条里，`夜战` / `工程` / `桥涵` / `装药` **一条都没有**（v5.2 的补给与护送有 18 条）。这两套机制当时只靠 selftest [69]/[70] 的 32 条断言 + 一次手动反向验证——断言本身是好的，但不在 `npm run mut` 的常驻防线里，**下次有人改 `attackRange` 或 `worksTick`，没有任何自动机制会告诉他"你打穿了断言"**。

本轮补了 7 条（237 → 244），全部验证会红：

| 变异 | 期望红 | 结果 |
|---|---|---|
| `attackRange` 不夹夜战射界 | 照明区外：野炮射程被压到 2 | ✓ |
| 照明区不豁免射界 | 站在灯下不受夜战射界影响 | ✓ |
| `doDemolish` 不扣装药 | 炸一次扣一份装药 | ✓ |
| 装药 0 也能炸（早退守卫失效） | 装药用完就炸不动 | ✓ |
| `worksTick` 不修 | 敌工兵站在断桥上能抢修 | ✓ |
| `demolish` 判定不看断桥数 | 只断一座 → 判负 | ✓ |
| `makeUnit` 忽略关卡覆写 | 关卡可以在单位上覆写装药（**新加**） | ✓ |

> **补的时候被咬了一口**：最后一条原本指望 selftest 的「两支工兵各带 5 份装药」，
> 结果变异不红——因为 `TYPE.engc.chg` 本来就是 5，关卡的覆写值也是 5，
> **把覆写整段删掉，两颗数还是相等**。这是"拿业务数据测机制"的典型翻车：
> 数据刚好重合，机制坏了也看不出来。改成造两支只有 `chg` 不同的单位去测，
> 断言立刻变红。教训写进 `MEMORY.md` 的断言规矩。
